=head1 DESCRIPTION

Geo::Coder::Free::OpenAddresses provides an interface to the free geolocation databases at
L<http://results.openaddresses.io>,
L<https://github.com/whosonfirst-data>,
L<https://github.com/dr5hn/countries-states-cities-database.git> and
L<https://download.geofabrik.de/europe-latest.osm.bz2>.
The SQLite database is in a file held in $OPENADDR_HOME/openaddresses.sql.

Refer to the source URL for licencing information for these files.

To install,
run the createdatabases.PL script which imports the data into an SQLite database.
This process will take some time.

=head2 Optional modules

Two modules are used to parse an address when they are installed, and the
lookup goes on without them when they are not:

=over 4

=item * L<Geo::Address::Parser> splits a US address into its fields before the
database is searched for them.

=item * L<Geo::libpostal> is tried last, for US and Canadian addresses the
other steps could not parse.  The first call to it in a process loads
libpostal's model, which is several gigabytes, so that call can take several
seconds and the process then holds that memory.  Pass C<< libpostal => 0 >> to
C<new()> to leave it unused, for example in a short-lived or memory-constrained
process, or in a test with a time limit.

=back

When looking for a house number in a street, if that address isn't found but that
street is found, a place in the street is given.
So "106 Wells Street, Fort Wayne, Allen, Indiana, USA" isn't found, a match for
"Wells Street, Fort Wayne, Allen, Indiana, USA" will be given instead.
Arguably that's incorrect, but it is the behaviour I want.
If "exact" is not given,
it will go on to look just for the town if the street isn't found.

The word "county" is removed from US county searches,
that either C<Leesburg, Loudoun County, Virginia, US> or C<Leesburg, Loudoun, Virginia, US> will work.

    # Input schema (Params::Validate::Strict) - exactly one of location or scantext is required
    location     => { type => 'scalar',   optional => 1 }  # address string (exclusive with scantext)

The domain of each parameter:

=over 4

=item * C<location> - any characters.  Once normalised (commas and spaces removed)
an address of up to 16 characters is looked up as written, in upper case, and a
longer one by a digest of 16 characters.

=item * C<scantext> - under 6 characters it is ignored, counted in characters, not
bytes.  Words are made of word characters, so an emoji is punctuation and is dropped.

=item * Known bug: a normalised address of over 16 characters containing a character
beyond Latin-1 dies with C<Wide character in subroutine entry>, so a CJK or Cyrillic
street in a US address can kill a lookup.

=item * Known bug: a Latin-1 string is treated differently depending on how perl
stores it.  Unless it has been upgraded internally it isn't upper-cased correctly,
so it gets another digest, and in a C<scantext> its accented letter ends the word.
F<t/domain.t> has TODOs for both bugs.
