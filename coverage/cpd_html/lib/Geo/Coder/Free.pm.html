  120: =head1 DESCRIPTION
  121: 
  122: C<Geo::Coder::Free> translates addresses into latitude/longitude coordinates
  123: using local SQLite databases built from free data sources - MaxMind/GeoNames,
  124: OpenAddresses, Who's On First, OpenStreetMap, and dr5hn's countries/states/cities
  125: database.  It deliberately avoids paid or rate-limited online geocoding services.
  126: The module is designed to be flexible, supporting both command-line and programmatic usage.
  127: It also includes a sample CGI script for a web-based geocoding service.
  128: 
  129: Geocoding dispatch order depends on whether C<OPENADDR_HOME> (or C<openaddr>) is set:
  130: 
  131: B<With OpenAddresses data:>
  132: 
  133: =over 4
  134: 
  135: =item 1. C<Geo::Coder::Free::OpenAddresses> - requires C<OPENADDR_HOME>
  136: 
  137: =item 2. C<Geo::Coder::Free::Local> - user-curated CSV entries (tried as fallback)
  138: 
  139: =item 3. C<Geo::Coder::Free::MaxMind> - bundled, always available
  140: 
  141: =back
  142: 
  143: B<Without OpenAddresses data:>
  144: 
  145: =over 4
  146: 
  147: =item 1. C<Geo::Coder::Free::MaxMind> only - Local is not consulted.
  148: 
  149: =back
  150: 
  151: The C<cgi-bin> directory contains a simple DIY geo-coding website:
  152: 
  153:     cgi-bin/page.fcgi page=query q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA
  154: 
  155: The sample website is currently down while a new host is sought.
  156: When it returns, you will be able to test it with:
  157: 
  158:     curl 'https://geocode.nigelhorne.com/cgi-bin/page.fcgi?page=query&q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA'
  159: 
  160: =head1 LIMITATIONS
  161: 
  162: =over 4
  163: 
  164: =item * C<scantext> mode only finds locations in OpenAddresses; it falls back
  165: silently when C<OPENADDR_HOME> is not set (B<FIXME>: should warn).
  166: 
  167: =item * The C<__DATA__> alternatives table is hard-coded; it should live in a
  168: user-editable config file.
  169: 
  170: =item * The address-regex scantext path misses birth-year sentences such as
  171: C<"She was born May 21, 1937 in Noblesville, IN."> because the regex requires
  172: a preceding capital-letter word directly before the city.
  173: 
  174: =item * C<reverse_geocode> is only partially implemented; the MaxMind path does
  175: not return meaningful results.
  176: 
  177: =item * Without OpenAddresses data, a two-part C<"City, Country"> location is
  178: often answered wrongly.  The MaxMind backend reads the first part as a region
  179: when it can, and answers with the first row it finds in that region, not with
  180: the city: C<"Berlin, Germany"> and C<"Munich, Germany"> both come back at
  181: 52.08, 7.38, and C<"Toronto, Canada"> comes back in British Columbia.  Some
  182: others, such as C<"Paris, France">, are not found at all.  These results carry
  183: C<< accuracy => 'region' >> and C<< confidence => 0.1 >>, so a caller that needs
  184: a city should check L</provenance> and reject them.  Naming the region as well,
  185: as in C<"Munich, Bavaria, Germany">, gives the right answer.
  186: 
  187: =item * Place names are matched as they are spelled in the data, with no
  188: folding of accents: C<"ZE<uuml>rich, Switzerland"> is found and C<"Zurich, Switzerland">
  189: is not.  Pass locations as Perl character strings (decoded, for example by
  190: C<use utf8> or an C<:encoding(UTF-8)> layer), not as undecoded UTF-8 bytes,
  191: since a byte string does not match the name in the data.
  192: 
  193: =back

  395: =head2 valid_location
  396: 
  397: =head3 SYNOPSIS
  398: 
  399:     if ($geo->valid_location($row->{'place'})) {
  400:         push @found, $geo->geocode(location => $row->{'place'});
  401:     }
  402: 
  403: =head3 DESCRIPTION
  404: 
  405: Answers whether a string is something this module will even try to look up.
  406: It is the public form of the rule C<geocode()> applies before it touches a
  407: backend, so a caller working down a spreadsheet column can skip a row whose
  408: value is a bare number - or is empty - instead of catching the croak that
  409: would otherwise kill the whole run.  That rule is defined once, in
  410: L<Geo::Location::Predicate>, and the backends apply it too: what
  411: C<valid_location()> refuses is refused wherever it is looked up.
  412: 
  413: Only that cheap syntactic test is answered.  A true result means the string is
  414: not disqualified, B<not> that a backend knows it: C<'Ramsgate, Kent'> is valid
  415: and may still find nothing, while C<'0044'> is invalid and is never looked up.
  416: The rule rejects a string of digits only, which is what a numeric column holds
  417: when the wrong column has been read, so anything with a non-digit in it counts
  418: as valid - C<'3.14'> and C<'-'> included.  C<undef>, C<''> and a reference are
  419: not valid.
  420: 
  421: =head3 API SPECIFICATION
  422: 
  423: =head4 input
  424: 
  425:     location => { type => 'scalar', optional => 1 }  # the string to test
  426: 
  427: =over 4
  428: 
  429: =item * False: C<undef>, C<''>, a reference, and a string only of digits of any
  430: length.  A digit is a Unicode decimal digit, so C<"\x{661}"> counts as one.
  431: 
  432: =item * True: anything with a non-digit in it.  The shortest are one character
  433: long.  C<'-'>, C<' '>, C<'3.14'>, C<"1\n">, a zero byte and any non-ASCII letter,
  434: emoji or control character are all true.  No maximum length applies.
  435: 
  436: =back
  437: 
  438: =head4 output
  439: 
  440:     { type => 'boolean' }  # false for undef, '' and a digit-only string
  441: 
  442: =head3 EXAMPLE
  443: 
  444:     my $geo = Geo::Coder::Free->new();

  446:     $geo->valid_location('Ramsgate, Kent');   # true
  447:     $geo->valid_location('0044');             # false - never a location
  448:     $geo->valid_location('');                 # false
  449:     $geo->valid_location(undef);              # false

  453:     $geo->valid_location('0044');

  497:     # A batch caller with a dirty column: skip the row, do not kill the run
  498:     for my $place (@column) {
  499:         my $pt = $geo->geocode(location => $place, on_error => 'undef');
  500:         next unless defined $pt;
  501:         push @found, $pt;
  502:     }
  503: 
  504: =head3 DESCRIPTION
  505: 
  506: A location or a scantext that is not a location at all - a bare number, such as
  507: the C<0044> a numeric column holds - is refused before any backend is
  508: touched.  C<valid_location()> answers the same question, so a caller can filter
  509: first; C<on_error> chooses what happens when one gets through anyway:
  510: 
  511: =over 4
  512: 
  513: =item * C<'croak'> (the default) - C<Carp::croak>, the behaviour every existing
  514: caller already has.
  515: 
  516: =item * C<'undef'> - return C<undef>, so one bad row in a spreadsheet column is
  517: skipped rather than ending the run.  It changes the answer for B<only> the two
  518: documented input errors below; an exception from a backend is still an
  519: exception, and a malformed argument list still croaks.
  520: 
  521: =back
  522: 
  523: The option is deliberately narrow, so a batch caller wants C<valid_location()>
  524: with it: that predicate answers false for C<undef> and C<''> as well, which are
  525: the other two things an empty cell holds.  A call with neither a location nor a
  526: scantext is a usage error rather than an input error - the same croak as calling
  527: C<geocode()> with no arguments - and stays a croak on either setting.
  528: 
  529: =head3 API SPECIFICATION
  530: 
  531: =head4 input
  532: 
  533:     # Input schema (Params::Validate::Strict) - exactly one of location or scantext is required
  534:     location     => { type => 'scalar',   optional => 1 }  # address string (exclusive with scantext)
  535:     scantext     => { type => 'scalar',   optional => 1 }  # free text to scan for place names
  536:     region       => { type => 'scalar',   optional => 1 }  # ISO 3166-1 alpha-2 country code hint
  537:     ignore_words => { type => 'arrayref', optional => 1 }  # words to suppress during scantext scan
  538:     on_error     => { type => 'scalar',   optional => 1 }  # 'croak' (default) or 'undef'
  539: 
  540: The domain of each parameter:
  541: 
  542: =over 4
  543: 
  544: =item * C<location> - a string with a non-digit in it, from one character up; no
  545: maximum length applies.  It reaches the backends unchanged, whatever its
  546: characters.  C<''> finds nothing and is not an error; C<undef> counts as absent.
  547: A string only of digits, or a reference, croaks C<invalid location to geocode()>.
  548: 
  549: =item * C<scantext> - the same partitions as C<location>, with the message
  550: C<invalid scantext to geocode()>.  Without OpenAddresses it is not looked at and
  551: finds nothing.
  552: 
  553: =item * C<location> and C<scantext> together - both are checked.  With
  554: OpenAddresses the scantext is searched, and without it the location is.
  555: 
  556: =item * C<region> - any string; nothing is refused.  C<CA>, C<AU> and C<IE> are
  557: appended to a scantext candidate by name, in either case, and any other value
  558: is appended as written.  C<''> and C<'0'> append nothing.
  559: 
  560: =item * C<ignore_words> - an arrayref of words, matched in any case.  A false
  561: value is the same as absent.  With OpenAddresses, anything else true dies with
  562: perl's own C<ARRAY> reference error during a scantext scan; without it the value
  563: is not looked at.
  564: 
  565: =item * C<on_error> - exactly C<'croak'> or C<'undef'>, in lower case; C<undef> is
  566: C<'croak'>.  Anything else, C<''> included, croaks C<on_error must be ...>, and
  567: that is reported before a bad location or scantext.
  568: 
  569: =item * The arguments - a bare string, an even list or a hashref.  No arguments, a
  570: lone C<undef>, an empty hashref, a reference other than a hashref, an odd list
  571: longer than one, or options with neither a location nor a scantext croak C<Usage:>.
  572: 
  573: =back
  574: 
  575: =head4 output
  576: 
  577:     # Output schema (Return::Set)
  578:     # scalar context: { type => 'object',   isa => 'Geo::Location::Point', optional => 1 }
  579:     # list context:   { type => 'arrayref', of  => { isa => 'Geo::Location::Point' } }
  580: 
  581: =head4 provenance
  582: 
  583: Every result carries C<geocoder>, C<database>, C<confidence> and C<accuracy>
  584: which distribution produced
  585: it, which backend answered, how good the match was, and how precise the
  586: coordinate is.  C<provenance()> reads the four back.  C<location> is set by every
  587: path but the MaxMind cities one, and C<text> only by a scantext lookup; C<lat>,
  588: C<long> and C<lng> come from the value object itself.
  589: 
  590: =head3 MESSAGES
  591: 
  592:     Usage: ...::geocode(...)        No location or scantext argument given.
  593:     invalid location to geocode()   location is purely numeric.
  594:     invalid scantext to geocode()   scantext is purely numeric.
  595:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  596: 
  597: =head3 PSEUDOCODE
  598: 
  599:     if self is not a blessed object -> delegate to new()->geocode(@args)
  600:     normalise @_ into %params
  601:     validate: on_error is 'croak' or 'undef' (croak if not)
  602:     validate: location is not purely numeric; scantext is not purely numeric
  603:               (undef instead of croaking when on_error is 'undef')
  604:     if openaddr backend is available:
  605:         if scantext:
  606:             try the raw scantext string as a direct location
  607:             build stopword set from %_COMMON_WORDS + ignore_words param
  608:             try 3-word windows (triplets) at confidence 0.8
  609:             try 2-word windows (duplets) at confidence 0.7
  610:             try the address-pattern regex at confidence 0.7
  611:             try region-specific address finders (GB / US / CA / IE)
  612:             mark scantext as a miss; return undef
  613:         else:
  614:             try openaddr backend
  615:             try local backend
  616:             try __DATA__ alternatives map
  617:     try maxmind backend for location lookups
  618:     croak if no scantext and no location

  622: sub geocode {
  623: 	my $self = shift;
  624: 
  625: 	# Handle being called as a function rather than a method
  626: 	if (!ref($self)) {
  627: 		if (scalar @_) {
  628: 			return __PACKAGE__->new()->geocode(@_);
  629: 		} elsif (!defined($self)) {
  630: 			Carp::croak(_i18n('usage_geocode', __PACKAGE__));
  631: 		} elsif ($self eq __PACKAGE__) {
  632: 			Carp::croak(_i18n('usage_geocode', $self));
  633: 		}
  634: 		return __PACKAGE__->new()->geocode($self);
  635: 	} elsif (ref($self) eq 'HASH') {
  636: 		return __PACKAGE__->new()->geocode($self);
  637: 	}
  638: 
  639: 	my %params = _normalize_args(_i18n('usage_geocode', __PACKAGE__), 'location', @_);
  640: 
  641: 	# What to do with an input this module rejects before it touches a backend.
  642: 	# 'croak' is the historical behaviour and stays the default, so no existing
  643: 	# caller changes; 'undef' is for a batch caller working down a dirty column,
  644: 	# which wants the row skipped rather than the whole run killed.  Only the two
  645: 	# input errors below consult it: a backend that throws still throws, because
  646: 	# nothing here is wrapped in an eval
  647: 	my $on_error = $params{'on_error'} // 'croak';
  648: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  649: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  650: 
  651: 	# Reject pure-numeric inputs early - they are never valid addresses.
  652: 	# The rule is Geo::Location::Predicate's, the same one the backends
  653: 	# apply, and valid_location() answers it in public, so a caller can
  654: 	# pre-filter with it and never reach this croak at all.
  655: 	if (defined($params{'location'}) && !_valid_location($params{'location'})) {
  656: 		return if !length($params{'location'}) || ($on_error eq 'undef');
  657: 		Carp::croak(_i18n('invalid_location', __PACKAGE__, $params{'location'}));
  658: 	}
  659: 	if (defined($params{'scantext'}) && !_valid_location($params{'scantext'})) {
  660: 		return if !length($params{'scantext'}) || ($on_error eq 'undef');
  661: 		Carp::croak(_i18n('invalid_scantext', __PACKAGE__, $params{'scantext'}));
  662: 	}
  663: 
  664: 	if ($self->{'openaddr'}) {
  665: 		if (my $scantext = $params{'scantext'}) {
  666: 			return if $self->{'scantext_misses'}{$scantext};
  667: 
  668: 			# First try the whole scantext as a direct location lookup -
  669: 			# saves work when the text happens to be a valid address string.
  670: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  671: 			my @direct = grep { defined }
  672: 				$self->{'local'}->geocode($scantext),
  673: 				$self->{'openaddr'}->geocode($scantext),
  674: 				$self->{'maxmind'}->geocode($scantext);
  675: 			return @direct if @direct;
  676: 
  677: 			my $region = $params{'region'};
  678: 			my $country = defined($region) ? ($_REGION_COUNTRY{uc $region} // $region) : undef;
  679: 
  680: 			# Build the effective stopword set.  When the caller supplies no
  681: 			# ignore_words we avoid copying %_COMMON_WORDS (which is immutable
  682: 			# at runtime) by using a reference to it directly.  Only when extra
  683: 			# words are needed do we allocate and populate a merged hash.
  684: 			my $ignore_words;
  685: 			if (my $iw = $params{'ignore_words'}) {
  686: 				my %merged = %_COMMON_WORDS;
  687: 				$merged{lc $_} = 1 for @{$iw};
  688: 				$ignore_words = \%merged;
  689: 			} else {
  690: 				$ignore_words = \%_COMMON_WORDS;
  691: 			}
  692: 
  693: 			# 3-word window search
  694: 			my @triplets = _find_word_ngrams($scantext, 3, $ignore_words);
  695: 			my $res = $self->_resolve_scan_candidates(\@triplets, $country, $CONF_TRIPLET, $scantext);
  696: 			if (@{$res}) {
  697: 				return wantarray ? @{$res} : $res->[0];
  698: 			}
  699: 
  700: 			# 2-word window search
  701: 			my @duplets = _find_word_ngrams($scantext, 2, $ignore_words);
  702: 			$res = $self->_resolve_scan_candidates(\@duplets, $country, $CONF_DUPLET, $scantext);
  703: 			if (@{$res}) {
  704: 				return wantarray ? @{$res} : $res->[0];
  705: 			}
  706: 
  707: 			# Regex-based address pattern - catches "City, ST"-style fragments.
  708: 			# Note: misses sentences like "born May 21, 1937 in Noblesville, IN"
  709: 			# because the pattern requires a capitalised word before the city.
  710: 			my @regex_matches = $scantext =~
  711: 				/\b(?:\d+\s+)?(?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*\.?),\s*
  712: 				 (?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*(?:,\s*[A-Z]{2,})*)\b/gx;
  713: 			my @places = grep { defined && $_ ne '' } @regex_matches;
  714: 			$res = $self->_resolve_scan_candidates(\@places, $country, $CONF_REGEX, $scantext);
  715: 			if (@{$res}) {
  716: 				return wantarray ? @{$res} : $res->[0];
  717: 			}
  718: 
  719: 			# Region-specific structured address patterns
  720: 			if ($region) {
  721: 				my @candidates;
  722: 				my $code = uc $region;
  723: 				if    ($code eq 'GB') { @candidates = _find_gb_addresses($scantext) }
  724: 				elsif ($code eq 'US') { @candidates = _find_us_addresses($scantext) }
  725: 				elsif ($code eq 'CA') { @candidates = _find_ca_addresses($scantext) }
  726: 				# Irish addresses are written in the same comma-separated
  727: 				# "street, town, county, country" form as British ones
  728: 				elsif ($code eq 'IE') { @candidates = _find_gb_addresses($scantext) }
  729: 
  730: 				if (@candidates) {
  731: 					my @regional;
  732: 					for my $candidate (@candidates) {
  733: 						next if $ignore_words->{lc $candidate};
  734: 						my @hits = grep { defined }
  735: 							$self->{'openaddr'}->geocode("$candidate, $country");
  736: 						push @regional, @hits if @hits;
  737: 					}
  738: 					return @regional if @regional;
  739: 				}
  740: 			}
  741: 
  742: 			$self->{'scantext_misses'}{$scantext} = 1;
  743: 			return;
  744: 		}
  745: 
  746: 		# Standard (non-scantext) lookup path
  747: 		if (wantarray) {
  748: 			my @rc = $self->{'openaddr'}->geocode(\%params);
  749: 			return @rc if @rc && $rc[0];
  750: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  751: 			@rc = $self->{'local'}->geocode(\%params);
  752: 			return @rc if @rc && $rc[0];
  753: 		} else {
  754: 			if (my $rc = $self->{'openaddr'}->geocode(\%params)) {
  755: 				return $rc;
  756: 			}
  757: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  758: 			if (my $rc = $self->{'local'}->geocode(\%params)) {
  759: 				return $rc;
  760: 			}
  761: 		}
  762: 
  763: 		# Try the alternatives table - hand-curated mappings for locations that
  764: 		# the databases have under slightly different names.
  765: 		# M3 (transitive reduction): every scantext path inside this block returned
  766: 		# early above; at this point $params{'scantext'} is provably falsy, so the
  767: 		# former `if (!$params{'scantext'})` guard was a tautology - removed.
  768: 		if (my $alt = $self->{'alternatives'}) {
  769: 			my $location = $params{'location'};
  770: 			# Not each(): the recursive geocode() calls below walk the same
  771: 			# hash, sharing and resetting its iterator, so an each() loop here
  772: 			# would start again from the top and retry the same key forever.
  773: 			foreach my $key (sort keys %{$alt}) {
  774: 				next if $_alternatives_active{$key};
  775: 				my $value = $alt->{$key};
  776: 				next unless $location =~ $key;
  777: 				local $_alternatives_active{$key} = 1;
  778: 				(my $new_loc = $location) =~ s/$key/$value/;
  779: 				$params{'location'} = $new_loc;
  780: 				if (my $rc = $self->geocode(\%params)) {
  781: 					return $rc;
  782: 				}
  783: 				# Also try the comma-free variant ("Tyne and Wear" etc.)
  784: 				if ($value =~ /, /) {
  785: 					(my $flat = $value) =~ s/,//g;
  786: 					($new_loc = $location) =~ s/$key/$flat/;
  787: 					$params{'location'} = $new_loc;
  788: 					if (my $rc = $self->geocode(\%params)) {
  789: 						return $rc;
  790: 					}
  791: 				}
  792: 				# Restore for the next iteration
  793: 				$params{'location'} = $location;
  794: 			}
  795: 		}
  796: 	}
  797: 
  798: 	# Final fallback: MaxMind for location lookups.
  799: 	# Scantext without OPENADDR_HOME will silently reach here and return undef;
  800: 	# a proper fix would warn here (see LIMITATIONS).
  801: 	# M8 (tautology elimination): both arms of the former wantarray ternary were
  802: 	# identical - collapsed to a single call; context propagates implicitly.
  803: 	if ($params{'location'}) {
  804: 		return $self->{'maxmind'}->geocode(\%params);
  805: 	}
  806: 
  807: 	Carp::croak(_i18n('usage_geocode', __PACKAGE__)) unless $params{'scantext'};
  808: 	return;
  809: }

  811: =head2 geocode_many
  812: 
  813: =head3 SYNOPSIS
  814: 
  815:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  816: 
  817:     for my $place (@places) {
  818:         my $pt = $batch->{$place};              # a Geo::Location::Point, or undef
  819:         next unless defined $pt;
  820:         printf "%s is at %.4f, %.4f\n", $place, $pt->lat(), $pt->long();
  821:     }
  822: 
  823:     printf "geocoded %d of %d places in %d lookups\n",
  824:         $batch->{'resolved'},
  825:         $batch->{'resolved'} + $batch->{'unresolved'},
  826:         $batch->{'lookups'};
  827: 
  828: =head3 DESCRIPTION
  829: 
  830: The loop a batch caller writes around C<geocode()>, run for it: one lookup per
  831: B<distinct> value, with the same options and the same results, plus the counts
  832: that caller would otherwise keep itself - how many values made a backend read,
  833: how many resolved, how many did not, which ones, and which backend read for them
  834: 
  835: The hashref returned holds one entry per distinct value given, keyed by the
  836: value, plus five keys of its own:
  837: 
  838: =over 4
  839: 
  840: =item * C<< $batch->{$value} >> - the C<Geo::Location::Point> the value resolved
  841: to, or C<undef> if nothing did.  Every distinct value in the input is keyed, so
  842: a caller walking a column can look each row up without first asking whether the
  843: batch covered it.  An C<undef> in the input has no key of its own and shares the
  844: entry of the empty string, which is not a location either.
  845: 
  846: =item * C<lookups> - how many distinct values made a backend read to answer
  847: them: one per value, however many backends looked at it.  A value the module
  848: refuses before any backend is touched - a bare number, C<''>, C<undef>, a
  849: reference - is not counted, and neither is a value a backend answered from a
  850: cache or from a hand-curated entry, because nothing was read for it.  This is
  851: what makes the count the work a caller is capping rather than the work it asked
  852: for.  A value repeated in the batch is one lookup.  Every backend reports its
  853: reads through C<reads()>, and a value every backend has already missed is
  854: remembered in L<Geo::Coder::Free::MissCache>, one process-level cache that all
  855: backends and instances share, whose entries expire after an hour and can be
  856: emptied early with L</clear_miss_cache>.  A later batch in the same process is
  857: answered from those caches and so reports the reads it needed, often none, in
  858: place of the ones the first batch made.
  859: 
  860: =item * C<reads> - how many reads each backend made for the batch, keyed by the
  861: name C<provenance()> reports that backend under: C<MaxMind>, C<Local> or
  862: C<OpenAddresses>.  Every backend the object holds is named, at zero for one that
  863: read nothing, so a batch answered from a cache names its backends at zero rather
  864: than naming none.  C<lookups> counts values and this counts reads - a value that
  865: made two backends read is one lookup and a read for each of them, so these
  866: numbers can add up to more than C<lookups> - and the two vocabularies are the
  867: same, so a caller can put the backend that read a value beside the backend a
  868: result came from.
  869: 
  870: =item * C<resolved> - how many distinct values produced a point.
  871: 
  872: =item * C<unresolved> - how many produced nothing, the refused values included.
  873: 
  874: =item * C<unresolved_values> - those values, in the order they were first seen,
  875: so that a caller can record them as tried-and-failed rather than retrying them
  876: on every request.  Section 2.5 sketches this list under the name C<unresolved>;
  877: here C<unresolved> is the count a "geocoded N of M" message needs and the values
  878: themselves are C<unresolved_values>.
  879: 
  880: =back
  881: 
  882: C<resolved> and C<unresolved> always add up to the number of distinct values
  883: given, and the five keys above are reserved: a value equal to one of them is
  884: refused by name, before anything is looked up, rather than allowed to overwrite
  885: a count.
  886: 
  887: C<region> and C<on_error> are handed to every lookup and mean there what they
  888: mean in C<geocode()>, including the rule that a backend exception is still an
  889: exception - nothing here is wrapped in an C<eval>.  C<on_error> defaults to
  890: C<'croak'> for the same reason it does there: a batch should not quietly plot
  891: fewer points than its column holds unless the caller asked it to, and a caller
  892: working down a dirty column asks for C<'undef'>.  The two settings do not differ
  893: in which values are looked up, only in what happens to a value the module
  894: refuses: C<'croak'> dies on it with the message C<geocode()> gives for it,
  895: C<'undef'> counts it unresolved and carries on.
  896: 
  897: A batch of no values is not an error: the counts come back zero.
  898: 
  899: The values are treated as a set.  Repeating a value in the input looks it up
  900: once and every row is keyed to the same point object, so a column that repeats
  901: the same handful of places thousands of times costs the handful of lookups.
  902: 
  903: =head3 API SPECIFICATION
  904: 
  905: =head4 input
  906: 
  907:     # Input schema (Params::Validate::Strict) - values required, options optional
  908:     values   => { type => 'arrayref' }                  # location strings, one per row
  909:     region   => { type => 'scalar', optional => 1 }     # ISO 3166-1 alpha-2 country code hint
  910:     on_error => { type => 'scalar', optional => 1 }     # 'croak' (the default) or 'undef'
  911: 
  912: The domain of each parameter:
  913: 
  914: =over 4
  915: 
  916: =item * C<values> - an arrayref of any size, from none up.  Anything that is not
  917: an arrayref, or none at all, croaks C<Usage:>.  Each row is a C<location> as
  918: C<geocode()> defines it, in any characters, and keys the result as given.
  919: C<undef> and C<''> are one value, which is unresolved on either C<on_error>
  920: setting.  A string only of digits, or a reference, follows C<on_error>.
  921: 
  922: =item * A reserved value - C<lookups>, C<reads>, C<resolved>, C<unresolved> and
  923: C<unresolved_values>, spelled exactly, croak on either C<on_error> setting before
  924: anything is looked up.  C<Lookups> or C<' resolved'> are ordinary values.
  925: 
  926: =item * C<region> - any string, handed to every lookup as it is.
  927: 
  928: =item * C<on_error> - as for C<geocode()>.  It is checked first, so a bad setting
  929: croaks even with no values, or with a reserved value.
  930: 
  931: =item * The options - a hashref or an even list of non-references.  A lone scalar,
  932: an odd list, an arrayref or a reference as a value croak C<Usage:>.
  933: 
  934: =back

  938:     # Output schema (Return::Set)
  939:     { type => 'hashref' }
  940:     #   $result->{$value}            => { isa => 'Geo::Location::Point', optional => 1 }
  941:     #   $result->{lookups}           => { type => 'integer' }
  942:     #   $result->{reads}             => { type => 'hashref' }

  983: sub geocode_many {
  984: 	my $self = shift;
  985: 
  986: 	# The same calling conventions as the rest of the module, with the batch's
  987: 	# own spelling for the plain-function form: the values are always an
  988: 	# arrayref, so that is what a function call arrives holding.
  989: 	if (!Scalar::Util::blessed($self)) {
  990: 		return __PACKAGE__->new()->geocode_many($self, @_)
  991: 			if ref($self) eq 'ARRAY';
  992: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless @_;
  993: 		return __PACKAGE__->new()->geocode_many(@_);
  994: 	}
  995: 
  996: 	my $values = shift;
  997: 	Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless ref($values) eq 'ARRAY';
  998: 
  999: 	# Options are a hashref or an even list.  A lone scalar is neither: there is
 1000: 	# no bare-string form of a batch, so it is refused rather than guessed at.
 1001: 	my $opts;
 1002: 	if (@_ == 1 && ref($_[0]) eq 'HASH') {
 1003: 		$opts = { %{$_[0]} };
 1004: 	} elsif ((scalar @_) % 2 == 0 && !grep { ref } @_) {
 1005: 		$opts = { @_ };
 1006: 	} else {
 1007: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__));
 1008: 	}
 1009: 
 1010: 	my $on_error = $opts->{'on_error'} // 'croak';
 1011: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
 1012: 		unless $on_error eq 'croak' || $on_error eq 'undef';
 1013: 
 1014: 	my $region = $opts->{'region'};
 1015: 
 1016: 	# A value spelled like one of the keys this method answers with would
 1017: 	# overwrite it, so it is refused by name - before anything is looked up,
 1018: 	# rather than after a count has been lost.
 1019: 	my %reserved = map { $_ => 1 } @RESULT_KEYS;
 1020: 	for my $value (@{$values}) {
 1021: 		my $key = defined($value) ? $value : '';
 1022: 		Carp::croak(_i18n('reserved_location', __PACKAGE__, $key)) if $reserved{$key};
 1023: 	}
 1024: 
 1025: 	my %results = map { $_ => 0 } @RESULT_KEYS;
 1026: 	$results{'unresolved_values'} = [];
 1027: 	$results{'reads'} = {};
 1028: 
 1029: 	# A batch is a set: a value repeated in the input is looked up once, and
 1030: 	# every row holding it is keyed to the same object.
 1031: 	my %seen;
 1032: 	for my $value (@{$values}) {
 1033: 		# undef has no key of its own, and the empty string it shares is not a
 1034: 		# location either, so it is unresolved without reaching a backend.
 1035: 		my $key = defined($value) ? $value : '';
 1036: 		next if $seen{$key}++;
 1037: 
 1038: 		# What geocode() makes of this value on this setting is asked of
 1039: 		# geocode() rather than written out again here: the guard, its message and
 1040: 		# the choice of backend are all its own.  The backends' read counters are
 1041: 		# taken around the call, so the value is counted as a lookup only if one of
 1042: 		# them actually read: a value answered from a cache, or from a hand-curated
 1043: 		# entry, is not counted as work the batch did not do.  Taking them per
 1044: 		# backend rather than in total says which backend read, and which answered
 1045: 		# from somewhere else: a read is added to the name of the backend that made
 1046: 		# it, so a value two backends read through is one lookup and a read each.
 1047: 		my $reads_before = $self->_backend_reads();
 1048: 		my $point = $self->geocode(
 1049: 			location => $key,
 1050: 			defined($region) ? (region => $region) : (),
 1051: 			on_error => $on_error,
 1052: 		);
 1053: 		my $reads_after = $self->_backend_reads();
 1054: 
 1055: 		my $read = 0;
 1056: 		foreach my $backend (keys %{$reads_after}) {
 1057: 			my $reads = $reads_after->{$backend} - ($reads_before->{$backend} // 0);
 1058: 			next unless $reads > 0;
 1059: 			$results{'reads'}{$backend} += $reads;
 1060: 			$read += $reads;
 1061: 		}
 1062: 
 1063: 		# A value the module refuses is not a lookup: it never reached a backend,
 1064: 		# so it does not count against the work a caller is capping.
 1065: 		$results{'lookups'}++ if _valid_location($key) && $read;
 1066: 		$results{$key} = $point;
 1067: 
 1068: 		if (defined($point)) {
 1069: 			$results{'resolved'}++;
 1070: 		} else {
 1071: 			$results{'unresolved'}++;
 1072: 			push @{$results{'unresolved_values'}}, $value;
 1073: 		}
 1074: 	}
 1075: 
 1076: 	# A backend that read nothing is reported as well, at zero: what a caller is
 1077: 	# asking is which backend read and which answered from a cache, and a backend
 1078: 	# left out of the answer cannot be told from one that answered from one.
 1079: 	# Local is built the first time a lookup falls through to it, so it appears
 1080: 	# once it has been consulted, whether or not it found anything.
 1081: 	foreach my $backend (keys %{$self->_backend_reads()}) {
 1082: 		$results{'reads'}{$backend} //= 0;
 1083: 	}
 1084: 
 1085: 	return \%results;
 1086: }
 1087: 
 1088: # How much reading each backend has done so far, by the name it is reported
 1089: # under.  Counters rather than flags: the change across a call says which
 1090: # backend read for that value, and a backend that was never called cannot leave
 1091: # a stale flag behind.  A backend object may not exist yet - Local is built on
 1092: # first use - and a test may hand the facade a stand-in, so each slot is asked
 1093: # only if it holds something that can answer.
 1094: sub _backend_reads {
 1095: 	my $self = shift;
 1096: 
 1097: 	my %reads;
 1098: 	foreach my $slot (sort keys %_BACKEND_NAMES) {
 1099: 		my $backend = $self->{$slot} or next;
 1100: 		next unless Scalar::Util::blessed($backend) && $backend->can('reads');
 1101: 		$reads{$_BACKEND_NAMES{$slot}} = $backend->reads() // 0;
 1102: 	}
 1103: 
 1104: 	return \%reads;
 1105: }

 1148: =head2 provenance
 1149: 
 1150:     my ($dist, $backend, $confidence, $accuracy) = $geocoder->provenance($point);
 1151:

 1153:

 1158: reach for the hash keys itself:
 1159: 
 1160: =over 4
 1161: 
 1162: =item * C<$dist> - the distribution that produced the result: the C<geocoder>

 1410: # Purpose:  Try to geocode each candidate place string via the openaddr backend,
 1411: #           annotating every hit with location/text/confidence metadata and
 1412: #           memoising misses to avoid re-querying the same failing string.
 1413: # Entry:    $self       - geocoder instance with {openaddr} and {scantext_misses}.
 1414: #           $candidates - arrayref of place-name strings to probe.
 1415: #           $region     - optional country appended to each candidate: an ISO
 1416: #                         code, or the name from %_REGION_COUNTRY.
 1417: #           $confidence - numeric confidence score assigned to all hits.
 1418: #           $scantext   - original free text (stored inside each result object).
 1419: # Exit:     Arrayref of Geo::Location::Point objects; empty arrayref on no hits.
 1420: # Side Effects: Populates $self->{scantext_misses} for every non-matching place.
 1421: sub _resolve_scan_candidates {
 1422: 	my ($self, $candidates, $region, $confidence, $scantext) = @_;
 1423: 	my @results;
 1424: 	for my $place (@{$candidates}) {
 1425: 		my $location = $region ? "$place, $region" : $place;
 1426: 		next if $self->{'scantext_misses'}{$location};

 1428: 		if (@res) {
 1429: 			for my $entry (@res) {
 1430: 				$entry->{'location'}   = $location;
 1431: 				$entry->{'text'}       = $scantext;
 1432: 				$entry->{'confidence'} = $confidence;
 1433: 			}
 1434: 			push @results, @res;
 1435: 		} else {
 1436: 			$self->{'scantext_misses'}{$location} = 1;
 1437: 		}
 1438: 	}
 1439: 	return \@results;

 1442: # Purpose:  Slide a window of $n words across $text and return all comma-joined
 1443: #           n-grams, excluding pure-numeric tokens and stopwords.  A token of
 1444: #           digits only is not a word of a place name, which is the question
 1445: #           Geo::Location::Predicate::_valid_location() answers, so it is asked
 1446: #           there rather than spelled out here (t/location-rule.t fails if the
 1447: #           rule is written out again).
 1448: #           Replaces the former _find_word_triplets ($n=3) and
 1449: #           _find_word_duplets ($n=2) which were identical except for window size
 1450: #           and the duplets version was missing the lc() normalisation on stopwords.
 1451: # Entry:    $text - raw string; $n - window size; $stop - stopword hashref.
 1452: # Exit:     Flat list of n-gram strings.
 1453: sub _find_word_ngrams {
 1454: 	my ($text, $n, $stop) = @_;
 1455: 	$text =~ s/,+/ /g;
 1456: 	$text =~ s/\s+/ /g;
 1457: 	$text =~ s/^\s+|\s+$//g;
 1458: 	my @words = grep { !$stop->{lc $_} && _valid_location($_) } split /\s+/, $text;
 1459: 	my @ngrams;
 1460: 	for my $i (0 .. $#words - ($n - 1)) {
 1461: 		push @ngrams, join ', ', @words[$i .. $i + $n - 1];
 1462: 	}
 1463: 	return @ngrams;
 1464: }

 1466: # Purpose:  Extract structured US street addresses from free text.
 1467: # Entry:    $text - arbitrary string.
 1468: # Exit:     List of full address strings matching the US pattern.
 1469: sub _find_us_addresses {
 1470: 	my $text = shift;
 1471: 	my @addresses;
 1472: 	my $re = qr/
 1473: 		\b \d{1,5} \s+                                      # house number
 1474: 		(?:[A-Za-z0-9]+(?:\s+[A-Za-z0-9]+){0,6}) \s+       # street name: 1-7 words (bounded)
 1475: 		(?:Avenue|Ave\.?|Boulevard|Blvd\.?|Road|Rd\.?|Lane|Ln\.?|Drive|Dr\.?|Street|St\.?)
 1476: 		(?:\s+[A-Za-z]{2})? ,\s*
 1477: 		(?:[A-Za-z]+(?:\s+[A-Za-z]+){0,3}) ,\s*            # city: 1-4 words
 1478: 		[A-Z]{2} \s* (?:\d{5}(?:-\d{4})?)? \b              # state + optional zip
 1479: 	/x;
 1480: 	while ($text =~ /$re/g) {
 1481: 		push @addresses, $&;
 1482: 	}
 1483: 	return @addresses;
 1484: }

 1486: # Purpose:  Extract British-style addresses from free text.
 1487: # Entry:    $text - arbitrary string.
 1488: # Exit:     List of trimmed address strings.
 1489: sub _find_gb_addresses {
 1490: 	my $text = shift;
 1491: 	my @addresses;
 1492: 	# ReDoS fix: the former pattern used \s*,?\s* between all parts and
 1493: 	# [A-Za-z\s'-]+ groups - with commas optional, the engine must try all
 1494: 	# possible splits of a long string among 5 overlapping space-containing
 1495: 	# groups, causing exponential backtracking.  Making commas mandatory
 1496: 	# eliminates the ambiguity entirely: UK postal addresses always have commas.
 1497: 	# All groups are non-capturing (only $& is used).
 1498: 	my $re = qr/
 1499: 		\b
 1500: 		(?:\d{1,5} | [\w'-]+)                   # house number or single-word name
 1501: 		\s+
 1502: 		(?:[\w'-]+(?:\s+[\w'-]+){0,5})           # street name (up to 6 words)
 1503: 		\s*,\s*                                   # COMMA REQUIRED - kills the ambiguity
 1504: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # town (up to 4 words)
 1505: 		\s*,\s*                                   # COMMA REQUIRED
 1506: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # county (up to 4 words)
 1507: 		\s*,\s*                                   # COMMA REQUIRED
 1508: 		(?:[\w'-]+(?:\s+[\w'-]+){0,2})           # country (up to 3 words)
 1509: 		\b
 1510: 	/x;
 1511: 	while ($text =~ /$re/g) {
 1512: 		(my $addr = $&) =~ s/[,\s]+$//;
 1513: 		push @addresses, $addr;
 1514: 	}
 1515: 	return @addresses;
 1516: }

 1541: =head1 GETTING STARTED
 1542: 
 1543: To download, import and set up the local database:
 1544: before running C<make>, but after running C<perl Makefile.PL>, follow these instructions.
 1545: 
 1546: Optionally set C<OPENADDR_HOME> to point to an empty directory and download the data from
 1547: L<http://results.openaddresses.io> into that directory; and
 1548: optionally set C<WHOSONFIRST_HOME> to point to an empty directory and download the data using
 1549: L<https://github.com/nigelhorne/NJH-Snippets/blob/master/bin/wof-clone>.
 1550: The script C<bin/download_databases> (see below) will do those for you.
 1551: You do not need to download the MaxMind data - that is downloaded automatically.
 1552: 
 1553: You will need to create the database used by C<Geo::Coder::Free>.
 1554: 
 1555: Install L<App::csv2sqlite> and L<https://github.com/nigelhorne/NJH-Snippets>.
 1556: Run C<bin/create_sqlite> - this converts the MaxMind "cities" database from CSV to SQLite.
 1557: 
 1558: To use with MariaDB, set C<MARIADB_SERVER="$hostname;$port"> and
 1559: C<MARIADB_USER="$user;$password"> (TODO: username/password should be asked for interactively).
 1560: The code will use a database called C<geo_code_free>, which will be dropped and recreated if it exists.
 1561: C<$user> needs only DROP, CREATE, SELECT, INSERT, and INDEX privileges on that database.
 1562: 
 1563: The following optional steps download and install large databases.
 1564: This will take a long time and use a lot of disc space.
 1565: 
 1566: =over 4
 1567: 
 1568: =item 1
 1569: 
 1570: C<mkdir $WHOSONFIRST_HOME; cd $WHOSONFIRST_HOME> then run C<wof-clone> from NJH-Snippets.
 1571: 
 1572: This can take a long time because it contains many nested directories, which filesystem drivers
 1573: can be slow to navigate (particularly on EXT4 and ZFS).
 1574: 
 1575: =item 2
 1576: 
 1577: Install L<https://github.com/dr5hn/countries-states-cities-database.git> into C<$DR5HN_HOME>.
 1578: This data covers cities only, so it is not used when C<OSM_HOME> is set (OSM is far more
 1579: comprehensive).  Only Australia, Canada, and the US are imported, as the UK data is difficult
 1580: to parse.
 1581: 
 1582: =item 3
 1583: 
 1584: Run C<bin/download_databases> - this downloads the Who's On First, OpenAddr, OpenStreetMap,
 1585: and dr5hn databases.
 1586: OpenStreetMap now uses PBF files, so you will need C<apt install osmium-tool> first.
 1587: Check the values of C<OSM_HOME>, C<OPENADDR_HOME>, C<DR5HN_HOME> and C<WHOSONFIRST_HOME>
 1588: within that script and adjust them for your setup.
 1589: The C<Makefile.PL> file downloads the MaxMind database automatically, as it is not optional.
 1590: 
 1591: =item 4
 1592: 
 1593: Run C<bin/create_db> - this creates the database used by C<Geo::Coder::Free> from the data you
 1594: have just downloaded.
 1595: The database is called C<openaddr.sql> for historical reasons (before Who's On First was added);
 1596: it actually contains data from all sources above.
 1597: 
 1598: =back
 1599: 
 1600: Now you are ready to run C<make>.
 1601: See the comment at the start of C<createdatabase.PL> for further details.
