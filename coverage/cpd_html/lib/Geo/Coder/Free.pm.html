  155: =head1 DESCRIPTION
  156: 
  157: C<Geo::Coder::Free> translates addresses into latitude/longitude coordinates
  158: using local SQLite databases built from free data sources - MaxMind/GeoNames,
  159: OpenAddresses, Who's On First, OpenStreetMap, and dr5hn's countries/states/cities
  160: database.  It deliberately avoids paid or rate-limited online geocoding services.
  161: The module is designed to be flexible, supporting both command-line and programmatic usage.
  162: It also includes a sample CGI script for a web-based geocoding service.
  163: 
  164: Geocoding dispatch order depends on whether C<OPENADDR_HOME> (or C<openaddr>) is set:
  165: 
  166: B<With OpenAddresses data:>
  167: 
  168: =over 4
  169: 
  170: =item 1. C<Geo::Coder::Free::OpenAddresses> - requires C<OPENADDR_HOME>
  171: 
  172: =item 2. C<Geo::Coder::Free::Local> - user-curated CSV entries (tried as fallback)
  173: 
  174: =item 3. C<Geo::Coder::Free::MaxMind> - bundled, always available
  175: 
  176: =back
  177: 
  178: B<Without OpenAddresses data:>
  179: 
  180: =over 4
  181: 
  182: =item 1. C<Geo::Coder::Free::MaxMind> only - Local is not consulted.
  183: 
  184: =back
  185: 
  186: The C<cgi-bin> directory contains a simple DIY geo-coding website:
  187: 
  188:     cgi-bin/page.fcgi page=query q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA
  189: 
  190: The sample website is currently down while a new host is sought.
  191: When it returns, you will be able to test it with:

  195: =head1 LIMITATIONS
  196: 
  197: =over 4
  198: 
  199: =item * C<scantext> mode only finds locations in OpenAddresses.  When
  200: C<OPENADDR_HOME> is not set it finds nothing, and warns once per object.
  201: 
  202: =item * Pass decoded character strings.  Non-ASCII text is matched exactly, so C<Munchen>
  203: doesn't find C<ME<uuml>nchen>, and bytes that have not been decoded are a different address.
  204: 
  205: =item * The C<__DATA__> alternatives table is hard-coded; it should live in a
  206: user-editable config file.
  207: 
  208: =item * The address-regex scantext path misses birth-year sentences such as
  209: C<"She was born May 21, 1937 in Noblesville, IN."> because the regex requires
  210: a preceding capital-letter word directly before the city.
  211: 
  212: =item * C<reverse_geocode> is only partially implemented; the MaxMind path does
  213: not return meaningful results.
  214: 
  215: =item * Without OpenAddresses data, a two-part C<"City, Country"> location is
  216: often answered wrongly.  The MaxMind backend reads the first part as a region
  217: when it can, and answers with the first row it finds in that region, not with
  218: the city: C<"Berlin, Germany"> and C<"Munich, Germany"> both come back at
  219: 52.08, 7.38, and C<"Toronto, Canada"> comes back in British Columbia.  Some
  220: others, such as C<"Paris, France">, are not found at all.  These results carry
  221: C<< accuracy => 'region' >> and C<< confidence => 0.1 >>, so a caller that needs
  222: a city should check L</provenance> and reject them.  Naming the region as well,
  223: as in C<"Munich, Bavaria, Germany">, gives the right answer.
  224: 
  225: =item * Place names are matched as they are spelled in the data, with no
  226: folding of accents: C<"ZE<uuml>rich, Switzerland"> is found and C<"Zurich, Switzerland">
  227: is not.  Pass locations as Perl character strings (decoded, for example by
  228: C<use utf8> or an C<:encoding(UTF-8)> layer), not as undecoded UTF-8 bytes,
  229: since a byte string does not match the name in the data.
  230: 
  231: =back

  442: =head2 valid_location
  443: 
  444: =head3 SYNOPSIS
  445: 
  446:     if ($geo->valid_location($row->{'place'})) {
  447:         push @found, $geo->geocode(location => $row->{'place'});
  448:     }
  449: 
  450: =head3 DESCRIPTION
  451: 
  452: Answers whether a string is something this module will even try to look up.
  453: It is the public form of the rule C<geocode()> applies before it touches a
  454: backend, so a caller working down a spreadsheet column can skip a row whose
  455: value is a bare number - or is empty - instead of catching the croak that
  456: would otherwise kill the whole run.  That rule is defined once, in
  457: L<Geo::Location::Predicate>, and the backends apply it too: what
  458: C<valid_location()> refuses is refused wherever it is looked up.
  459: 
  460: Only that cheap syntactic test is answered.  A true result means the string is
  461: not disqualified, B<not> that a backend knows it: C<'Ramsgate, Kent'> is valid
  462: and may still find nothing, while C<'0044'> is invalid and is never looked up.
  463: The rule rejects a string of digits only, which is what a numeric column holds
  464: when the wrong column has been read, so anything with a non-digit in it counts
  465: as valid - C<'3.14'> and C<'-'> included.  C<undef>, C<''> and a reference are
  466: not valid.
  467: 
  468: =head3 API SPECIFICATION
  469: 
  470: =head4 input
  471: 
  472:     location => { type => 'scalar', optional => 1 }  # the string to test
  473: 
  474: =over 4
  475: 
  476: =item * False: C<undef>, C<''>, a reference, and a string only of digits of any
  477: length.  A digit is a Unicode decimal digit, so C<"\x{661}"> counts as one.
  478: 
  479: =item * True: anything with a non-digit in it.  The shortest are one character
  480: long.  C<'-'>, C<' '>, C<'3.14'>, C<"1\n">, a zero byte and any non-ASCII letter,
  481: emoji or control character are all true.  No maximum length applies.
  482: 
  483: =back
  484: 
  485: =head4 output
  486: 
  487:     { type => 'boolean' }  # false for undef, '' and a digit-only string
  488: 
  489: =head3 EXAMPLE
  490: 
  491:     my $geo = Geo::Coder::Free->new();
  492: 
  493:     $geo->valid_location('Ramsgate, Kent');   # true
  494:     $geo->valid_location('0044');             # false - never a location
  495:     $geo->valid_location('');                 # false
  496:     $geo->valid_location(undef);              # false
  497: 
  498: Accepts the three calling conventions the rest of this module does:
  499: 
  500:     $geo->valid_location('0044');
  501:     Geo::Coder::Free->valid_location('0044');
  502:     Geo::Coder::Free::valid_location('0044');
  503:

  506: sub valid_location {
  507: 	my $self = shift;
  508: 
  509: 	# The location is whichever argument is not the invocant, so that the
  510: 	# predicate reads the same whether it is called on an instance, on the
  511: 	# class or as a plain function.
  512: 	my $location;
  513: 	if (ref($self)) {
  514: 		$location = shift;
  515: 	} elsif (@_) {
  516: 		$location = shift;
  517: 	} elsif (defined($self) && $self ne __PACKAGE__) {
  518: 		$location = $self;
  519: 	}
  520: 
  521: 	return _valid_location($location) ? 1 : 0;
  522: }

  524: =head2 geocode
  525: 
  526: =head3 SYNOPSIS
  527: 
  528:     # Standard lookup (returns a Geo::Location::Point or undef)
  529:     my $pt = $geo->geocode(location => 'Ramsgate, Kent, UK');
  530:     printf "lat=%.6f lon=%.6f\n", $pt->lat(), $pt->long();
  531: 
  532:     # Scantext - returns a list of Geo::Location::Point objects
  533:     my @hits = $geo->geocode(
  534:         scantext     => 'She lived in Ramsgate, Kent.',
  535:         region       => 'GB',
  536:         ignore_words => [qw(lived)],
  537:     );
  538: 
  539:     # Invocation flexibility (all equivalent)
  540:     $geo->geocode('Ramsgate, Kent, UK');
  541:     $geo->geocode({ location => 'Ramsgate, Kent, UK' });
  542:     $geo->geocode(location => 'Ramsgate, Kent, UK');
  543: 
  544:     # A batch caller with a dirty column: skip the row, do not kill the run
  545:     for my $place (@column) {
  546:         my $pt = $geo->geocode(location => $place, on_error => 'undef');
  547:         next unless defined $pt;
  548:         push @found, $pt;
  549:     }
  550: 
  551: =head3 DESCRIPTION
  552: 
  553: A location or a scantext that is not a location at all - a bare number, such as
  554: the C<0044> a numeric column holds - is refused before any backend is
  555: touched.  C<valid_location()> answers the same question, so a caller can filter
  556: first; C<on_error> chooses what happens when one gets through anyway:
  557: 
  558: =over 4
  559: 
  560: =item * C<'croak'> (the default) - C<Carp::croak>, the behaviour every existing
  561: caller already has.
  562: 
  563: =item * C<'undef'> - return C<undef>, so one bad row in a spreadsheet column is
  564: skipped rather than ending the run.  It changes the answer for B<only> the two
  565: documented input errors below; an exception from a backend is still an
  566: exception, and a malformed argument list still croaks.
  567: 
  568: =back
  569: 
  570: The option is deliberately narrow, so a batch caller wants C<valid_location()>
  571: with it: that predicate answers false for C<undef> and C<''> as well, which are
  572: the other two things an empty cell holds.  A call with neither a location nor a
  573: scantext is a usage error rather than an input error - the same croak as calling
  574: C<geocode()> with no arguments - and stays a croak on either setting.
  575: 
  576: =head3 API SPECIFICATION
  577: 
  578: =head4 input
  579: 
  580:     # Input schema (Params::Validate::Strict) - at least one of location or scantext is required
  581:     location     => { type => 'scalar',   optional => 1 }  # address string
  582:     scantext     => { type => 'scalar',   optional => 1 }  # free text to scan for place names
  583:     region       => { type => 'scalar',   optional => 1 }  # ISO 3166-1 alpha-2 country code hint
  584:     ignore_words => { type => 'arrayref', optional => 1 }  # words to suppress during scantext scan
  585:     on_error     => { type => 'scalar',   optional => 1 }  # 'croak' (default) or 'undef'
  586: 
  587: The domain of each parameter:
  588: 
  589: =over 4
  590: 
  591: =item * C<location> - a string with a non-digit in it, from one character up; no
  592: maximum length applies.  It reaches the backends unchanged, whatever its
  593: characters.  C<''> finds nothing and is not an error; C<undef> counts as absent.
  594: A string only of digits, or a reference, croaks C<invalid location to geocode()>.
  595: 
  596: =item * C<scantext> - the same partitions as C<location>, with the message
  597: C<invalid scantext to geocode()>.  Without OpenAddresses it is not looked at and
  598: finds nothing.
  599: 
  600: =item * C<location> and C<scantext> together - both are checked.  With
  601: OpenAddresses the scantext is searched, and without it the location is.
  602: 
  603: =item * C<region> - any string; nothing is refused.  C<CA>, C<AU> and C<IE> are
  604: appended to a scantext candidate by name, in either case.  Any other two letters
  605: are appended in upper case, and any other value as written.  C<''> and C<'0'>
  606: append nothing.  A scantext that found nothing is remembered per C<region> and
  607: C<ignore_words>, as long as a miss in L<Geo::Coder::Free::MissCache> lasts and
  608: until L</clear_miss_cache>.
  609: 
  610: =item * C<ignore_words> - an arrayref of words, matched in any case.  A false
  611: value is the same as absent.  With OpenAddresses, anything else true dies with
  612: perl's own C<ARRAY> reference error during a scantext scan; without it the value
  613: is not looked at.
  614: 
  615: =item * C<on_error> - exactly C<'croak'> or C<'undef'>, in lower case; C<undef> is
  616: C<'croak'>.  Anything else, C<''> included, croaks C<on_error must be ...>, and
  617: that is reported before a bad location or scantext.
  618: 
  619: =item * The arguments - a bare string, an even list or a hashref.  No arguments, a
  620: lone C<undef>, an empty hashref, a reference other than a hashref, an odd list
  621: longer than one, or options with neither a location nor a scantext croak C<Usage:>.
  622: 
  623: =back
  624: 
  625: =head4 output
  626: 
  627:     # Output schema (Return::Set)
  628:     # scalar context: { type => 'object',   isa => 'Geo::Location::Point', optional => 1 }
  629:     # list context:   { type => 'arrayref', of  => { isa => 'Geo::Location::Point' } }
  630: 
  631: =head4 provenance
  632: 
  633: Every result carries C<geocoder>, C<database>, C<confidence> and C<accuracy>
  634: which distribution produced
  635: it, which backend answered, how good the match was, and how precise the
  636: coordinate is.  C<provenance()> reads the four back.  C<location> is set by every
  637: path but the MaxMind cities one, and C<text> only by a scantext lookup; C<lat>,
  638: C<long> and C<lng> come from the value object itself.
  639: 
  640: =head3 MESSAGES
  641: 
  642:     Usage: ...::geocode(...)        No location or scantext argument given.
  643:     invalid location to geocode()   location is purely numeric.
  644:     invalid scantext to geocode()   scantext is purely numeric.
  645:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  646: 
  647: =head3 PSEUDOCODE
  648: 
  649:     if self is not a blessed object -> delegate to new()->geocode(@args)
  650:     normalise @_ into %params
  651:     validate: on_error is 'croak' or 'undef' (croak if not)
  652:     validate: location is not purely numeric; scantext is not purely numeric
  653:               (undef instead of croaking when on_error is 'undef')
  654:     if openaddr backend is available:
  655:         if scantext:
  656:             try the raw scantext string as a direct location
  657:             build stopword set from %_COMMON_WORDS + ignore_words param
  658:             try 3-word windows (triplets) at confidence 0.8
  659:             try 2-word windows (duplets) at confidence 0.7
  660:             try the address-pattern regex at confidence 0.7
  661:             try region-specific address finders (GB / US / CA / IE)
  662:             mark scantext as a miss; return undef
  663:         else:
  664:             try openaddr backend
  665:             try local backend
  666:             try __DATA__ alternatives map
  667:     try maxmind backend for location lookups
  668:     croak if no scantext and no location
  669:

  672: sub geocode {
  673: 	my $self = shift;
  674: 
  675: 	# Handle being called as a function rather than a method
  676: 	if (!ref($self)) {
  677: 		if (scalar @_) {
  678: 			return __PACKAGE__->new()->geocode(@_);
  679: 		} elsif (!defined($self)) {
  680: 			Carp::croak(_i18n('usage_geocode', __PACKAGE__));
  681: 		} elsif ($self eq __PACKAGE__) {
  682: 			Carp::croak(_i18n('usage_geocode', $self));
  683: 		}
  684: 		return __PACKAGE__->new()->geocode($self);
  685: 	} elsif (ref($self) eq 'HASH') {
  686: 		return __PACKAGE__->new()->geocode($self);
  687: 	}
  688: 
  689: 	my %params = _normalize_args(_i18n('usage_geocode', __PACKAGE__), 'location', @_);
  690: 
  691: 	# What to do with an input this module rejects before it touches a backend.
  692: 	# 'croak' is the historical behaviour and stays the default, so no existing
  693: 	# caller changes; 'undef' is for a batch caller working down a dirty column,
  694: 	# which wants the row skipped rather than the whole run killed.  Only the two
  695: 	# input errors below consult it: a backend that throws still throws, because
  696: 	# nothing here is wrapped in an eval
  697: 	my $on_error = $params{'on_error'} // 'croak';
  698: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  699: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  700: 
  701: 	# Reject pure-numeric inputs early - they are never valid addresses.
  702: 	# The rule is Geo::Location::Predicate's, the same one the backends
  703: 	# apply, and valid_location() answers it in public, so a caller can
  704: 	# pre-filter with it and never reach this croak at all.
  705: 	if (defined($params{'location'}) && !_valid_location($params{'location'})) {
  706: 		return if !length($params{'location'}) || ($on_error eq 'undef');
  707: 		Carp::croak(_i18n('invalid_location', __PACKAGE__, $params{'location'}));
  708: 	}
  709: 	if (defined($params{'scantext'}) && !_valid_location($params{'scantext'})) {
  710: 		return if !length($params{'scantext'}) || ($on_error eq 'undef');
  711: 		Carp::croak(_i18n('invalid_scantext', __PACKAGE__, $params{'scantext'}));
  712: 	}
  713: 
  714: 	if ($self->{'openaddr'}) {
  715: 		if (my $scantext = $params{'scantext'}) {
  716: 			my $miss_key = _scantext_miss_key($scantext, $params{'region'}, $params{'ignore_words'});
  717: 			return if $self->_scantext_missed($miss_key);
  718: 
  719: 			# First try the whole scantext as a direct location lookup -
  720: 			# saves work when the text happens to be a valid address string.
  721: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  722: 			my @direct = grep { defined }
  723: 				$self->{'local'}->geocode($scantext),
  724: 				$self->{'openaddr'}->geocode($scantext),
  725: 				$self->{'maxmind'}->geocode($scantext);
  726: 			return wantarray ? @direct : $direct[0] if @direct;
  727: 
  728: 			my $region = $params{'region'};
  729: 			my $country = defined($region) ? ($_REGION_COUNTRY{uc $region} // $region) : undef;
  730: 			# An ISO code is upper case to the parsers, whatever it was given in
  731: 			$country = uc($country) if defined($country) && ($country =~ /\A[a-z]{2}\z/);
  732: 
  733: 			# Build the effective stopword set.  When the caller supplies no
  734: 			# ignore_words we avoid copying %_COMMON_WORDS (which is immutable
  735: 			# at runtime) by using a reference to it directly.  Only when extra
  736: 			# words are needed do we allocate and populate a merged hash.
  737: 			my $ignore_words;
  738: 			if (my $iw = $params{'ignore_words'}) {
  739: 				my %merged = %_COMMON_WORDS;
  740: 				$merged{lc $_} = 1 for @{$iw};
  741: 				$ignore_words = \%merged;
  742: 			} else {
  743: 				$ignore_words = \%_COMMON_WORDS;
  744: 			}
  745: 
  746: 			# 3-word window search
  747: 			my @triplets = _find_word_ngrams($scantext, 3, $ignore_words);
  748: 			my $res = $self->_resolve_scan_candidates(\@triplets, $country, $CONF_TRIPLET, $scantext);
  749: 			if (@{$res}) {
  750: 				return wantarray ? @{$res} : $res->[0];
  751: 			}
  752: 
  753: 			# 2-word window search
  754: 			my @duplets = _find_word_ngrams($scantext, 2, $ignore_words);
  755: 			$res = $self->_resolve_scan_candidates(\@duplets, $country, $CONF_DUPLET, $scantext);
  756: 			if (@{$res}) {
  757: 				return wantarray ? @{$res} : $res->[0];
  758: 			}
  759: 
  760: 			# Regex-based address pattern - catches "City, ST"-style fragments.
  761: 			# Note: misses sentences like "born May 21, 1937 in Noblesville, IN"
  762: 			# because the pattern requires a capitalised word before the city.
  763: 			my @regex_matches = $scantext =~
  764: 				/\b(?:\d+\s+)?(?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*\.?),\s*
  765: 				 (?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*(?:,\s*[A-Z]{2,})*)\b/gx;
  766: 			my @places = grep { defined && $_ ne '' } @regex_matches;
  767: 			$res = $self->_resolve_scan_candidates(\@places, $country, $CONF_REGEX, $scantext);
  768: 			if (@{$res}) {
  769: 				return wantarray ? @{$res} : $res->[0];
  770: 			}
  771: 
  772: 			# Region-specific structured address patterns
  773: 			if ($region) {
  774: 				my @candidates;
  775: 				my $code = uc $region;
  776: 				if    ($code eq 'GB') { @candidates = _find_gb_addresses($scantext) }
  777: 				elsif ($code eq 'US') { @candidates = _find_us_addresses($scantext) }
  778: 				elsif ($code eq 'CA') { @candidates = _find_ca_addresses($scantext) }
  779: 				# Irish addresses are written in the same comma-separated
  780: 				# "street, town, county, country" form as British ones
  781: 				elsif ($code eq 'IE') { @candidates = _find_gb_addresses($scantext) }
  782: 
  783: 				if (@candidates) {
  784: 					my @regional;
  785: 					for my $candidate (@candidates) {
  786: 						next if $ignore_words->{lc $candidate};
  787: 						my @hits = grep { defined }
  788: 							$self->{'openaddr'}->geocode("$candidate, $country");
  789: 						push @regional, @hits if @hits;
  790: 					}
  791: 					return wantarray ? @regional : $regional[0] if @regional;
  792: 				}
  793: 			}
  794: 
  795: 			$self->_remember_scantext_miss($miss_key);
  796: 			return;
  797: 		}
  798: 
  799: 		# Standard (non-scantext) lookup path
  800: 		if (wantarray) {
  801: 			my @rc = $self->{'openaddr'}->geocode(\%params);
  802: 			return @rc if @rc && $rc[0];
  803: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  804: 			@rc = $self->{'local'}->geocode(\%params);
  805: 			return @rc if @rc && $rc[0];
  806: 		} else {
  807: 			if (my $rc = $self->{'openaddr'}->geocode(\%params)) {
  808: 				return $rc;
  809: 			}
  810: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  811: 			if (my $rc = $self->{'local'}->geocode(\%params)) {
  812: 				return $rc;
  813: 			}
  814: 		}
  815: 
  816: 		# Try the alternatives table - hand-curated mappings for locations that
  817: 		# the databases have under slightly different names.
  818: 		# M3 (transitive reduction): every scantext path inside this block returned
  819: 		# early above; at this point $params{'scantext'} is provably falsy, so the
  820: 		# former `if (!$params{'scantext'})` guard was a tautology - removed.
  821: 		if (my $alt = $self->{'alternatives'}) {
  822: 			my $location = $params{'location'};
  823: 			# Not each(): the recursive geocode() calls below walk the same
  824: 			# hash, sharing and resetting its iterator, so an each() loop here
  825: 			# would start again from the top and retry the same key forever.
  826: 			foreach my $key (sort keys %{$alt}) {
  827: 				next if $_alternatives_active{$key};
  828: 				my $value = $alt->{$key};
  829: 				next unless $location =~ $key;
  830: 				local $_alternatives_active{$key} = 1;
  831: 				(my $new_loc = $location) =~ s/$key/$value/;
  832: 				$params{'location'} = $new_loc;
  833: 				if (my $rc = $self->geocode(\%params)) {
  834: 					return $rc;
  835: 				}
  836: 				# Also try the comma-free variant ("Tyne and Wear" etc.)
  837: 				if ($value =~ /, /) {
  838: 					(my $flat = $value) =~ s/,//g;
  839: 					($new_loc = $location) =~ s/$key/$flat/;
  840: 					$params{'location'} = $new_loc;
  841: 					if (my $rc = $self->geocode(\%params)) {
  842: 						return $rc;
  843: 					}
  844: 				}
  845: 				# Restore for the next iteration
  846: 				$params{'location'} = $location;
  847: 			}
  848: 		}
  849: 	}
  850: 
  851: 	# Final fallback: MaxMind for location lookups.
  852: 	# Scantext without OPENADDR_HOME falls through this to the warning below.
  853: 	# M8 (tautology elimination): both arms of the former wantarray ternary were
  854: 	# identical - collapsed to a single call; context propagates implicitly.
  855: 	if ($params{'location'}) {
  856: 		return $self->{'maxmind'}->geocode(\%params);
  857: 	}
  858: 
  859: 	Carp::croak(_i18n('usage_geocode', __PACKAGE__)) unless $params{'scantext'};
  860: 
  861: 	# Once per object: a caller scanning a whole file doesn't want a line each
  862: 	Carp::carp(_i18n('scantext_needs_oa', __PACKAGE__)) unless $self->{'warned_scantext'}++;
  863: 	return;
  864: }

  866: =head2 geocode_many
  867: 
  868: =head3 SYNOPSIS
  869: 
  870:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  871: 
  872:     for my $place (@places) {
  873:         my $pt = $batch->{$place};              # a Geo::Location::Point, or undef
  874:         next unless defined $pt;
  875:         printf "%s is at %.4f, %.4f\n", $place, $pt->lat(), $pt->long();
  876:     }
  877: 
  878:     printf "geocoded %d of %d places in %d lookups\n",
  879:         $batch->{'resolved'},
  880:         $batch->{'resolved'} + $batch->{'unresolved'},
  881:         $batch->{'lookups'};
  882: 
  883: =head3 DESCRIPTION
  884: 
  885: The loop a batch caller writes around C<geocode()>, run for it: one lookup per
  886: B<distinct> value, with the same options and the same results, plus the counts
  887: that caller would otherwise keep itself - how many values made a backend read,
  888: how many resolved, how many did not, which ones, and which backend read for them
  889: 
  890: The hashref returned holds one entry per distinct value given, keyed by the
  891: value, plus five keys of its own:
  892: 
  893: =over 4
  894: 
  895: =item * C<< $batch->{$value} >> - the C<Geo::Location::Point> the value resolved
  896: to, or C<undef> if nothing did.  Every distinct value in the input is keyed, so
  897: a caller walking a column can look each row up without first asking whether the
  898: batch covered it.  An C<undef> in the input has no key of its own and shares the
  899: entry of the empty string, which is not a location either.
  900: 
  901: =item * C<lookups> - how many distinct values made a backend read to answer
  902: them: one per value, however many backends looked at it.  A value the module
  903: refuses before any backend is touched - a bare number, C<''>, C<undef>, a
  904: reference - is not counted, and neither is a value a backend answered from a
  905: cache or from a hand-curated entry, because nothing was read for it.  This is
  906: what makes the count the work a caller is capping rather than the work it asked
  907: for.  A value repeated in the batch is one lookup.  Every backend reports its
  908: reads through C<reads()>, and a value every backend has already missed is
  909: remembered in L<Geo::Coder::Free::MissCache>, one process-level cache that all
  910: backends and instances share, whose entries expire after an hour and can be
  911: emptied early with L</clear_miss_cache>.  A later batch in the same process is
  912: answered from those caches and so reports the reads it needed, often none, in
  913: place of the ones the first batch made.
  914: 
  915: =item * C<reads> - how many reads each backend made for the batch, keyed by the
  916: name C<provenance()> reports that backend under: C<MaxMind>, C<Local> or
  917: C<OpenAddresses>.  Every backend the object holds is named, at zero for one that
  918: read nothing, so a batch answered from a cache names its backends at zero rather
  919: than naming none.  C<lookups> counts values and this counts reads - a value that
  920: made two backends read is one lookup and a read for each of them, so these
  921: numbers can add up to more than C<lookups> - and the two vocabularies are the
  922: same, so a caller can put the backend that read a value beside the backend a
  923: result came from.
  924: 
  925: =item * C<resolved> - how many distinct values produced a point.
  926: 
  927: =item * C<unresolved> - how many produced nothing, the refused values included.
  928: 
  929: =item * C<unresolved_values> - those values, in the order they were first seen,
  930: so that a caller can record them as tried-and-failed rather than retrying them
  931: on every request.  Section 2.5 sketches this list under the name C<unresolved>;
  932: here C<unresolved> is the count a "geocoded N of M" message needs and the values
  933: themselves are C<unresolved_values>.
  934: 
  935: =back
  936: 
  937: C<resolved> and C<unresolved> always add up to the number of distinct values
  938: given, and the five keys above are reserved: a value equal to one of them is
  939: refused by name, before anything is looked up, rather than allowed to overwrite
  940: a count.
  941: 
  942: C<region> and C<on_error> are handed to every lookup and mean there what they
  943: mean in C<geocode()>, including the rule that a backend exception is still an
  944: exception - nothing here is wrapped in an C<eval>.  C<on_error> defaults to
  945: C<'croak'> for the same reason it does there: a batch should not quietly plot
  946: fewer points than its column holds unless the caller asked it to, and a caller
  947: working down a dirty column asks for C<'undef'>.  The two settings do not differ
  948: in which values are looked up, only in what happens to a value the module
  949: refuses: C<'croak'> dies on it with the message C<geocode()> gives for it,
  950: C<'undef'> counts it unresolved and carries on.
  951: 
  952: A batch of no values is not an error: the counts come back zero.
  953: 
  954: The values are treated as a set.  Repeating a value in the input looks it up
  955: once and every row is keyed to the same point object, so a column that repeats
  956: the same handful of places thousands of times costs the handful of lookups.
  957: 
  958: =head3 API SPECIFICATION
  959: 
  960: =head4 input
  961: 
  962:     # Input schema (Params::Validate::Strict) - values required, options optional
  963:     values   => { type => 'arrayref' }                  # location strings, one per row
  964:     region   => { type => 'scalar', optional => 1 }     # ISO 3166-1 alpha-2 country code hint
  965:     on_error => { type => 'scalar', optional => 1 }     # 'croak' (the default) or 'undef'
  966: 
  967: The domain of each parameter:
  968: 
  969: =over 4
  970: 
  971: =item * C<values> - an arrayref of any size, from none up.  Anything that is not
  972: an arrayref, or none at all, croaks C<Usage:>.  Each row is a C<location> as
  973: C<geocode()> defines it, in any characters, and keys the result as given.
  974: C<undef> and C<''> are one value, which is unresolved on either C<on_error>
  975: setting.  A string only of digits, or a reference, follows C<on_error>.
  976: 
  977: =item * A reserved value - C<lookups>, C<reads>, C<resolved>, C<unresolved> and
  978: C<unresolved_values>, spelled exactly, croak on either C<on_error> setting before
  979: anything is looked up.  C<Lookups> or C<' resolved'> are ordinary values.
  980: 
  981: =item * C<region> - any string, handed to every lookup as it is.
  982: 
  983: =item * C<on_error> - as for C<geocode()>.  It is checked first, so a bad setting
  984: croaks even with no values, or with a reserved value.
  985: 
  986: =item * The options - a hashref or an even list of non-references.  A lone scalar,
  987: an odd list, an arrayref or a reference as a value croak C<Usage:>.
  988: 
  989: =back
  990:

  992: 
  993:     # Output schema (Return::Set)
  994:     { type => 'hashref' }

 1038: sub geocode_many {
 1039: 	my $self = shift;
 1040: 
 1041: 	# The same calling conventions as the rest of the module, with the batch's
 1042: 	# own spelling for the plain-function form: the values are always an
 1043: 	# arrayref, so that is what a function call arrives holding.
 1044: 	if (!Scalar::Util::blessed($self)) {
 1045: 		return __PACKAGE__->new()->geocode_many($self, @_)
 1046: 			if ref($self) eq 'ARRAY';
 1047: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless @_;
 1048: 		return __PACKAGE__->new()->geocode_many(@_);
 1049: 	}
 1050: 
 1051: 	my $values = shift;
 1052: 	Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless ref($values) eq 'ARRAY';
 1053: 
 1054: 	# Options are a hashref or an even list.  A lone scalar is neither: there is
 1055: 	# no bare-string form of a batch, so it is refused rather than guessed at.
 1056: 	my $opts;
 1057: 	if (@_ == 1 && ref($_[0]) eq 'HASH') {
 1058: 		$opts = { %{$_[0]} };
 1059: 	} elsif ((scalar @_) % 2 == 0 && !grep { ref } @_) {
 1060: 		$opts = { @_ };
 1061: 	} else {
 1062: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__));
 1063: 	}
 1064: 
 1065: 	my $on_error = $opts->{'on_error'} // 'croak';
 1066: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
 1067: 		unless $on_error eq 'croak' || $on_error eq 'undef';
 1068: 
 1069: 	my $region = $opts->{'region'};
 1070: 
 1071: 	# A value spelled like one of the keys this method answers with would
 1072: 	# overwrite it, so it is refused by name - before anything is looked up,
 1073: 	# rather than after a count has been lost.
 1074: 	my %reserved = map { $_ => 1 } @RESULT_KEYS;
 1075: 	for my $value (@{$values}) {
 1076: 		my $key = defined($value) ? $value : '';
 1077: 		Carp::croak(_i18n('reserved_location', __PACKAGE__, $key)) if $reserved{$key};
 1078: 	}
 1079: 
 1080: 	my %results = map { $_ => 0 } @RESULT_KEYS;
 1081: 	$results{'unresolved_values'} = [];
 1082: 	$results{'reads'} = {};
 1083: 
 1084: 	# A batch is a set: a value repeated in the input is looked up once, and
 1085: 	# every row holding it is keyed to the same object.
 1086: 	my %seen;
 1087: 	for my $value (@{$values}) {
 1088: 		# undef has no key of its own, and the empty string it shares is not a
 1089: 		# location either, so it is unresolved without reaching a backend.
 1090: 		my $key = defined($value) ? $value : '';
 1091: 		next if $seen{$key}++;
 1092: 
 1093: 		# What geocode() makes of this value on this setting is asked of
 1094: 		# geocode() rather than written out again here: the guard, its message and
 1095: 		# the choice of backend are all its own.  The backends' read counters are
 1096: 		# taken around the call, so the value is counted as a lookup only if one of
 1097: 		# them actually read: a value answered from a cache, or from a hand-curated
 1098: 		# entry, is not counted as work the batch did not do.  Taking them per
 1099: 		# backend rather than in total says which backend read, and which answered
 1100: 		# from somewhere else: a read is added to the name of the backend that made
 1101: 		# it, so a value two backends read through is one lookup and a read each.
 1102: 		my $reads_before = $self->_backend_reads();
 1103: 		my $point = $self->geocode(
 1104: 			location => $key,
 1105: 			defined($region) ? (region => $region) : (),
 1106: 			on_error => $on_error,
 1107: 		);
 1108: 		my $reads_after = $self->_backend_reads();
 1109: 
 1110: 		my $read = 0;
 1111: 		foreach my $backend (keys %{$reads_after}) {
 1112: 			my $reads = $reads_after->{$backend} - ($reads_before->{$backend} // 0);
 1113: 			next unless $reads > 0;
 1114: 			$results{'reads'}{$backend} += $reads;
 1115: 			$read += $reads;
 1116: 		}
 1117: 
 1118: 		# A value the module refuses is not a lookup: it never reached a backend,
 1119: 		# so it does not count against the work a caller is capping.
 1120: 		$results{'lookups'}++ if _valid_location($key) && $read;
 1121: 		$results{$key} = $point;
 1122: 
 1123: 		if (defined($point)) {
 1124: 			$results{'resolved'}++;
 1125: 		} else {
 1126: 			$results{'unresolved'}++;
 1127: 			push @{$results{'unresolved_values'}}, $value;
 1128: 		}
 1129: 	}
 1130: 
 1131: 	# A backend that read nothing is reported as well, at zero: what a caller is
 1132: 	# asking is which backend read and which answered from a cache, and a backend
 1133: 	# left out of the answer cannot be told from one that answered from one.
 1134: 	# Local is built the first time a lookup falls through to it, so it appears
 1135: 	# once it has been consulted, whether or not it found anything.
 1136: 	foreach my $backend (keys %{$self->_backend_reads()}) {
 1137: 		$results{'reads'}{$backend} //= 0;
 1138: 	}
 1139: 
 1140: 	return \%results;
 1141: }
 1142: 
 1143: # How much reading each backend has done so far, by the name it is reported
 1144: # under.  Counters rather than flags: the change across a call says which
 1145: # backend read for that value, and a backend that was never called cannot leave
 1146: # a stale flag behind.  A backend object may not exist yet - Local is built on
 1147: # first use - and a test may hand the facade a stand-in, so each slot is asked
 1148: # only if it holds something that can answer.
 1149: sub _backend_reads {
 1150: 	my $self = shift;
 1151: 
 1152: 	my %reads;
 1153: 	foreach my $slot (sort keys %_BACKEND_NAMES) {
 1154: 		my $backend = $self->{$slot} or next;
 1155: 		next unless Scalar::Util::blessed($backend) && $backend->can('reads');
 1156: 		$reads{$_BACKEND_NAMES{$slot}} = $backend->reads() // 0;
 1157: 	}
 1158: 
 1159: 	return \%reads;
 1160: }

 1207: =head2 provenance
 1208: 
 1209:     my ($dist, $backend, $confidence, $accuracy) = $geocoder->provenance($point);
 1210:

 1212: 
 1213:     my $provenance = $geocoder->provenance($point);
 1214:     print $provenance->{'backend'};

 1217: reach for the hash keys itself:
 1218: 
 1219: =over 4
 1220: 
 1221: =item * C<$dist> - the distribution that produced the result: the C<geocoder>
 1222: key, C<Geo::Coder::Free> for a result from this distribution, or the wrapper
 1223: that passed it on, such as C<Geo::Coder::List>.
 1224: 
 1225: =item * C<$backend> - which backend answered, in a short vocabulary: C<Local>,
 1226: C<MaxMind>, C<OpenAddresses> or C<GeoNames>.  This is the C<database> key with

 1230: consumers that already match on it.
 1231:

 1233: 
 1234: =item * C<$accuracy> - how precise the coordinate is: C<address>, C<street>,
 1235: C<postcode>, C<locality>, C<city>, C<region> or C<country>.

 1237: =back

 1448: # Purpose:  Normalise the four calling conventions accepted by geocode/reverse_geocode:
 1449: #             hashref, even-length key-val list, odd-length list, single bare string.
 1450: # Entry:    $error_msg - message to croak if a non-hash reference is passed.
 1451: #           $bare_key  - hash key to assign to a single bare string argument
 1452: #                        ('location' for geocode, 'latlng' for reverse_geocode).
 1453: #           @args - raw @_ after $self has been shifted.
 1454: # Exit:     Flat key-value %params hash.
 1455: # Side Effects: None; croaks on unsupported reference argument.
 1456: sub _normalize_args {
 1457: 	my ($error_msg, $bare_key, @args) = @_;
 1458: 	return %{$args[0]}              if ref($args[0]) eq 'HASH';
 1459: 	Carp::croak($error_msg)         if ref($args[0]);
 1460: 	return @args                    if @args && @args % 2 == 0;
 1461: 	return ($bare_key => $args[0])  if @args == 1;
 1462: 	# M7 (logic-gap closure): odd-count > 1 is not a valid calling convention.
 1463: 	# The former code silently returned () here, discarding the trailing elements.
 1464: 	# Fail fast instead of propagating a malformed argument list downstream.
 1465: 	Carp::croak($error_msg)         if @args;
 1466: 	return ();
 1467: }

 1469: # Purpose:  Try to geocode each candidate place string via the openaddr backend,
 1470: #           annotating every hit with location/text/confidence metadata and
 1471: #           memoising misses to avoid re-querying the same failing string.
 1472: # Entry:    $self       - geocoder instance with {openaddr} and {scantext_misses}.
 1473: #           $candidates - arrayref of place-name strings to probe.
 1474: #           $region     - optional country appended to each candidate: an ISO
 1475: #                         code, or the name from %_REGION_COUNTRY.
 1476: #           $confidence - numeric confidence score assigned to all hits.
 1477: #           $scantext   - original free text (stored inside each result object).
 1478: # Exit:     Arrayref of Geo::Location::Point objects; empty arrayref on no hits.
 1479: # Side Effects: Populates $self->{scantext_misses} for every non-matching place.
 1480: sub _resolve_scan_candidates {
 1481: 	my ($self, $candidates, $region, $confidence, $scantext) = @_;
 1482: 	my @results;
 1483: 	for my $place (@{$candidates}) {
 1484: 		my $location = $region ? "$place, $region" : $place;
 1485: 		next if $self->_scantext_missed($location);
 1486: 		my @res = grep { defined } $self->{'openaddr'}->geocode($location);
 1487: 		if (@res) {
 1488: 			for my $entry (@res) {
 1489: 				$entry->{'location'}   = $location;
 1490: 				$entry->{'text'}       = $scantext;
 1491: 				$entry->{'confidence'} = $confidence;
 1492: 			}
 1493: 			push @results, @res;
 1494: 		} else {
 1495: 			$self->_remember_scantext_miss($location);
 1496: 		}
 1497: 	}
 1498: 	return \@results;
 1499: }

 1501: # Purpose:  The key a scantext miss is remembered under.  A miss depends on what
 1502: #           was searched for, so a different region or ignore_words is another search.
 1503: # Entry:    $text; $region and $ignore_words as given to geocode(), or undef.
 1504: # Exit:     The text itself when there are no options, otherwise a composite key.
 1505: sub _scantext_miss_key {
 1506: 	my ($text, $region, $ignore_words) = @_;
 1507: 
 1508: 	my @words = $ignore_words ? sort(map { lc($_) } @{$ignore_words}) : ();
 1509: 	return $text if !length($region // '') && !@words;
 1510: 
 1511: 	return join("\0", $text, uc($region // ''), @words);
 1512: }

 1514: # Purpose:  Is this key a scantext miss that has not expired?
 1515: # Side Effects: Forgets everything after clear_miss_cache(), and an expired entry.
 1516: sub _scantext_missed {
 1517: 	my ($self, $key) = @_;
 1518: 
 1519: 	my $misses = $self->{'scantext_misses'} or return 0;
 1520: 	if (($self->{'scantext_generation'} // 0) != $_scantext_generation) {
 1521: 		%{$misses} = ();
 1522: 		$self->{'scantext_generation'} = $_scantext_generation;
 1523: 		return 0;
 1524: 	}
 1525: 
 1526: 	my $expires_at = $misses->{$key} // return 0;
 1527: 	return 1 if $expires_at > time();
 1528: 	delete $misses->{$key};
 1529: 
 1530: 	return 0;
 1531: }

 1533: # Purpose:  Remember a scantext miss for as long as MissCache remembers a miss.
 1534: # Side Effects: Starts again rather than grow past $SCANTEXT_MISS_LIMIT entries.
 1535: sub _remember_scantext_miss {
 1536: 	my ($self, $key) = @_;
 1537: 
 1538: 	my $misses = $self->{'scantext_misses'} //= {};
 1539: 	%{$misses} = () if keys(%{$misses}) >= $SCANTEXT_MISS_LIMIT;
 1540: 	$misses->{$key} = time() + Geo::Coder::Free::MissCache->expires_after();

 1546: # Purpose:  Slide a window of $n words across $text and return all comma-joined
 1547: #           n-grams, excluding pure-numeric tokens and stopwords.  A token of
 1548: #           digits only is not a word of a place name, which is the question
 1549: #           Geo::Location::Predicate::_valid_location() answers, so it is asked
 1550: #           there rather than spelled out here (t/location-rule.t fails if the
 1551: #           rule is written out again).
 1552: #           Replaces the former _find_word_triplets ($n=3) and
 1553: #           _find_word_duplets ($n=2) which were identical except for window size
 1554: #           and the duplets version was missing the lc() normalisation on stopwords.
 1555: # Entry:    $text - raw string; $n - window size; $stop - stopword hashref.
 1556: # Exit:     Flat list of n-gram strings.
 1557: sub _find_word_ngrams {
 1558: 	my ($text, $n, $stop) = @_;
 1559: 	$text =~ s/,+/ /g;
 1560: 	$text =~ s/\s+/ /g;
 1561: 	$text =~ s/^\s+|\s+$//g;
 1562: 	my @words = grep { !$stop->{lc $_} && _valid_location($_) } split /\s+/, $text;
 1563: 	my @ngrams;
 1564: 	for my $i (0 .. $#words - ($n - 1)) {
 1565: 		push @ngrams, join ', ', @words[$i .. $i + $n - 1];
 1566: 	}
 1567: 	return @ngrams;
 1568: }

 1570: # Purpose:  Extract structured US street addresses from free text.
 1571: # Entry:    $text - arbitrary string.
 1572: # Exit:     List of full address strings matching the US pattern.
 1573: sub _find_us_addresses {
 1574: 	my $text = shift;
 1575: 	my @addresses;
 1576: 	my $re = qr/
 1577: 		\b \d{1,5} \s+                                      # house number
 1578: 		(?:[A-Za-z0-9]+(?:\s+[A-Za-z0-9]+){0,6}) \s+       # street name: 1-7 words (bounded)
 1579: 		(?:Avenue|Ave\.?|Boulevard|Blvd\.?|Road|Rd\.?|Lane|Ln\.?|Drive|Dr\.?|Street|St\.?)
 1580: 		(?:\s+[A-Za-z]{2})? ,\s*
 1581: 		(?:[A-Za-z]+(?:\s+[A-Za-z]+){0,3}) ,\s*            # city: 1-4 words
 1582: 		[A-Z]{2} \s* (?:\d{5}(?:-\d{4})?)? \b              # state + optional zip
 1583: 	/x;
 1584: 	while ($text =~ /$re/g) {
 1585: 		push @addresses, $&;
 1586: 	}
 1587: 	return @addresses;
 1588: }

 1590: # Purpose:  Extract British-style addresses from free text.
 1591: # Entry:    $text - arbitrary string.
 1592: # Exit:     List of trimmed address strings.
 1593: sub _find_gb_addresses {
 1594: 	my $text = shift;
 1595: 	my @addresses;
 1596: 	# ReDoS fix: the former pattern used \s*,?\s* between all parts and
 1597: 	# [A-Za-z\s'-]+ groups - with commas optional, the engine must try all
 1598: 	# possible splits of a long string among 5 overlapping space-containing
 1599: 	# groups, causing exponential backtracking.  Making commas mandatory
 1600: 	# eliminates the ambiguity entirely: UK postal addresses always have commas.
 1601: 	# All groups are non-capturing (only $& is used).
 1602: 	my $re = qr/
 1603: 		\b
 1604: 		(?:\d{1,5} | [\w'-]+)                   # house number or single-word name
 1605: 		\s+
 1606: 		(?:[\w'-]+(?:\s+[\w'-]+){0,5})           # street name (up to 6 words)
 1607: 		\s*,\s*                                   # COMMA REQUIRED - kills the ambiguity
 1608: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # town (up to 4 words)
 1609: 		\s*,\s*                                   # COMMA REQUIRED
 1610: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # county (up to 4 words)
 1611: 		\s*,\s*                                   # COMMA REQUIRED
 1612: 		(?:[\w'-]+(?:\s+[\w'-]+){0,2})           # country (up to 3 words)
 1613: 		\b
 1614: 	/x;
 1615: 	while ($text =~ /$re/g) {
 1616: 		(my $addr = $&) =~ s/[,\s]+$//;
 1617: 		push @addresses, $addr;
 1618: 	}
 1619: 	return @addresses;
 1620: }

 1645: =head1 GETTING STARTED
 1646: 
 1647: To download, import and set up the local database:
 1648: before running C<make>, but after running C<perl Makefile.PL>, follow these instructions.
 1649: 
 1650: Optionally set C<OPENADDR_HOME> to point to an empty directory and download the data from
 1651: L<http://results.openaddresses.io> into that directory; and
 1652: optionally set C<WHOSONFIRST_HOME> to point to an empty directory and download the data using
 1653: L<https://github.com/nigelhorne/NJH-Snippets/blob/master/bin/wof-clone>.
 1654: The script C<bin/download_databases> (see below) will do those for you.
 1655: You do not need to download the MaxMind data - that is downloaded automatically.
 1656: 
 1657: You will need to create the database used by C<Geo::Coder::Free>.
 1658: 
 1659: Install L<App::csv2sqlite> and L<https://github.com/nigelhorne/NJH-Snippets>.
 1660: Run C<bin/create_sqlite> - this converts the MaxMind "cities" database from CSV to SQLite.
 1661: 
 1662: To use with MariaDB, set C<MARIADB_SERVER="$hostname;$port"> and
 1663: C<MARIADB_USER="$user;$password"> (TODO: username/password should be asked for interactively).
 1664: The code will use a database called C<geo_code_free>, which will be dropped and recreated if it exists.
 1665: C<$user> needs only DROP, CREATE, SELECT, INSERT, and INDEX privileges on that database.
 1666: 
 1667: The following optional steps download and install large databases.
 1668: This will take a long time and use a lot of disc space.
 1669: 
 1670: =over 4
 1671: 
 1672: =item 1
 1673: 
 1674: C<mkdir $WHOSONFIRST_HOME; cd $WHOSONFIRST_HOME> then run C<wof-clone> from NJH-Snippets.
 1675: 
 1676: This can take a long time because it contains many nested directories, which filesystem drivers
 1677: can be slow to navigate (particularly on EXT4 and ZFS).
 1678: 
 1679: =item 2
 1680: 
 1681: Install L<https://github.com/dr5hn/countries-states-cities-database.git> into C<$DR5HN_HOME>.
 1682: This data covers cities only, so it is not used when C<OSM_HOME> is set (OSM is far more
 1683: comprehensive).  Only Australia, Canada, and the US are imported, as the UK data is difficult
 1684: to parse.
 1685: 
 1686: =item 3
 1687: 
 1688: Run C<bin/download_databases> - this downloads the Who's On First, OpenAddr, OpenStreetMap,
 1689: and dr5hn databases.
 1690: OpenStreetMap now uses PBF files, so you will need C<apt install osmium-tool> first.
 1691: Check the values of C<OSM_HOME>, C<OPENADDR_HOME>, C<DR5HN_HOME> and C<WHOSONFIRST_HOME>
 1692: within that script and adjust them for your setup.
 1693: The C<Makefile.PL> file downloads the MaxMind database automatically, as it is not optional.
 1694: 
 1695: =item 4
 1696: 
 1697: Run C<bin/create_db> - this creates the database used by C<Geo::Coder::Free> from the data you
 1698: have just downloaded.
 1699: The database is called C<openaddr.sql> for historical reasons (before Who's On First was added);
 1700: it actually contains data from all sources above.
 1701: 
 1702: =back
