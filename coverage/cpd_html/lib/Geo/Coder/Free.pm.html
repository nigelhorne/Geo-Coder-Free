  104: =head1 DESCRIPTION
  105: 
  106: C<Geo::Coder::Free> translates addresses into latitude/longitude coordinates
  107: using local SQLite databases built from free data sources - MaxMind/GeoNames,
  108: OpenAddresses, Who's On First, OpenStreetMap, and dr5hn's countries/states/cities
  109: database.  It deliberately avoids paid or rate-limited online geocoding services.
  110: The module is designed to be flexible, supporting both command-line and programmatic usage.
  111: It also includes a sample CGI script for a web-based geocoding service.
  112: 
  113: Geocoding dispatch order depends on whether C<OPENADDR_HOME> (or C<openaddr>) is set:
  114: 
  115: B<With OpenAddresses data:>
  116: 
  117: =over 4
  118: 
  119: =item 1. C<Geo::Coder::Free::OpenAddresses> - requires C<OPENADDR_HOME>
  120: 
  121: =item 2. C<Geo::Coder::Free::Local> - user-curated CSV entries (tried as fallback)
  122: 
  123: =item 3. C<Geo::Coder::Free::MaxMind> - bundled, always available
  124: 
  125: =back
  126: 
  127: B<Without OpenAddresses data:>
  128: 
  129: =over 4
  130: 
  131: =item 1. C<Geo::Coder::Free::MaxMind> only - Local is not consulted.
  132: 
  133: =back
  134: 
  135: The C<cgi-bin> directory contains a simple DIY geo-coding website:
  136: 
  137:     cgi-bin/page.fcgi page=query q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA
  138: 
  139: The sample website is currently down while a new host is sought.
  140: When it returns, you will be able to test it with:
  141: 
  142:     curl 'https://geocode.nigelhorne.com/cgi-bin/page.fcgi?page=query&q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA'

  144: =head1 LIMITATIONS
  145: 
  146: =over 4
  147: 
  148: =item * C<scantext> mode only finds locations in OpenAddresses; it falls back
  149: silently when C<OPENADDR_HOME> is not set (B<FIXME>: should warn).
  150: 
  151: =item * The C<__DATA__> alternatives table is hard-coded; it should live in a
  152: user-editable config file.
  153: 
  154: =item * The address-regex scantext path misses birth-year sentences such as
  155: C<"She was born May 21, 1937 in Noblesville, IN."> because the regex requires
  156: a preceding capital-letter word directly before the city.
  157: 
  158: =item * C<reverse_geocode> is only partially implemented; the MaxMind path does
  159: not return meaningful results.
  160: 
  161: =item * Without OpenAddresses data, a two-part C<"City, Country"> location is
  162: often answered wrongly.  The MaxMind backend reads the first part as a region
  163: when it can, and answers with the first row it finds in that region, not with
  164: the city: C<"Berlin, Germany"> and C<"Munich, Germany"> both come back at
  165: 52.08, 7.38, and C<"Toronto, Canada"> comes back in British Columbia.  Some
  166: others, such as C<"Paris, France">, are not found at all.  These results carry
  167: C<< accuracy => 'region' >> and C<< confidence => 0.1 >>, so a caller that needs
  168: a city should check L</provenance> and reject them.  Naming the region as well,
  169: as in C<"Munich, Bavaria, Germany">, gives the right answer.
  170: 
  171: =item * Place names are matched as they are spelled in the data, with no
  172: folding of accents: C<"ZE<uuml>rich, Switzerland"> is found and C<"Zurich, Switzerland">
  173: is not.  Pass locations as Perl character strings (decoded, for example by
  174: C<use utf8> or an C<:encoding(UTF-8)> layer), not as undecoded UTF-8 bytes,
  175: since a byte string does not match the name in the data.
  176: 
  177: =back

  357: =head2 valid_location
  358: 
  359: =head3 SYNOPSIS
  360: 
  361:     if ($geo->valid_location($row->{'place'})) {
  362:         push @found, $geo->geocode(location => $row->{'place'});
  363:     }
  364: 
  365: =head3 DESCRIPTION
  366: 
  367: Answers whether a string is something this module will even try to look up.
  368: It is the public form of the rule C<geocode()> applies before it touches a
  369: backend, so a caller working down a spreadsheet column can skip a row whose
  370: value is a bare number - or is empty - instead of catching the croak that
  371: would otherwise kill the whole run.  That rule is defined once, in
  372: L<Geo::Location::Predicate>, and the backends apply it too: what
  373: C<valid_location()> refuses is refused wherever it is looked up.
  374: 
  375: Only that cheap syntactic test is answered.  A true result means the string is
  376: not disqualified, B<not> that a backend knows it: C<'Ramsgate, Kent'> is valid
  377: and may still find nothing, while C<'0044'> is invalid and is never looked up.
  378: The rule rejects a string of digits only, which is what a numeric column holds
  379: when the wrong column has been read, so anything with a non-digit in it counts
  380: as valid - C<'3.14'> and C<'-'> included.  C<undef>, C<''> and a reference are
  381: not valid.
  382: 
  383: =head3 API SPECIFICATION
  384: 
  385: =head4 input
  386: 
  387:     location => { type => 'scalar', optional => 1 }  # the string to test
  388: 
  389: =head4 output
  390: 
  391:     { type => 'boolean' }  # false for undef, '' and a digit-only string
  392: 
  393: =head3 EXAMPLE
  394: 
  395:     my $geo = Geo::Coder::Free->new();

  397:     $geo->valid_location('Ramsgate, Kent');   # true
  398:     $geo->valid_location('0044');             # false - never a location

  400:     $geo->valid_location(undef);              # false

  404:     $geo->valid_location('0044');

  406:     Geo::Coder::Free::valid_location('0044');

  414: 	# predicate reads the same whether it is called on an instance, on the
  415: 	# class or as a plain function.

  418: 		$location = shift;

  428: =head2 geocode
  429: 
  430: =head3 SYNOPSIS
  431: 
  432:     # Standard lookup (returns a Geo::Location::Point or undef)
  433:     my $pt = $geo->geocode(location => 'Ramsgate, Kent, UK');
  434:     printf "lat=%.6f lon=%.6f\n", $pt->lat(), $pt->long();
  435: 
  436:     # Scantext - returns a list of Geo::Location::Point objects
  437:     my @hits = $geo->geocode(
  438:         scantext     => 'She lived in Ramsgate, Kent.',
  439:         region       => 'GB',
  440:         ignore_words => [qw(lived)],
  441:     );
  442: 
  443:     # Invocation flexibility (all equivalent)
  444:     $geo->geocode('Ramsgate, Kent, UK');
  445:     $geo->geocode({ location => 'Ramsgate, Kent, UK' });
  446:     $geo->geocode(location => 'Ramsgate, Kent, UK');
  447: 
  448:     # A batch caller with a dirty column: skip the row, do not kill the run
  449:     for my $place (@column) {
  450:         my $pt = $geo->geocode(location => $place, on_error => 'undef');
  451:         next unless defined $pt;
  452:         push @found, $pt;
  453:     }
  454: 
  455: =head3 DESCRIPTION
  456: 
  457: A location or a scantext that is not a location at all - a bare number, such as
  458: the C<0044> a numeric column holds - is refused before any backend is
  459: touched.  C<valid_location()> answers the same question, so a caller can filter
  460: first; C<on_error> chooses what happens when one gets through anyway:
  461: 
  462: =over 4
  463: 
  464: =item * C<'croak'> (the default) - C<Carp::croak>, the behaviour every existing
  465: caller already has.
  466: 
  467: =item * C<'undef'> - return C<undef>, so one bad row in a spreadsheet column is
  468: skipped rather than ending the run.  It changes the answer for B<only> the two
  469: documented input errors below; an exception from a backend is still an
  470: exception, and a malformed argument list still croaks.
  471: 
  472: =back
  473: 
  474: The option is deliberately narrow, so a batch caller wants C<valid_location()>
  475: with it: that predicate answers false for C<undef> and C<''> as well, which are
  476: the other two things an empty cell holds.  A call with neither a location nor a
  477: scantext is a usage error rather than an input error - the same croak as calling
  478: C<geocode()> with no arguments - and stays a croak on either setting.
  479:

  484:     # Input schema (Params::Validate::Strict) - exactly one of location or scantext is required

  501: it, which backend answered, how good the match was, and how precise the
  502: coordinate is.  C<provenance()> reads the four back.  C<location> is set by every
  503: path but the MaxMind cities one, and C<text> only by a scantext lookup; C<lat>,
  504: C<long> and C<lng> come from the value object itself.
  505: 
  506: =head3 MESSAGES
  507: 
  508:     Usage: ...::geocode(...)        No location or scantext argument given.
  509:     invalid location to geocode()   location is purely numeric.
  510:     invalid scantext to geocode()   scantext is purely numeric.
  511:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  512: 
  513: =head3 PSEUDOCODE
  514: 
  515:     if self is not a blessed object -> delegate to new()->geocode(@args)
  516:     normalise @_ into %params
  517:     validate: on_error is 'croak' or 'undef' (croak if not)
  518:     validate: location is not purely numeric; scantext is not purely numeric
  519:               (undef instead of croaking when on_error is 'undef')
  520:     if openaddr backend is available:
  521:         if scantext:
  522:             try the raw scantext string as a direct location
  523:             build stopword set from %_COMMON_WORDS + ignore_words param
  524:             try 3-word windows (triplets) at confidence 0.8
  525:             try 2-word windows (duplets) at confidence 0.7
  526:             try the address-pattern regex at confidence 0.7
  527:             try region-specific address finders (GB / US / CA / IE)
  528:             mark scantext as a miss; return undef
  529:         else:
  530:             try openaddr backend
  531:             try local backend
  532:             try __DATA__ alternatives map
  533:     try maxmind backend for location lookups
  534:     croak if no scantext and no location

  538: sub geocode {
  539: 	my $self = shift;
  540: 
  541: 	# Handle being called as a function rather than a method
  542: 	if (!ref($self)) {
  543: 		if (scalar @_) {
  544: 			return __PACKAGE__->new()->geocode(@_);
  545: 		} elsif (!defined($self)) {
  546: 			Carp::croak(_i18n('usage_geocode', __PACKAGE__));
  547: 		} elsif ($self eq __PACKAGE__) {
  548: 			Carp::croak(_i18n('usage_geocode', $self));
  549: 		}
  550: 		return __PACKAGE__->new()->geocode($self);
  551: 	} elsif (ref($self) eq 'HASH') {
  552: 		return __PACKAGE__->new()->geocode($self);
  553: 	}
  554: 
  555: 	my %params = _normalize_args(_i18n('usage_geocode', __PACKAGE__), 'location', @_);
  556: 
  557: 	# What to do with an input this module rejects before it touches a backend.
  558: 	# 'croak' is the historical behaviour and stays the default, so no existing
  559: 	# caller changes; 'undef' is for a batch caller working down a dirty column,
  560: 	# which wants the row skipped rather than the whole run killed.  Only the two
  561: 	# input errors below consult it: a backend that throws still throws, because
  562: 	# nothing here is wrapped in an eval
  563: 	my $on_error = $params{'on_error'} // 'croak';
  564: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  565: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  566: 
  567: 	# Reject pure-numeric inputs early - they are never valid addresses.
  568: 	# The rule is Geo::Location::Predicate's, the same one the backends
  569: 	# apply, and valid_location() answers it in public, so a caller can
  570: 	# pre-filter with it and never reach this croak at all.
  571: 	if (defined($params{'location'}) && !_valid_location($params{'location'})) {
  572: 		return if !length($params{'location'}) || ($on_error eq 'undef');
  573: 		Carp::croak(_i18n('invalid_location', __PACKAGE__, $params{'location'}));
  574: 	}
  575: 	if (defined($params{'scantext'}) && !_valid_location($params{'scantext'})) {
  576: 		return if !length($params{'scantext'}) || ($on_error eq 'undef');
  577: 		Carp::croak(_i18n('invalid_scantext', __PACKAGE__, $params{'scantext'}));
  578: 	}
  579: 
  580: 	if ($self->{'openaddr'}) {
  581: 		if (my $scantext = $params{'scantext'}) {
  582: 			return if $self->{'scantext_misses'}{$scantext};
  583: 
  584: 			# First try the whole scantext as a direct location lookup -
  585: 			# saves work when the text happens to be a valid address string.
  586: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  587: 			my @direct = grep { defined }
  588: 				$self->{'local'}->geocode($scantext),
  589: 				$self->{'openaddr'}->geocode($scantext),
  590: 				$self->{'maxmind'}->geocode($scantext);
  591: 			return @direct if @direct;
  592: 
  593: 			my $region = $params{'region'};
  594: 			my $country = defined($region) ? ($_REGION_COUNTRY{uc $region} // $region) : undef;
  595: 
  596: 			# Build the effective stopword set.  When the caller supplies no
  597: 			# ignore_words we avoid copying %_COMMON_WORDS (which is immutable
  598: 			# at runtime) by using a reference to it directly.  Only when extra
  599: 			# words are needed do we allocate and populate a merged hash.
  600: 			my $ignore_words;
  601: 			if (my $iw = $params{'ignore_words'}) {
  602: 				my %merged = %_COMMON_WORDS;
  603: 				$merged{lc $_} = 1 for @{$iw};
  604: 				$ignore_words = \%merged;
  605: 			} else {
  606: 				$ignore_words = \%_COMMON_WORDS;
  607: 			}
  608: 
  609: 			# 3-word window search
  610: 			my @triplets = _find_word_ngrams($scantext, 3, $ignore_words);
  611: 			my $res = $self->_resolve_scan_candidates(\@triplets, $country, $CONF_TRIPLET, $scantext);
  612: 			if (@{$res}) {
  613: 				return wantarray ? @{$res} : $res->[0];
  614: 			}
  615: 
  616: 			# 2-word window search
  617: 			my @duplets = _find_word_ngrams($scantext, 2, $ignore_words);
  618: 			$res = $self->_resolve_scan_candidates(\@duplets, $country, $CONF_DUPLET, $scantext);
  619: 			if (@{$res}) {
  620: 				return wantarray ? @{$res} : $res->[0];
  621: 			}
  622: 
  623: 			# Regex-based address pattern - catches "City, ST"-style fragments.
  624: 			# Note: misses sentences like "born May 21, 1937 in Noblesville, IN"
  625: 			# because the pattern requires a capitalised word before the city.
  626: 			my @regex_matches = $scantext =~
  627: 				/\b(?:\d+\s+)?(?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*\.?),\s*
  628: 				 (?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*(?:,\s*[A-Z]{2,})*)\b/gx;
  629: 			my @places = grep { defined && $_ ne '' } @regex_matches;
  630: 			$res = $self->_resolve_scan_candidates(\@places, $country, $CONF_REGEX, $scantext);
  631: 			if (@{$res}) {
  632: 				return wantarray ? @{$res} : $res->[0];
  633: 			}
  634: 
  635: 			# Region-specific structured address patterns
  636: 			if ($region) {
  637: 				my @candidates;
  638: 				my $code = uc $region;
  639: 				if    ($code eq 'GB') { @candidates = _find_gb_addresses($scantext) }
  640: 				elsif ($code eq 'US') { @candidates = _find_us_addresses($scantext) }
  641: 				elsif ($code eq 'CA') { @candidates = _find_ca_addresses($scantext) }
  642: 				# Irish addresses are written in the same comma-separated
  643: 				# "street, town, county, country" form as British ones
  644: 				elsif ($code eq 'IE') { @candidates = _find_gb_addresses($scantext) }
  645: 
  646: 				if (@candidates) {
  647: 					my @regional;
  648: 					for my $candidate (@candidates) {
  649: 						next if $ignore_words->{lc $candidate};
  650: 						my @hits = grep { defined }
  651: 							$self->{'openaddr'}->geocode("$candidate, $country");
  652: 						push @regional, @hits if @hits;
  653: 					}
  654: 					return @regional if @regional;
  655: 				}
  656: 			}
  657: 
  658: 			$self->{'scantext_misses'}{$scantext} = 1;
  659: 			return;
  660: 		}
  661: 
  662: 		# Standard (non-scantext) lookup path
  663: 		if (wantarray) {
  664: 			my @rc = $self->{'openaddr'}->geocode(\%params);
  665: 			return @rc if @rc && $rc[0];
  666: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  667: 			@rc = $self->{'local'}->geocode(\%params);
  668: 			return @rc if @rc && $rc[0];
  669: 		} else {
  670: 			if (my $rc = $self->{'openaddr'}->geocode(\%params)) {
  671: 				return $rc;
  672: 			}
  673: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  674: 			if (my $rc = $self->{'local'}->geocode(\%params)) {
  675: 				return $rc;
  676: 			}
  677: 		}
  678: 
  679: 		# Try the alternatives table - hand-curated mappings for locations that
  680: 		# the databases have under slightly different names.
  681: 		# M3 (transitive reduction): every scantext path inside this block returned
  682: 		# early above; at this point $params{'scantext'} is provably falsy, so the
  683: 		# former `if (!$params{'scantext'})` guard was a tautology - removed.
  684: 		if (my $alt = $self->{'alternatives'}) {
  685: 			my $location = $params{'location'};
  686: 			# Not each(): the recursive geocode() calls below walk the same
  687: 			# hash, sharing and resetting its iterator, so an each() loop here
  688: 			# would start again from the top and retry the same key forever.
  689: 			foreach my $key (sort keys %{$alt}) {
  690: 				next if $_alternatives_active{$key};
  691: 				my $value = $alt->{$key};
  692: 				next unless $location =~ $key;
  693: 				local $_alternatives_active{$key} = 1;
  694: 				(my $new_loc = $location) =~ s/$key/$value/;
  695: 				$params{'location'} = $new_loc;
  696: 				if (my $rc = $self->geocode(\%params)) {
  697: 					return $rc;
  698: 				}
  699: 				# Also try the comma-free variant ("Tyne and Wear" etc.)
  700: 				if ($value =~ /, /) {
  701: 					(my $flat = $value) =~ s/,//g;
  702: 					($new_loc = $location) =~ s/$key/$flat/;
  703: 					$params{'location'} = $new_loc;
  704: 					if (my $rc = $self->geocode(\%params)) {
  705: 						return $rc;
  706: 					}
  707: 				}
  708: 				# Restore for the next iteration
  709: 				$params{'location'} = $location;
  710: 			}
  711: 		}
  712: 	}
  713: 
  714: 	# Final fallback: MaxMind for location lookups.
  715: 	# Scantext without OPENADDR_HOME will silently reach here and return undef;
  716: 	# a proper fix would warn here (see LIMITATIONS).
  717: 	# M8 (tautology elimination): both arms of the former wantarray ternary were
  718: 	# identical - collapsed to a single call; context propagates implicitly.
  719: 	if ($params{'location'}) {
  720: 		return $self->{'maxmind'}->geocode(\%params);
  721: 	}
  722: 
  723: 	Carp::croak(_i18n('usage_geocode', __PACKAGE__)) unless $params{'scantext'};
  724: 	return;
  725: }

  727: =head2 geocode_many
  728: 
  729: =head3 SYNOPSIS
  730: 
  731:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  732: 
  733:     for my $place (@places) {
  734:         my $pt = $batch->{$place};              # a Geo::Location::Point, or undef
  735:         next unless defined $pt;
  736:         printf "%s is at %.4f, %.4f\n", $place, $pt->lat(), $pt->long();
  737:     }
  738: 
  739:     printf "geocoded %d of %d places in %d lookups\n",
  740:         $batch->{'resolved'},
  741:         $batch->{'resolved'} + $batch->{'unresolved'},
  742:         $batch->{'lookups'};
  743: 
  744: =head3 DESCRIPTION
  745: 
  746: The loop a batch caller writes around C<geocode()>, run for it: one lookup per
  747: B<distinct> value, with the same options and the same results, plus the counts
  748: that caller would otherwise keep itself - how many values made a backend read,
  749: how many resolved, how many did not, which ones, and which backend read for them
  750: 
  751: The hashref returned holds one entry per distinct value given, keyed by the
  752: value, plus five keys of its own:
  753: 
  754: =over 4
  755: 
  756: =item * C<< $batch->{$value} >> - the C<Geo::Location::Point> the value resolved
  757: to, or C<undef> if nothing did.  Every distinct value in the input is keyed, so
  758: a caller walking a column can look each row up without first asking whether the
  759: batch covered it.  An C<undef> in the input has no key of its own and shares the
  760: entry of the empty string, which is not a location either.
  761: 
  762: =item * C<lookups> - how many distinct values made a backend read to answer
  763: them: one per value, however many backends looked at it.  A value the module
  764: refuses before any backend is touched - a bare number, C<''>, C<undef>, a
  765: reference - is not counted, and neither is a value a backend answered from a
  766: cache or from a hand-curated entry, because nothing was read for it.  This is
  767: what makes the count the work a caller is capping rather than the work it asked
  768: for.  A value repeated in the batch is one lookup.  Every backend reports its
  769: reads through C<reads()>, and a value every backend has already missed is
  770: remembered in L<Geo::Coder::Free::MissCache>, one process-level cache that all
  771: backends and instances share, whose entries expire after an hour and can be
  772: emptied early with L</clear_miss_cache>.  A later batch in the same process is
  773: answered from those caches and so reports the reads it needed, often none, in
  774: place of the ones the first batch made.
  775: 
  776: =item * C<reads> - how many reads each backend made for the batch, keyed by the
  777: name C<provenance()> reports that backend under: C<MaxMind>, C<Local> or
  778: C<OpenAddresses>.  Every backend the object holds is named, at zero for one that
  779: read nothing, so a batch answered from a cache names its backends at zero rather
  780: than naming none.  C<lookups> counts values and this counts reads - a value that
  781: made two backends read is one lookup and a read for each of them, so these
  782: numbers can add up to more than C<lookups> - and the two vocabularies are the
  783: same, so a caller can put the backend that read a value beside the backend a
  784: result came from.
  785: 
  786: =item * C<resolved> - how many distinct values produced a point.
  787: 
  788: =item * C<unresolved> - how many produced nothing, the refused values included.
  789: 
  790: =item * C<unresolved_values> - those values, in the order they were first seen,
  791: so that a caller can record them as tried-and-failed rather than retrying them
  792: on every request.  Section 2.5 sketches this list under the name C<unresolved>;
  793: here C<unresolved> is the count a "geocoded N of M" message needs and the values
  794: themselves are C<unresolved_values>.
  795: 
  796: =back
  797: 
  798: C<resolved> and C<unresolved> always add up to the number of distinct values
  799: given, and the five keys above are reserved: a value equal to one of them is
  800: refused by name, before anything is looked up, rather than allowed to overwrite
  801: a count.
  802: 
  803: C<region> and C<on_error> are handed to every lookup and mean there what they
  804: mean in C<geocode()>, including the rule that a backend exception is still an
  805: exception - nothing here is wrapped in an C<eval>.  C<on_error> defaults to
  806: C<'croak'> for the same reason it does there: a batch should not quietly plot
  807: fewer points than its column holds unless the caller asked it to, and a caller
  808: working down a dirty column asks for C<'undef'>.  The two settings do not differ
  809: in which values are looked up, only in what happens to a value the module
  810: refuses: C<'croak'> dies on it with the message C<geocode()> gives for it,
  811: C<'undef'> counts it unresolved and carries on.
  812: 
  813: A batch of no values is not an error: the counts come back zero.
  814: 
  815: The values are treated as a set.  Repeating a value in the input looks it up
  816: once and every row is keyed to the same point object, so a column that repeats
  817: the same handful of places thousands of times costs the handful of lookups.
  818: 
  819: =head3 API SPECIFICATION
  820: 
  821: =head4 input
  822: 
  823:     # Input schema (Params::Validate::Strict) - values required, options optional
  824:     values   => { type => 'arrayref' }                  # location strings, one per row
  825:     region   => { type => 'scalar', optional => 1 }     # ISO 3166-1 alpha-2 country code hint
  826:     on_error => { type => 'scalar', optional => 1 }     # 'croak' (the default) or 'undef'
  827: 
  828: =head4 output
  829: 
  830:     # Output schema (Return::Set)
  831:     { type => 'hashref' }
  832:     #   $result->{$value}            => { isa => 'Geo::Location::Point', optional => 1 }
  833:     #   $result->{lookups}           => { type => 'integer' }
  834:     #   $result->{reads}             => { type => 'hashref' }
  835:     #   $result->{resolved}          => { type => 'integer' }
  836:     #   $result->{unresolved}        => { type => 'integer' }
  837:     #   $result->{unresolved_values} => { type => 'arrayref' }
  838: 
  839: =head3 MESSAGES
  840: 
  841:     Usage: ...::geocode_many(...)   No values argument, one that is not an arrayref,
  842:                                     or options that are neither a list nor a hashref.
  843:     invalid location to geocode()   A value refused under on_error => 'croak', with the
  844:                                     message geocode() gives for that value.
  845:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  846:     <value> is one of the keys ...  A value spelled like one of the five returned keys.

  848: =head3 EXAMPLE
  849: 
  850:     my $geo = Geo::Coder::Free->new(openaddr => $ENV{OPENADDR_HOME});

  852:     # A log file's place column: repeats, a few unreadable values, one empty cell.

  856:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');

  858:     printf "geocoded %d of %d distinct places in %d lookups\n",

  863:     # Which backend did the reading, and which answered from a cache: a backend

  865:     while (my ($backend, $reads) = each %{$batch->{'reads'}}) {

  875: sub geocode_many {
  876: 	my $self = shift;
  877: 
  878: 	# The same calling conventions as the rest of the module, with the batch's
  879: 	# own spelling for the plain-function form: the values are always an
  880: 	# arrayref, so that is what a function call arrives holding.
  881: 	if (!Scalar::Util::blessed($self)) {
  882: 		return __PACKAGE__->new()->geocode_many($self, @_)
  883: 			if ref($self) eq 'ARRAY';
  884: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless @_;
  885: 		return __PACKAGE__->new()->geocode_many(@_);
  886: 	}
  887: 
  888: 	my $values = shift;
  889: 	Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless ref($values) eq 'ARRAY';
  890: 
  891: 	# Options are a hashref or an even list.  A lone scalar is neither: there is
  892: 	# no bare-string form of a batch, so it is refused rather than guessed at.
  893: 	my $opts;
  894: 	if (@_ == 1 && ref($_[0]) eq 'HASH') {
  895: 		$opts = { %{$_[0]} };
  896: 	} elsif ((scalar @_) % 2 == 0 && !grep { ref } @_) {
  897: 		$opts = { @_ };
  898: 	} else {
  899: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__));
  900: 	}
  901: 
  902: 	my $on_error = $opts->{'on_error'} // 'croak';
  903: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  904: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  905: 
  906: 	my $region = $opts->{'region'};
  907: 
  908: 	# A value spelled like one of the keys this method answers with would
  909: 	# overwrite it, so it is refused by name - before anything is looked up,
  910: 	# rather than after a count has been lost.
  911: 	my %reserved = map { $_ => 1 } @RESULT_KEYS;
  912: 	for my $value (@{$values}) {
  913: 		my $key = defined($value) ? $value : '';
  914: 		Carp::croak(_i18n('reserved_location', __PACKAGE__, $key)) if $reserved{$key};
  915: 	}
  916: 
  917: 	my %results = map { $_ => 0 } @RESULT_KEYS;
  918: 	$results{'unresolved_values'} = [];
  919: 	$results{'reads'} = {};
  920: 
  921: 	# A batch is a set: a value repeated in the input is looked up once, and
  922: 	# every row holding it is keyed to the same object.
  923: 	my %seen;
  924: 	for my $value (@{$values}) {
  925: 		# undef has no key of its own, and the empty string it shares is not a
  926: 		# location either, so it is unresolved without reaching a backend.
  927: 		my $key = defined($value) ? $value : '';
  928: 		next if $seen{$key}++;
  929: 
  930: 		# What geocode() makes of this value on this setting is asked of
  931: 		# geocode() rather than written out again here: the guard, its message and
  932: 		# the choice of backend are all its own.  The backends' read counters are
  933: 		# taken around the call, so the value is counted as a lookup only if one of
  934: 		# them actually read: a value answered from a cache, or from a hand-curated
  935: 		# entry, is not counted as work the batch did not do.  Taking them per
  936: 		# backend rather than in total says which backend read, and which answered
  937: 		# from somewhere else: a read is added to the name of the backend that made
  938: 		# it, so a value two backends read through is one lookup and a read each.
  939: 		my $reads_before = $self->_backend_reads();
  940: 		my $point = $self->geocode(
  941: 			location => $key,
  942: 			defined($region) ? (region => $region) : (),
  943: 			on_error => $on_error,
  944: 		);
  945: 		my $reads_after = $self->_backend_reads();
  946: 
  947: 		my $read = 0;
  948: 		foreach my $backend (keys %{$reads_after}) {
  949: 			my $reads = $reads_after->{$backend} - ($reads_before->{$backend} // 0);
  950: 			next unless $reads > 0;
  951: 			$results{'reads'}{$backend} += $reads;
  952: 			$read += $reads;
  953: 		}
  954: 
  955: 		# A value the module refuses is not a lookup: it never reached a backend,
  956: 		# so it does not count against the work a caller is capping.
  957: 		$results{'lookups'}++ if _valid_location($key) && $read;
  958: 		$results{$key} = $point;
  959: 
  960: 		if (defined($point)) {
  961: 			$results{'resolved'}++;
  962: 		} else {
  963: 			$results{'unresolved'}++;
  964: 			push @{$results{'unresolved_values'}}, $value;
  965: 		}
  966: 	}
  967: 
  968: 	# A backend that read nothing is reported as well, at zero: what a caller is
  969: 	# asking is which backend read and which answered from a cache, and a backend
  970: 	# left out of the answer cannot be told from one that answered from one.
  971: 	# Local is built the first time a lookup falls through to it, so it appears
  972: 	# once it has been consulted, whether or not it found anything.
  973: 	foreach my $backend (keys %{$self->_backend_reads()}) {
  974: 		$results{'reads'}{$backend} //= 0;
  975: 	}
  976: 
  977: 	return \%results;
  978: }
  979: 
  980: # How much reading each backend has done so far, by the name it is reported
  981: # under.  Counters rather than flags: the change across a call says which
  982: # backend read for that value, and a backend that was never called cannot leave
  983: # a stale flag behind.  A backend object may not exist yet - Local is built on
  984: # first use - and a test may hand the facade a stand-in, so each slot is asked
  985: # only if it holds something that can answer.
  986: sub _backend_reads {
  987: 	my $self = shift;
  988: 
  989: 	my %reads;
  990: 	foreach my $slot (sort keys %_BACKEND_NAMES) {
  991: 		my $backend = $self->{$slot} or next;
  992: 		next unless Scalar::Util::blessed($backend) && $backend->can('reads');
  993: 		$reads{$_BACKEND_NAMES{$slot}} = $backend->reads() // 0;
  994: 	}
  995: 
  996: 	return \%reads;
  997: }

 1037: =head2 provenance
 1038: 
 1039:     my ($dist, $backend, $confidence, $accuracy) = $geocoder->provenance($point);
 1040: 
 1041: or, in scalar context, the same four as a hashref:
 1042: 
 1043:     my $provenance = $geocoder->provenance($point);
 1044:     print $provenance->{'backend'};
 1045: 
 1046: Where a result came from and how good it is, so that a caller does not have to
 1047: reach for the hash keys itself:
 1048: 
 1049: =over 4
 1050: 
 1051: =item * C<$dist> - the distribution that produced the result: the C<geocoder>
 1052: key, C<Geo::Coder::Free> for a result from this distribution, or the wrapper
 1053: that passed it on, such as C<Geo::Coder::List>.
 1054: 
 1055: =item * C<$backend> - which backend answered, in a short vocabulary: C<Local>,
 1056: C<MaxMind>, C<OpenAddresses> or C<GeoNames>.  This is the C<database> key with
 1057: the distribution's prefix removed, so that the two spellings the backends use -
 1058: C<Geo::Coder::Free::Local> from C<Local>, and C<MaxMind> from C<MaxMind> - speak
 1059: the same vocabulary here.  B<The C<database> key itself is unchanged>, for the
 1060: consumers that already match on it.
 1061: 
 1062: =item * C<$confidence> - how good the match was, 0.0 to 1.0, where 1.0 is exact.
 1063: 
 1064: =item * C<$accuracy> - how precise the coordinate is: C<address>, C<street>,
 1065: C<postcode>, C<locality>, C<city>, C<region> or C<country>.
 1066: 
 1067: =back
 1068: 
 1069: Returns an empty list - and an empty hashref in scalar context - when handed
 1070: something that is not a result.  A key a result does not carry comes back
 1071: C<undef> rather than being guessed at, because a plain hash from another
 1072: geocoder has no provenance to report.
 1073: 
 1074: =head3 API SPECIFICATION
 1075: 
 1076: =head4 input
 1077: 
 1078:     point => { type => 'hashref', optional => 1 }  # a result, usually a Geo::Location::Point
 1079: 
 1080: =head4 output
 1081: 
 1082:     # list context
 1083:     { type => 'array', min => 0, max => 4 }   # dist, backend, confidence, accuracy; or ()
 1084: 
 1085:     # scalar context
 1086:     {
 1087:         type   => 'hashref',
 1088:         schema => {
 1089:             dist       => { type => 'string', optional => 1 },
 1090:             backend    => { type => 'string', optional => 1 },
 1091:             confidence => { type => 'number', optional => 1, min => 0, max => 1 },
 1092:             accuracy   => { type => 'string', optional => 1 },
 1093:         },
 1094:     }   # {} when handed something that is not a result
 1095: 
 1096: =cut

 1101: 	return wantarray ? () : {} unless defined($point) && ref($point)

 1114:

 1262: #             hashref, even-length key-val list, odd-length list, single bare string.

 1283: #           annotating every hit with location/text/confidence metadata and
 1284: #           memoising misses to avoid re-querying the same failing string.
 1285: # Entry:    $self       - geocoder instance with {openaddr} and {scantext_misses}.

 1359: # Entry:    $text - arbitrary string.

 1447: =item 2
 1448: 
 1449: Install L<https://github.com/dr5hn/countries-states-cities-database.git> into C<$DR5HN_HOME>.
 1450: This data covers cities only, so it is not used when C<OSM_HOME> is set (OSM is far more
 1451: comprehensive).  Only Australia, Canada, and the US are imported, as the UK data is difficult
 1452: to parse.
 1453: 
 1454: =item 3
 1455: 
 1456: Run C<bin/download_databases> - this downloads the Who's On First, OpenAddr, OpenStreetMap,
 1457: and dr5hn databases.
 1458: OpenStreetMap now uses PBF files, so you will need C<apt install osmium-tool> first.
 1459: Check the values of C<OSM_HOME>, C<OPENADDR_HOME>, C<DR5HN_HOME> and C<WHOSONFIRST_HOME>
 1460: within that script and adjust them for your setup.
 1461: The C<Makefile.PL> file downloads the MaxMind database automatically, as it is not optional.
 1462: 
 1463: =item 4
 1464: 
 1465: Run C<bin/create_db> - this creates the database used by C<Geo::Coder::Free> from the data you
 1466: have just downloaded.
 1467: The database is called C<openaddr.sql> for historical reasons (before Who's On First was added);
 1468: it actually contains data from all sources above.
 1469: 
 1470: =back
 1471: 
 1472: Now you are ready to run C<make>.
 1473: See the comment at the start of C<createdatabase.PL> for further details.
