  107: =head1 DESCRIPTION
  108: 
  109: C<Geo::Coder::Free> translates addresses into latitude/longitude coordinates
  110: using local SQLite databases built from free data sources - MaxMind/GeoNames,
  111: OpenAddresses, Who's On First, OpenStreetMap, and dr5hn's countries/states/cities
  112: database.  It deliberately avoids paid or rate-limited online geocoding services.
  113: The module is designed to be flexible, supporting both command-line and programmatic usage.
  114: It also includes a sample CGI script for a web-based geocoding service.
  115: 
  116: Geocoding dispatch order depends on whether C<OPENADDR_HOME> (or C<openaddr>) is set:
  117: 
  118: B<With OpenAddresses data:>
  119: 
  120: =over 4
  121: 
  122: =item 1. C<Geo::Coder::Free::OpenAddresses> - requires C<OPENADDR_HOME>
  123: 
  124: =item 2. C<Geo::Coder::Free::Local> - user-curated CSV entries (tried as fallback)
  125: 
  126: =item 3. C<Geo::Coder::Free::MaxMind> - bundled, always available
  127: 
  128: =back
  129: 
  130: B<Without OpenAddresses data:>
  131: 
  132: =over 4
  133: 
  134: =item 1. C<Geo::Coder::Free::MaxMind> only - Local is not consulted.
  135: 
  136: =back
  137: 
  138: The C<cgi-bin> directory contains a simple DIY geo-coding website:
  139: 
  140:     cgi-bin/page.fcgi page=query q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA
  141: 
  142: The sample website is currently down while a new host is sought.
  143: When it returns, you will be able to test it with:
  144: 
  145:     curl 'https://geocode.nigelhorne.com/cgi-bin/page.fcgi?page=query&q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA'

  147: =head1 LIMITATIONS
  148: 
  149: =over 4
  150: 
  151: =item * C<scantext> mode only finds locations in OpenAddresses; it falls back
  152: silently when C<OPENADDR_HOME> is not set (B<FIXME>: should warn).
  153: 
  154: =item * The C<__DATA__> alternatives table is hard-coded; it should live in a
  155: user-editable config file.
  156: 
  157: =item * The address-regex scantext path misses birth-year sentences such as
  158: C<"She was born May 21, 1937 in Noblesville, IN."> because the regex requires
  159: a preceding capital-letter word directly before the city.
  160: 
  161: =item * C<reverse_geocode> is only partially implemented; the MaxMind path does
  162: not return meaningful results.
  163: 
  164: =item * The C<alternatives> map loop uses C<each %{$alt}>, which retains its
  165: iterator position across calls.  After a successful match and early C<return>,
  166: the next C<geocode()> call on the same input starts iterating from the key
  167: B<after> the matched one, potentially missing the match entirely until C<each>
  168: wraps around.  Workaround: call C<keys %{$alt}> once to reset the iterator
  169: before iterating.
  170: 
  171: =item * Without OpenAddresses data, a two-part C<"City, Country"> location is
  172: often answered wrongly.  The MaxMind backend reads the first part as a region
  173: when it can, and answers with the first row it finds in that region, not with
  174: the city: C<"Berlin, Germany"> and C<"Munich, Germany"> both come back at
  175: 52.08, 7.38, and C<"Toronto, Canada"> comes back in British Columbia.  Some
  176: others, such as C<"Paris, France">, are not found at all.  These results carry
  177: C<< accuracy => 'region' >> and C<< confidence => 0.1 >>, so a caller that needs
  178: a city should check L</provenance> and reject them.  Naming the region as well,
  179: as in C<"Munich, Bavaria, Germany">, gives the right answer.
  180: 
  181: =item * Place names are matched as they are spelled in the data, with no
  182: folding of accents: C<"ZE<uuml>rich, Switzerland"> is found and C<"Zurich, Switzerland">
  183: is not.  Pass locations as Perl character strings (decoded, for example by
  184: C<use utf8> or an C<:encoding(UTF-8)> layer), not as undecoded UTF-8 bytes,
  185: since a byte string does not match the name in the data.
  186: 
  187: =back

  352: =head2 valid_location
  353: 
  354: =head3 SYNOPSIS
  355: 
  356:     if ($geo->valid_location($row->{'place'})) {
  357:         push @found, $geo->geocode(location => $row->{'place'});
  358:     }
  359: 
  360: =head3 DESCRIPTION
  361: 
  362: Answers whether a string is something this module will even try to look up.
  363: It is the public form of the rule C<geocode()> applies before it touches a
  364: backend, so a caller working down a spreadsheet column can skip a row whose
  365: value is a bare number - or is empty - instead of catching the croak that
  366: would otherwise kill the whole run.  That rule is defined once, in
  367: L<Geo::Location::Predicate>, and the backends apply it too: what
  368: C<valid_location()> refuses is refused wherever it is looked up.
  369: 
  370: Only that cheap syntactic test is answered.  A true result means the string is
  371: not disqualified, B<not> that a backend knows it: C<'Ramsgate, Kent'> is valid
  372: and may still find nothing, while C<'0044'> is invalid and is never looked up.
  373: The rule rejects a string of digits only, which is what a numeric column holds
  374: when the wrong column has been read, so anything with a non-digit in it counts
  375: as valid - C<'3.14'> and C<'-'> included.  C<undef>, C<''> and a reference are
  376: not valid.
  377: 
  378: =head3 API SPECIFICATION
  379: 
  380: =head4 input
  381: 
  382:     location => { type => 'scalar', optional => 1 }  # the string to test
  383: 
  384: =head4 output
  385: 
  386:     { type => 'boolean' }  # false for undef, '' and a digit-only string
  387: 
  388: =head3 EXAMPLE
  389: 
  390:     my $geo = Geo::Coder::Free->new();
  391: 
  392:     $geo->valid_location('Ramsgate, Kent');   # true
  393:     $geo->valid_location('0044');             # false - never a location
  394:     $geo->valid_location('');                 # false
  395:     $geo->valid_location(undef);              # false

  399:     $geo->valid_location('0044');

  423: =head2 geocode
  424: 
  425: =head3 SYNOPSIS
  426: 
  427:     # Standard lookup (returns a Geo::Location::Point or undef)
  428:     my $pt = $geo->geocode(location => 'Ramsgate, Kent, UK');
  429:     printf "lat=%.6f lon=%.6f\n", $pt->lat(), $pt->long();
  430: 
  431:     # Scantext - returns a list of Geo::Location::Point objects
  432:     my @hits = $geo->geocode(
  433:         scantext     => 'She lived in Ramsgate, Kent.',
  434:         region       => 'GB',
  435:         ignore_words => [qw(lived)],
  436:     );
  437: 
  438:     # Invocation flexibility (all equivalent)
  439:     $geo->geocode('Ramsgate, Kent, UK');
  440:     $geo->geocode({ location => 'Ramsgate, Kent, UK' });
  441:     $geo->geocode(location => 'Ramsgate, Kent, UK');
  442: 
  443:     # A batch caller with a dirty column: skip the row, do not kill the run
  444:     for my $place (@column) {
  445:         my $pt = $geo->geocode(location => $place, on_error => 'undef');
  446:         next unless defined $pt;
  447:         push @found, $pt;
  448:     }
  449: 
  450: =head3 DESCRIPTION
  451: 
  452: A location or a scantext that is not a location at all - a bare number, such as
  453: the C<0044> a numeric column holds - is refused before any backend is
  454: touched.  C<valid_location()> answers the same question, so a caller can filter
  455: first; C<on_error> chooses what happens when one gets through anyway:
  456: 
  457: =over 4
  458: 
  459: =item * C<'croak'> (the default) - C<Carp::croak>, the behaviour every existing
  460: caller already has.
  461: 
  462: =item * C<'undef'> - return C<undef>, so one bad row in a spreadsheet column is
  463: skipped rather than ending the run.  It changes the answer for B<only> the two
  464: documented input errors below; an exception from a backend is still an
  465: exception, and a malformed argument list still croaks.
  466: 
  467: =back
  468: 
  469: The option is deliberately narrow, so a batch caller wants C<valid_location()>
  470: with it: that predicate answers false for C<undef> and C<''> as well, which are
  471: the other two things an empty cell holds.  A call with neither a location nor a
  472: scantext is a usage error rather than an input error - the same croak as calling
  473: C<geocode()> with no arguments - and stays a croak on either setting.
  474:

  494: Every result carries C<geocoder>, C<database>, C<confidence> and C<accuracy>

  503:     Usage: ...::geocode(...)        No location or scantext argument given.
  504:     invalid location to geocode()   location is purely numeric.
  505:     invalid scantext to geocode()   scantext is purely numeric.
  506:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  507: 
  508: =head3 PSEUDOCODE
  509: 
  510:     if self is not a blessed object -> delegate to new()->geocode(@args)
  511:     normalise @_ into %params
  512:     validate: on_error is 'croak' or 'undef' (croak if not)
  513:     validate: location is not purely numeric; scantext is not purely numeric
  514:               (undef instead of croaking when on_error is 'undef')
  515:     if openaddr backend is available:
  516:         if scantext:
  517:             try the raw scantext string as a direct location
  518:             build stopword set from %_COMMON_WORDS + ignore_words param
  519:             try 3-word windows (triplets) at confidence 0.8
  520:             try 2-word windows (duplets) at confidence 0.7
  521:             try the address-pattern regex at confidence 0.7
  522:             try region-specific address finders (GB / US / CA)
  523:             mark scantext as a miss; return undef
  524:         else:
  525:             try openaddr backend
  526:             try local backend
  527:             try __DATA__ alternatives map
  528:     try maxmind backend for location lookups
  529:     croak if no scantext and no location

  533: sub geocode {
  534: 	my $self = shift;
  535: 
  536: 	# Handle being called as a function rather than a method
  537: 	if (!ref($self)) {
  538: 		if (scalar @_) {
  539: 			return __PACKAGE__->new()->geocode(@_);
  540: 		} elsif (!defined($self)) {
  541: 			Carp::croak(_i18n('usage_geocode', __PACKAGE__));
  542: 		} elsif ($self eq __PACKAGE__) {
  543: 			Carp::croak(_i18n('usage_geocode', $self));
  544: 		}
  545: 		return __PACKAGE__->new()->geocode($self);
  546: 	} elsif (ref($self) eq 'HASH') {
  547: 		return __PACKAGE__->new()->geocode($self);
  548: 	}
  549: 
  550: 	my %params = _normalize_args(_i18n('usage_geocode', __PACKAGE__), 'location', @_);
  551: 
  552: 	# What to do with an input this module rejects before it touches a backend.
  553: 	# 'croak' is the historical behaviour and stays the default, so no existing
  554: 	# caller changes; 'undef' is for a batch caller working down a dirty column,
  555: 	# which wants the row skipped rather than the whole run killed.  Only the two
  556: 	# input errors below consult it: a backend that throws still throws, because
  557: 	# nothing here is wrapped in an eval
  558: 	my $on_error = $params{'on_error'} // 'croak';
  559: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  560: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  561: 
  562: 	# Reject pure-numeric inputs early — they are never valid addresses.
  563: 	# The rule is Geo::Location::Predicate's, the same one the backends
  564: 	# apply, and valid_location() answers it in public, so a caller can
  565: 	# pre-filter with it and never reach this croak at all.
  566: 	if (defined($params{'location'}) && !_valid_location($params{'location'})) {
  567: 		return if !length($params{'location'}) || ($on_error eq 'undef');
  568: 		Carp::croak(_i18n('invalid_location', __PACKAGE__, $params{'location'}));
  569: 	}
  570: 	if (defined($params{'scantext'}) && !_valid_location($params{'scantext'})) {
  571: 		return if !length($params{'scantext'}) || ($on_error eq 'undef');
  572: 		Carp::croak(_i18n('invalid_scantext', __PACKAGE__, $params{'scantext'}));
  573: 	}
  574: 
  575: 	if ($self->{'openaddr'}) {
  576: 		if (my $scantext = $params{'scantext'}) {
  577: 			return if $self->{'scantext_misses'}{$scantext};
  578: 
  579: 			# First try the whole scantext as a direct location lookup —
  580: 			# saves work when the text happens to be a valid address string.
  581: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  582: 			my @direct = grep { defined }
  583: 				$self->{'local'}->geocode($scantext),
  584: 				$self->{'openaddr'}->geocode($scantext),
  585: 				$self->{'maxmind'}->geocode($scantext);
  586: 			return @direct if @direct;
  587: 
  588: 			my $region = $params{'region'};
  589: 
  590: 			# Build the effective stopword set.  When the caller supplies no
  591: 			# ignore_words we avoid copying %_COMMON_WORDS (which is immutable
  592: 			# at runtime) by using a reference to it directly.  Only when extra
  593: 			# words are needed do we allocate and populate a merged hash.
  594: 			my $ignore_words;
  595: 			if (my $iw = $params{'ignore_words'}) {
  596: 				my %merged = %_COMMON_WORDS;
  597: 				$merged{lc $_} = 1 for @{$iw};
  598: 				$ignore_words = \%merged;
  599: 			} else {
  600: 				$ignore_words = \%_COMMON_WORDS;
  601: 			}
  602: 
  603: 			# 3-word window search
  604: 			my @triplets = _find_word_ngrams($scantext, 3, $ignore_words);
  605: 			my $res = $self->_resolve_scan_candidates(\@triplets, $region, $CONF_TRIPLET, $scantext);
  606: 			if (@{$res}) {
  607: 				return wantarray ? @{$res} : $res->[0];
  608: 			}
  609: 
  610: 			# 2-word window search
  611: 			my @duplets = _find_word_ngrams($scantext, 2, $ignore_words);
  612: 			$res = $self->_resolve_scan_candidates(\@duplets, $region, $CONF_DUPLET, $scantext);
  613: 			if (@{$res}) {
  614: 				return wantarray ? @{$res} : $res->[0];
  615: 			}
  616: 
  617: 			# Regex-based address pattern — catches "City, ST"-style fragments.
  618: 			# Note: misses sentences like "born May 21, 1937 in Noblesville, IN"
  619: 			# because the pattern requires a capitalised word before the city.
  620: 			my @regex_matches = $scantext =~
  621: 				/\b(?:\d+\s+)?(?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*\.?),\s*
  622: 				 (?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*(?:,\s*[A-Z]{2,})*)\b/gx;
  623: 			my @places = grep { defined && $_ ne '' } @regex_matches;
  624: 			$res = $self->_resolve_scan_candidates(\@places, $region, $CONF_REGEX, $scantext);
  625: 			if (@{$res}) {
  626: 				return wantarray ? @{$res} : $res->[0];
  627: 			}
  628: 
  629: 			# Region-specific structured address patterns
  630: 			if ($region) {
  631: 				my @candidates;
  632: 				if    ($region eq 'GB') { @candidates = _find_gb_addresses($scantext) }
  633: 				elsif ($region eq 'US') { @candidates = _find_us_addresses($scantext) }
  634: 				elsif ($region eq 'Canada') { @candidates = _find_ca_addresses($scantext) }
  635: 
  636: 				if (@candidates) {
  637: 					my @regional;
  638: 					for my $candidate (@candidates) {
  639: 						next if $ignore_words->{lc $candidate};
  640: 						my @hits = grep { defined }
  641: 							$self->{'openaddr'}->geocode("$candidate, $region");
  642: 						push @regional, @hits if @hits;
  643: 					}
  644: 					return @regional if @regional;
  645: 				}
  646: 			}
  647: 
  648: 			$self->{'scantext_misses'}{$scantext} = 1;
  649: 			return;
  650: 		}
  651: 
  652: 		# Standard (non-scantext) lookup path
  653: 		if (wantarray) {
  654: 			my @rc = $self->{'openaddr'}->geocode(\%params);
  655: 			return @rc if @rc && $rc[0];
  656: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  657: 			@rc = $self->{'local'}->geocode(\%params);
  658: 			return @rc if @rc && $rc[0];
  659: 		} else {
  660: 			if (my $rc = $self->{'openaddr'}->geocode(\%params)) {
  661: 				return $rc;
  662: 			}
  663: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  664: 			if (my $rc = $self->{'local'}->geocode(\%params)) {
  665: 				return $rc;
  666: 			}
  667: 		}
  668: 
  669: 		# Try the alternatives table — hand-curated mappings for locations that
  670: 		# the databases have under slightly different names.
  671: 		# M3 (transitive reduction): every scantext path inside this block returned
  672: 		# early above; at this point $params{'scantext'} is provably falsy, so the
  673: 		# former `if (!$params{'scantext'})` guard was a tautology — removed.
  674: 		if (my $alt = $self->{'alternatives'}) {
  675: 			my $location = $params{'location'};
  676: 			while (my ($key, $value) = each %{$alt}) {
  677: 				next unless $location =~ $key;
  678: 				(my $new_loc = $location) =~ s/$key/$value/;
  679: 				$params{'location'} = $new_loc;
  680: 				if (my $rc = $self->geocode(\%params)) {
  681: 					return $rc;
  682: 				}
  683: 				# Also try the comma-free variant ("Tyne and Wear" etc.)
  684: 				if ($value =~ /, /) {
  685: 					(my $flat = $value) =~ s/,//g;
  686: 					($new_loc = $location) =~ s/$key/$flat/;
  687: 					$params{'location'} = $new_loc;
  688: 					if (my $rc = $self->geocode(\%params)) {
  689: 						return $rc;
  690: 					}
  691: 				}
  692: 				# Restore for the next iteration
  693: 				$params{'location'} = $location;
  694: 			}
  695: 		}
  696: 	}
  697: 
  698: 	# Final fallback: MaxMind for location lookups.
  699: 	# Scantext without OPENADDR_HOME will silently reach here and return undef;
  700: 	# a proper fix would warn here (see LIMITATIONS).
  701: 	# M8 (tautology elimination): both arms of the former wantarray ternary were
  702: 	# identical — collapsed to a single call; context propagates implicitly.
  703: 	if ($params{'location'}) {
  704: 		return $self->{'maxmind'}->geocode(\%params);
  705: 	}
  706: 
  707: 	Carp::croak(_i18n('usage_geocode', __PACKAGE__)) unless $params{'scantext'};
  708: 	return;
  709: }

  711: =head2 geocode_many
  712: 
  713: =head3 SYNOPSIS
  714: 
  715:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  716: 
  717:     for my $place (@places) {
  718:         my $pt = $batch->{$place};              # a Geo::Location::Point, or undef
  719:         next unless defined $pt;
  720:         printf "%s is at %.4f, %.4f\n", $place, $pt->lat(), $pt->long();
  721:     }
  722: 
  723:     printf "geocoded %d of %d places in %d lookups\n",
  724:         $batch->{'resolved'},
  725:         $batch->{'resolved'} + $batch->{'unresolved'},
  726:         $batch->{'lookups'};
  727: 
  728: =head3 DESCRIPTION
  729: 
  730: The loop a batch caller writes around C<geocode()>, run for it: one lookup per
  731: B<distinct> value, with the same options and the same results, plus the counts
  732: that caller would otherwise keep itself - how many values made a backend read,
  733: how many resolved, how many did not, which ones, and which backend read for them
  734: 
  735: The hashref returned holds one entry per distinct value given, keyed by the
  736: value, plus five keys of its own:
  737: 
  738: =over 4
  739: 
  740: =item * C<< $batch->{$value} >> - the C<Geo::Location::Point> the value resolved
  741: to, or C<undef> if nothing did.  Every distinct value in the input is keyed, so
  742: a caller walking a column can look each row up without first asking whether the
  743: batch covered it.  An C<undef> in the input has no key of its own and shares the
  744: entry of the empty string, which is not a location either.
  745: 
  746: =item * C<lookups> - how many distinct values made a backend read to answer
  747: them: one per value, however many backends looked at it.  A value the module
  748: refuses before any backend is touched - a bare number, C<''>, C<undef>, a
  749: reference - is not counted, and neither is a value a backend answered from a
  750: cache or from a hand-curated entry, because nothing was read for it.  This is
  751: what makes the count the work a caller is capping rather than the work it asked
  752: for.  A value repeated in the batch is one lookup.  Every backend reports its
  753: reads through C<reads()>, and a value every backend has already missed is
  754: remembered in L<Geo::Coder::Free::MissCache>, one process-level cache that all
  755: backends and instances share, whose entries expire after an hour and can be
  756: emptied early with L</clear_miss_cache>.  A later batch in the same process is
  757: answered from those caches and so reports the reads it needed, often none, in
  758: place of the ones the first batch made.
  759: 
  760: =item * C<reads> - how many reads each backend made for the batch, keyed by the
  761: name C<provenance()> reports that backend under: C<MaxMind>, C<Local> or
  762: C<OpenAddresses>.  Every backend the object holds is named, at zero for one that
  763: read nothing, so a batch answered from a cache names its backends at zero rather
  764: than naming none.  C<lookups> counts values and this counts reads - a value that
  765: made two backends read is one lookup and a read for each of them, so these
  766: numbers can add up to more than C<lookups> - and the two vocabularies are the
  767: same, so a caller can put the backend that read a value beside the backend a
  768: result came from.
  769: 
  770: =item * C<resolved> - how many distinct values produced a point.
  771: 
  772: =item * C<unresolved> - how many produced nothing, the refused values included.
  773: 
  774: =item * C<unresolved_values> - those values, in the order they were first seen,
  775: so that a caller can record them as tried-and-failed rather than retrying them
  776: on every request.  Section 2.5 sketches this list under the name C<unresolved>;
  777: here C<unresolved> is the count a "geocoded N of M" message needs and the values
  778: themselves are C<unresolved_values>.
  779: 
  780: =back
  781: 
  782: C<resolved> and C<unresolved> always add up to the number of distinct values
  783: given, and the five keys above are reserved: a value equal to one of them is
  784: refused by name, before anything is looked up, rather than allowed to overwrite
  785: a count.
  786: 
  787: C<region> and C<on_error> are handed to every lookup and mean there what they
  788: mean in C<geocode()>, including the rule that a backend exception is still an
  789: exception - nothing here is wrapped in an C<eval>.  C<on_error> defaults to
  790: C<'croak'> for the same reason it does there: a batch should not quietly plot
  791: fewer points than its column holds unless the caller asked it to, and a caller
  792: working down a dirty column asks for C<'undef'>.  The two settings do not differ
  793: in which values are looked up, only in what happens to a value the module
  794: refuses: C<'croak'> dies on it with the message C<geocode()> gives for it,
  795: C<'undef'> counts it unresolved and carries on.
  796: 
  797: A batch of no values is not an error: the counts come back zero.
  798: 
  799: The values are treated as a set.  Repeating a value in the input looks it up
  800: once and every row is keyed to the same point object, so a column that repeats
  801: the same handful of places thousands of times costs the handful of lookups.
  802: 
  803: =head3 API SPECIFICATION
  804: 
  805: =head4 input
  806: 
  807:     # Input schema (Params::Validate::Strict) - values required, options optional
  808:     values   => { type => 'arrayref' }                  # location strings, one per row
  809:     region   => { type => 'scalar', optional => 1 }     # ISO 3166-1 alpha-2 country code hint
  810:     on_error => { type => 'scalar', optional => 1 }     # 'croak' (the default) or 'undef'
  811: 
  812: =head4 output
  813: 
  814:     # Output schema (Return::Set)
  815:     { type => 'hashref' }
  816:     #   $result->{$value}            => { isa => 'Geo::Location::Point', optional => 1 }
  817:     #   $result->{lookups}           => { type => 'integer' }
  818:     #   $result->{reads}             => { type => 'hashref' }
  819:     #   $result->{resolved}          => { type => 'integer' }
  820:     #   $result->{unresolved}        => { type => 'integer' }
  821:     #   $result->{unresolved_values} => { type => 'arrayref' }
  822: 
  823: =head3 MESSAGES
  824: 
  825:     Usage: ...::geocode_many(...)   No values argument, one that is not an arrayref,
  826:                                     or options that are neither a list nor a hashref.
  827:     invalid location to geocode()   A value refused under on_error => 'croak', with the
  828:                                     message geocode() gives for that value.
  829:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  830:     <value> is one of the keys ...  A value spelled like one of the five returned keys.
  831: 
  832: =head3 EXAMPLE
  833: 
  834:     my $geo = Geo::Coder::Free->new(openaddr => $ENV{OPENADDR_HOME});
  835: 
  836:     # A log file's place column: repeats, a few unreadable values, one empty cell.
  837:     my @places = ('Ramsgate, Kent', '0044', 'Nowhere, Imaginary, ZZ',
  838:                   'Ramsgate, Kent', undef);
  839: 
  840:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  841: 
  842:     printf "geocoded %d of %d distinct places in %d lookups\n",
  843:         $batch->{'resolved'},
  844:         $batch->{'resolved'} + $batch->{'unresolved'},
  845:         $batch->{'lookups'};        # 4 distinct places, 2 of them looked up
  846: 
  847:     # Which backend did the reading, and which answered from a cache: a backend
  848:     # at zero answered nothing by reading.
  849:     while (my ($backend, $reads) = each %{$batch->{'reads'}}) {
  850:         print "$backend read $reads times\n";
  851:     }
  852: 
  853:     for my $place (@{$batch->{'unresolved_values'}}) {
  854:         warn "no coordinates for '" . (defined($place) ? $place : '') . "'\n";
  855:     }

  859: sub geocode_many {
  860: 	my $self = shift;
  861: 
  862: 	# The same calling conventions as the rest of the module, with the batch's
  863: 	# own spelling for the plain-function form: the values are always an
  864: 	# arrayref, so that is what a function call arrives holding.
  865: 	if (!Scalar::Util::blessed($self)) {
  866: 		return __PACKAGE__->new()->geocode_many($self, @_)
  867: 			if ref($self) eq 'ARRAY';
  868: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless @_;
  869: 		return __PACKAGE__->new()->geocode_many(@_);
  870: 	}
  871: 
  872: 	my $values = shift;
  873: 	Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless ref($values) eq 'ARRAY';
  874: 
  875: 	# Options are a hashref or an even list.  A lone scalar is neither: there is
  876: 	# no bare-string form of a batch, so it is refused rather than guessed at.
  877: 	my $opts;
  878: 	if (@_ == 1 && ref($_[0]) eq 'HASH') {
  879: 		$opts = { %{$_[0]} };
  880: 	} elsif ((scalar @_) % 2 == 0 && !grep { ref } @_) {
  881: 		$opts = { @_ };
  882: 	} else {
  883: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__));
  884: 	}
  885: 
  886: 	my $on_error = $opts->{'on_error'} // 'croak';
  887: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  888: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  889: 
  890: 	my $region = $opts->{'region'};
  891: 
  892: 	# A value spelled like one of the keys this method answers with would
  893: 	# overwrite it, so it is refused by name - before anything is looked up,
  894: 	# rather than after a count has been lost.
  895: 	my %reserved = map { $_ => 1 } @RESULT_KEYS;
  896: 	for my $value (@{$values}) {
  897: 		my $key = defined($value) ? $value : '';
  898: 		Carp::croak(_i18n('reserved_location', __PACKAGE__, $key)) if $reserved{$key};
  899: 	}
  900: 
  901: 	my %results = map { $_ => 0 } @RESULT_KEYS;
  902: 	$results{'unresolved_values'} = [];
  903: 	$results{'reads'} = {};
  904: 
  905: 	# A batch is a set: a value repeated in the input is looked up once, and
  906: 	# every row holding it is keyed to the same object.
  907: 	my %seen;
  908: 	for my $value (@{$values}) {
  909: 		# undef has no key of its own, and the empty string it shares is not a
  910: 		# location either, so it is unresolved without reaching a backend.
  911: 		my $key = defined($value) ? $value : '';
  912: 		next if $seen{$key}++;
  913: 
  914: 		# What geocode() makes of this value on this setting is asked of
  915: 		# geocode() rather than written out again here: the guard, its message and
  916: 		# the choice of backend are all its own.  The backends' read counters are
  917: 		# taken around the call, so the value is counted as a lookup only if one of
  918: 		# them actually read: a value answered from a cache, or from a hand-curated
  919: 		# entry, is not counted as work the batch did not do.  Taking them per
  920: 		# backend rather than in total says which backend read, and which answered
  921: 		# from somewhere else: a read is added to the name of the backend that made
  922: 		# it, so a value two backends read through is one lookup and a read each.
  923: 		my $reads_before = $self->_backend_reads();
  924: 		my $point = $self->geocode(
  925: 			location => $key,
  926: 			defined($region) ? (region => $region) : (),
  927: 			on_error => $on_error,
  928: 		);
  929: 		my $reads_after = $self->_backend_reads();
  930: 
  931: 		my $read = 0;
  932: 		foreach my $backend (keys %{$reads_after}) {
  933: 			my $reads = $reads_after->{$backend} - ($reads_before->{$backend} // 0);
  934: 			next unless $reads > 0;
  935: 			$results{'reads'}{$backend} += $reads;
  936: 			$read += $reads;
  937: 		}
  938: 
  939: 		# A value the module refuses is not a lookup: it never reached a backend,
  940: 		# so it does not count against the work a caller is capping.
  941: 		$results{'lookups'}++ if _valid_location($key) && $read;
  942: 		$results{$key} = $point;
  943: 
  944: 		if (defined($point)) {
  945: 			$results{'resolved'}++;
  946: 		} else {
  947: 			$results{'unresolved'}++;
  948: 			push @{$results{'unresolved_values'}}, $value;
  949: 		}
  950: 	}
  951: 
  952: 	# A backend that read nothing is reported as well, at zero: what a caller is
  953: 	# asking is which backend read and which answered from a cache, and a backend
  954: 	# left out of the answer cannot be told from one that answered from one.
  955: 	# Local is built the first time a lookup falls through to it, so it appears
  956: 	# once it has been consulted, whether or not it found anything.
  957: 	foreach my $backend (keys %{$self->_backend_reads()}) {
  958: 		$results{'reads'}{$backend} //= 0;
  959: 	}
  960: 
  961: 	return \%results;
  962: }
  963: 
  964: # How much reading each backend has done so far, by the name it is reported
  965: # under.  Counters rather than flags: the change across a call says which
  966: # backend read for that value, and a backend that was never called cannot leave
  967: # a stale flag behind.  A backend object may not exist yet - Local is built on
  968: # first use - and a test may hand the facade a stand-in, so each slot is asked
  969: # only if it holds something that can answer.
  970: sub _backend_reads {
  971: 	my $self = shift;
  972: 
  973: 	my %reads;
  974: 	foreach my $slot (sort keys %_BACKEND_NAMES) {
  975: 		my $backend = $self->{$slot} or next;
  976: 		next unless Scalar::Util::blessed($backend) && $backend->can('reads');
  977: 		$reads{$_BACKEND_NAMES{$slot}} = $backend->reads() // 0;
  978: 	}
  979: 
  980: 	return \%reads;
  981: }

  983: =head2 clear_miss_cache
  984: 
  985:     Geo::Coder::Free->clear_miss_cache();

  989: Forgets the lookups that found nothing.  Each backend remembers a miss in
  990: L<Geo::Coder::Free::MissCache>, one process-level cache that every backend and
  991: every instance shares, so an address that is not in the data is searched for
  992: once per process rather than once per call.  Entries expire after an hour; this
  993: method empties them now, for a caller that has rebuilt a database or downloaded

 1021: =head2 provenance
 1022: 
 1023:     my ($dist, $backend, $confidence, $accuracy) = $geocoder->provenance($point);
 1024: 
 1025: or, in scalar context, the same four as a hashref:
 1026: 
 1027:     my $provenance = $geocoder->provenance($point);
 1028:     print $provenance->{'backend'};
 1029: 
 1030: Where a result came from and how good it is, so that a caller does not have to
 1031: reach for the hash keys itself:
 1032: 
 1033: =over 4
 1034: 
 1035: =item * C<$dist> - the distribution that produced the result: the C<geocoder>
 1036: key, C<Geo::Coder::Free> for a result from this distribution, or the wrapper
 1037: that passed it on, such as C<Geo::Coder::List>.
 1038: 
 1039: =item * C<$backend> - which backend answered, in a short vocabulary: C<Local>,
 1040: C<MaxMind>, C<OpenAddresses> or C<GeoNames>.  This is the C<database> key with
 1041: the distribution's prefix removed, so that the two spellings the backends use -
 1042: C<Geo::Coder::Free::Local> from C<Local>, and C<MaxMind> from C<MaxMind> - speak
 1043: the same vocabulary here.  B<The C<database> key itself is unchanged>, for the
 1044: consumers that already match on it.
 1045: 
 1046: =item * C<$confidence> - how good the match was, 0.0 to 1.0, where 1.0 is exact.
 1047: 
 1048: =item * C<$accuracy> - how precise the coordinate is: C<address>, C<street>,
 1049: C<postcode>, C<locality>, C<city>, C<region> or C<country>.
 1050: 
 1051: =back
 1052: 
 1053: Returns an empty list - and an empty hashref in scalar context - when handed
 1054: something that is not a result.  A key a result does not carry comes back
 1055: C<undef> rather than being guessed at, because a plain hash from another
 1056: geocoder has no provenance to report.
 1057: 
 1058: =head3 API SPECIFICATION
 1059: 
 1060: =head4 input
 1061: 
 1062:     point => { type => 'hashref', optional => 1 }  # a result, usually a Geo::Location::Point
 1063: 
 1064: =head4 output
 1065: 
 1066:     # list context
 1067:     { type => 'array', min => 0, max => 4 }   # dist, backend, confidence, accuracy; or ()
 1068: 
 1069:     # scalar context
 1070:     {
 1071:         type   => 'hashref',
 1072:         schema => {
 1073:             dist       => { type => 'string', optional => 1 },
 1074:             backend    => { type => 'string', optional => 1 },
 1075:             confidence => { type => 'number', optional => 1, min => 0, max => 1 },
 1076:             accuracy   => { type => 'string', optional => 1 },
 1077:         },
 1078:     }   # {} when handed something that is not a result
 1079: 
 1080: =cut
 1081: 
 1082: sub provenance {
 1083: 	my ($self, $point) = @_;
 1084: 
 1085: 	return wantarray ? () : {} unless defined($point) && ref($point)
 1086: 		&& ((Scalar::Util::reftype($point) || '') eq 'HASH');
 1087: 
 1088: 	my $dist    = $point->{'geocoder'};
 1089: 	my $backend = $point->{'database'};
 1090: 	$backend =~ s/^Geo::Coder::Free::// if defined($backend);
 1091: 
 1092: 	my %provenance = (
 1093: 		dist       => $dist,
 1094: 		backend    => $backend,
 1095: 		confidence => $point->{'confidence'},
 1096: 		accuracy   => $point->{'accuracy'},
 1097: 	);
 1098: 
 1099: 	return wantarray ? @provenance{qw(dist backend confidence accuracy)} : \%provenance;
 1100: }

 1245: # Purpose:  Normalise the four calling conventions accepted by geocode/reverse_geocode:
 1246: #             hashref, even-length key-val list, odd-length list, single bare string.
 1247: # Entry:    $error_msg — message to croak if a non-hash reference is passed.
 1248: #           $bare_key  — hash key to assign to a single bare string argument
 1249: #                        ('location' for geocode, 'latlng' for reverse_geocode).
 1250: #           @args — raw @_ after $self has been shifted.
 1251: # Exit:     Flat key-value %params hash.
 1252: # Side Effects: None; croaks on unsupported reference argument.
 1253: sub _normalize_args {
 1254: 	my ($error_msg, $bare_key, @args) = @_;
 1255: 	return %{$args[0]}              if ref($args[0]) eq 'HASH';
 1256: 	Carp::croak($error_msg)         if ref($args[0]);
 1257: 	return @args                    if @args && @args % 2 == 0;
 1258: 	return ($bare_key => $args[0])  if @args == 1;
 1259: 	# M7 (logic-gap closure): odd-count > 1 is not a valid calling convention.
 1260: 	# The former code silently returned () here, discarding the trailing elements.
 1261: 	# Fail fast instead of propagating a malformed argument list downstream.
 1262: 	Carp::croak($error_msg)         if @args;
 1263: 	return ();

 1266: # Purpose:  Try to geocode each candidate place string via the openaddr backend,
 1267: #           annotating every hit with location/text/confidence metadata and
 1268: #           memoising misses to avoid re-querying the same failing string.
 1269: # Entry:    $self       — geocoder instance with {openaddr} and {scantext_misses}.
 1270: #           $candidates — arrayref of place-name strings to probe.
 1271: #           $region     — optional ISO country code appended to each candidate.
 1272: #           $confidence — numeric confidence score assigned to all hits.
 1273: #           $scantext   — original free text (stored inside each result object).
 1274: # Exit:     Arrayref of Geo::Location::Point objects; empty arrayref on no hits.
 1275: # Side Effects: Populates $self->{scantext_misses} for every non-matching place.
 1276: sub _resolve_scan_candidates {
 1277: 	my ($self, $candidates, $region, $confidence, $scantext) = @_;
 1278: 	my @results;
 1279: 	for my $place (@{$candidates}) {
 1280: 		my $location = $region ? "$place, $region" : $place;
 1281: 		next if $self->{'scantext_misses'}{$location};
 1282: 		my @res = grep { defined } $self->{'openaddr'}->geocode($location);
 1283: 		if (@res) {
 1284: 			for my $entry (@res) {
 1285: 				$entry->{'location'}   = $location;
 1286: 				$entry->{'text'}       = $scantext;
 1287: 				$entry->{'confidence'} = $confidence;
 1288: 			}
 1289: 			push @results, @res;
 1290: 		} else {
 1291: 			$self->{'scantext_misses'}{$location} = 1;
 1292: 		}
 1293: 	}
 1294: 	return \@results;
 1295: }

 1297: # Purpose:  Slide a window of $n words across $text and return all comma-joined
 1298: #           n-grams, excluding pure-numeric tokens and stopwords.  A token of
 1299: #           digits only is not a word of a place name, which is the question
 1300: #           Geo::Location::Predicate::_valid_location() answers, so it is asked
 1301: #           there rather than spelled out here (t/location-rule.t fails if the
 1302: #           rule is written out again).
 1303: #           Replaces the former _find_word_triplets ($n=3) and
 1304: #           _find_word_duplets ($n=2) which were identical except for window size
 1305: #           and the duplets version was missing the lc() normalisation on stopwords.
 1306: # Entry:    $text — raw string; $n — window size; $stop — stopword hashref.
 1307: # Exit:     Flat list of n-gram strings.
 1308: sub _find_word_ngrams {
 1309: 	my ($text, $n, $stop) = @_;

 1311: 	$text =~ s/\s+/ /g;
 1312: 	$text =~ s/^\s+|\s+$//g;

 1316: 		push @ngrams, join ', ', @words[$i .. $i + $n - 1];
 1317: 	}
 1318: 	return @ngrams;

 1341: # Purpose:  Extract British-style addresses from free text.
 1342: # Entry:    $text — arbitrary string.
 1343: # Exit:     List of trimmed address strings.
 1344: sub _find_gb_addresses {
 1345: 	my $text = shift;
 1346: 	my @addresses;
 1347: 	# ReDoS fix: the former pattern used \s*,?\s* between all parts and
 1348: 	# [A-Za-z\s'-]+ groups — with commas optional, the engine must try all
 1349: 	# possible splits of a long string among 5 overlapping space-containing
 1350: 	# groups, causing exponential backtracking.  Making commas mandatory
 1351: 	# eliminates the ambiguity entirely: UK postal addresses always have commas.

 1354: 		\b

 1356: 		\s+
 1357: 		(?:[\w'-]+(?:\s+[\w'-]+){0,5})           # street name (up to 6 words)
 1358: 		\s*,\s*                                   # COMMA REQUIRED — kills the ambiguity
 1359: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # town (up to 4 words)
 1360: 		\s*,\s*                                   # COMMA REQUIRED
 1361: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # county (up to 4 words)

 1363: 		(?:[\w'-]+(?:\s+[\w'-]+){0,2})           # country (up to 3 words)
 1364: 		\b
 1365: 	/x;
 1366: 	while ($text =~ /$re/g) {
 1367: 		(my $addr = $&) =~ s/[,\s]+$//;
 1368: 		push @addresses, $addr;
 1369: 	}
 1370: 	return @addresses;

 1396: =head1 GETTING STARTED
 1397: 
 1398: To download, import and set up the local database:
 1399: before running C<make>, but after running C<perl Makefile.PL>, follow these instructions.
 1400: 
 1401: Optionally set C<OPENADDR_HOME> to point to an empty directory and download the data from
 1402: L<http://results.openaddresses.io> into that directory; and
 1403: optionally set C<WHOSONFIRST_HOME> to point to an empty directory and download the data using
 1404: L<https://github.com/nigelhorne/NJH-Snippets/blob/master/bin/wof-clone>.
 1405: The script C<bin/download_databases> (see below) will do those for you.
 1406: You do not need to download the MaxMind data - that is downloaded automatically.
 1407: 
 1408: You will need to create the database used by C<Geo::Coder::Free>.
 1409: 
 1410: Install L<App::csv2sqlite> and L<https://github.com/nigelhorne/NJH-Snippets>.
 1411: Run C<bin/create_sqlite> - this converts the MaxMind "cities" database from CSV to SQLite.
 1412: 
 1413: To use with MariaDB, set C<MARIADB_SERVER="$hostname;$port"> and
 1414: C<MARIADB_USER="$user;$password"> (TODO: username/password should be asked for interactively).
 1415: The code will use a database called C<geo_code_free>, which will be dropped and recreated if it exists.
 1416: C<$user> needs only DROP, CREATE, SELECT, INSERT, and INDEX privileges on that database.
 1417: 
 1418: The following optional steps download and install large databases.
 1419: This will take a long time and use a lot of disc space.
 1420: 
 1421: =over 4
 1422: 
 1423: =item 1
 1424: 
 1425: C<mkdir $WHOSONFIRST_HOME; cd $WHOSONFIRST_HOME> then run C<wof-clone> from NJH-Snippets.
 1426: 
 1427: This can take a long time because it contains many nested directories, which filesystem drivers
 1428: can be slow to navigate (particularly on EXT4 and ZFS).

 1433: This data covers cities only, so it is not used when C<OSM_HOME> is set (OSM is far more
