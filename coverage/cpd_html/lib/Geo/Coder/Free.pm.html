  145: =head1 DESCRIPTION
  146: 
  147: C<Geo::Coder::Free> translates addresses into latitude/longitude coordinates
  148: using local SQLite databases built from free data sources - MaxMind/GeoNames,
  149: OpenAddresses, Who's On First, OpenStreetMap, and dr5hn's countries/states/cities
  150: database.  It deliberately avoids paid or rate-limited online geocoding services.
  151: The module is designed to be flexible, supporting both command-line and programmatic usage.
  152: It also includes a sample CGI script for a web-based geocoding service.
  153: 
  154: Geocoding dispatch order depends on whether C<OPENADDR_HOME> (or C<openaddr>) is set:
  155: 
  156: B<With OpenAddresses data:>
  157: 
  158: =over 4
  159: 
  160: =item 1. C<Geo::Coder::Free::OpenAddresses> - requires C<OPENADDR_HOME>
  161: 
  162: =item 2. C<Geo::Coder::Free::Local> - user-curated CSV entries (tried as fallback)
  163: 
  164: =item 3. C<Geo::Coder::Free::MaxMind> - bundled, always available
  165: 
  166: =back
  167: 
  168: B<Without OpenAddresses data:>
  169: 
  170: =over 4
  171: 
  172: =item 1. C<Geo::Coder::Free::MaxMind> only - Local is not consulted.
  173: 
  174: =back
  175: 
  176: The C<cgi-bin> directory contains a simple DIY geo-coding website:
  177: 
  178:     cgi-bin/page.fcgi page=query q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA
  179: 
  180: The sample website is currently down while a new host is sought.
  181: When it returns, you will be able to test it with:
  182: 
  183:     curl 'https://geocode.nigelhorne.com/cgi-bin/page.fcgi?page=query&q=1600+Pennsylvania+Avenue+NW+Washington+DC+USA'

  185: =head1 LIMITATIONS
  186: 
  187: =over 4
  188: 
  189: =item * C<scantext> mode only finds locations in OpenAddresses.  When
  190: C<OPENADDR_HOME> is not set it finds nothing, and warns once per object.
  191: 
  192: =item * Pass decoded character strings.  Non-ASCII text is matched exactly, so C<Munchen>
  193: doesn't find C<ME<uuml>nchen>, and bytes that have not been decoded are a different address.
  194: 
  195: =item * The C<__DATA__> alternatives table is hard-coded; it should live in a
  196: user-editable config file.
  197: 
  198: =item * The address-regex scantext path misses birth-year sentences such as
  199: C<"She was born May 21, 1937 in Noblesville, IN."> because the regex requires
  200: a preceding capital-letter word directly before the city.
  201: 
  202: =item * C<reverse_geocode> is only partially implemented; the MaxMind path does
  203: not return meaningful results.
  204: 
  205: =item * Without OpenAddresses data, a two-part C<"City, Country"> location is
  206: often answered wrongly.  The MaxMind backend reads the first part as a region
  207: when it can, and answers with the first row it finds in that region, not with
  208: the city: C<"Berlin, Germany"> and C<"Munich, Germany"> both come back at
  209: 52.08, 7.38, and C<"Toronto, Canada"> comes back in British Columbia.  Some
  210: others, such as C<"Paris, France">, are not found at all.  These results carry
  211: C<< accuracy => 'region' >> and C<< confidence => 0.1 >>, so a caller that needs
  212: a city should check L</provenance> and reject them.  Naming the region as well,
  213: as in C<"Munich, Bavaria, Germany">, gives the right answer.
  214: 
  215: =item * Place names are matched as they are spelled in the data, with no
  216: folding of accents: C<"ZE<uuml>rich, Switzerland"> is found and C<"Zurich, Switzerland">
  217: is not.  Pass locations as Perl character strings (decoded, for example by
  218: C<use utf8> or an C<:encoding(UTF-8)> layer), not as undecoded UTF-8 bytes,
  219: since a byte string does not match the name in the data.
  220: 
  221: =back

  430: =head2 valid_location
  431: 
  432: =head3 SYNOPSIS
  433: 
  434:     if ($geo->valid_location($row->{'place'})) {
  435:         push @found, $geo->geocode(location => $row->{'place'});
  436:     }
  437: 
  438: =head3 DESCRIPTION
  439: 
  440: Answers whether a string is something this module will even try to look up.
  441: It is the public form of the rule C<geocode()> applies before it touches a
  442: backend, so a caller working down a spreadsheet column can skip a row whose
  443: value is a bare number - or is empty - instead of catching the croak that
  444: would otherwise kill the whole run.  That rule is defined once, in
  445: L<Geo::Location::Predicate>, and the backends apply it too: what
  446: C<valid_location()> refuses is refused wherever it is looked up.
  447: 
  448: Only that cheap syntactic test is answered.  A true result means the string is
  449: not disqualified, B<not> that a backend knows it: C<'Ramsgate, Kent'> is valid
  450: and may still find nothing, while C<'0044'> is invalid and is never looked up.
  451: The rule rejects a string of digits only, which is what a numeric column holds
  452: when the wrong column has been read, so anything with a non-digit in it counts
  453: as valid - C<'3.14'> and C<'-'> included.  C<undef>, C<''> and a reference are
  454: not valid.
  455: 
  456: =head3 API SPECIFICATION
  457: 
  458: =head4 input
  459: 
  460:     location => { type => 'scalar', optional => 1 }  # the string to test
  461: 
  462: =over 4
  463: 
  464: =item * False: C<undef>, C<''>, a reference, and a string only of digits of any
  465: length.  A digit is a Unicode decimal digit, so C<"\x{661}"> counts as one.
  466: 
  467: =item * True: anything with a non-digit in it.  The shortest are one character
  468: long.  C<'-'>, C<' '>, C<'3.14'>, C<"1\n">, a zero byte and any non-ASCII letter,
  469: emoji or control character are all true.  No maximum length applies.
  470: 
  471: =back
  472: 
  473: =head4 output
  474: 
  475:     { type => 'boolean' }  # false for undef, '' and a digit-only string
  476: 
  477: =head3 EXAMPLE
  478: 
  479:     my $geo = Geo::Coder::Free->new();
  480: 
  481:     $geo->valid_location('Ramsgate, Kent');   # true
  482:     $geo->valid_location('0044');             # false - never a location
  483:     $geo->valid_location('');                 # false
  484:     $geo->valid_location(undef);              # false
  485: 
  486: Accepts the three calling conventions the rest of this module does:
  487: 
  488:     $geo->valid_location('0044');
  489:     Geo::Coder::Free->valid_location('0044');
  490:     Geo::Coder::Free::valid_location('0044');

  494: sub valid_location {
  495: 	my $self = shift;
  496: 
  497: 	# The location is whichever argument is not the invocant, so that the
  498: 	# predicate reads the same whether it is called on an instance, on the
  499: 	# class or as a plain function.
  500: 	my $location;
  501: 	if (ref($self)) {
  502: 		$location = shift;
  503: 	} elsif (@_) {
  504: 		$location = shift;
  505: 	} elsif (defined($self) && $self ne __PACKAGE__) {

  512: =head2 geocode
  513: 
  514: =head3 SYNOPSIS
  515: 
  516:     # Standard lookup (returns a Geo::Location::Point or undef)
  517:     my $pt = $geo->geocode(location => 'Ramsgate, Kent, UK');
  518:     printf "lat=%.6f lon=%.6f\n", $pt->lat(), $pt->long();
  519: 
  520:     # Scantext - returns a list of Geo::Location::Point objects
  521:     my @hits = $geo->geocode(
  522:         scantext     => 'She lived in Ramsgate, Kent.',
  523:         region       => 'GB',
  524:         ignore_words => [qw(lived)],
  525:     );
  526: 
  527:     # Invocation flexibility (all equivalent)
  528:     $geo->geocode('Ramsgate, Kent, UK');
  529:     $geo->geocode({ location => 'Ramsgate, Kent, UK' });
  530:     $geo->geocode(location => 'Ramsgate, Kent, UK');
  531: 
  532:     # A batch caller with a dirty column: skip the row, do not kill the run
  533:     for my $place (@column) {
  534:         my $pt = $geo->geocode(location => $place, on_error => 'undef');
  535:         next unless defined $pt;
  536:         push @found, $pt;
  537:     }
  538: 
  539: =head3 DESCRIPTION
  540: 
  541: A location or a scantext that is not a location at all - a bare number, such as
  542: the C<0044> a numeric column holds - is refused before any backend is
  543: touched.  C<valid_location()> answers the same question, so a caller can filter
  544: first; C<on_error> chooses what happens when one gets through anyway:
  545: 
  546: =over 4
  547: 
  548: =item * C<'croak'> (the default) - C<Carp::croak>, the behaviour every existing
  549: caller already has.
  550: 
  551: =item * C<'undef'> - return C<undef>, so one bad row in a spreadsheet column is
  552: skipped rather than ending the run.  It changes the answer for B<only> the two
  553: documented input errors below; an exception from a backend is still an
  554: exception, and a malformed argument list still croaks.
  555: 
  556: =back
  557: 
  558: The option is deliberately narrow, so a batch caller wants C<valid_location()>
  559: with it: that predicate answers false for C<undef> and C<''> as well, which are
  560: the other two things an empty cell holds.  A call with neither a location nor a
  561: scantext is a usage error rather than an input error - the same croak as calling
  562: C<geocode()> with no arguments - and stays a croak on either setting.
  563: 
  564: =head3 API SPECIFICATION
  565: 
  566: =head4 input
  567: 
  568:     # Input schema (Params::Validate::Strict) - at least one of location or scantext is required
  569:     location     => { type => 'scalar',   optional => 1 }  # address string
  570:     scantext     => { type => 'scalar',   optional => 1 }  # free text to scan for place names
  571:     region       => { type => 'scalar',   optional => 1 }  # ISO 3166-1 alpha-2 country code hint
  572:     ignore_words => { type => 'arrayref', optional => 1 }  # words to suppress during scantext scan
  573:     on_error     => { type => 'scalar',   optional => 1 }  # 'croak' (default) or 'undef'
  574: 
  575: The domain of each parameter:
  576: 
  577: =over 4
  578: 
  579: =item * C<location> - a string with a non-digit in it, from one character up; no
  580: maximum length applies.  It reaches the backends unchanged, whatever its
  581: characters.  C<''> finds nothing and is not an error; C<undef> counts as absent.
  582: A string only of digits, or a reference, croaks C<invalid location to geocode()>.
  583: 
  584: =item * C<scantext> - the same partitions as C<location>, with the message
  585: C<invalid scantext to geocode()>.  Without OpenAddresses it is not looked at and
  586: finds nothing.
  587: 
  588: =item * C<location> and C<scantext> together - both are checked.  With
  589: OpenAddresses the scantext is searched, and without it the location is.
  590: 
  591: =item * C<region> - any string; nothing is refused.  C<CA>, C<AU> and C<IE> are
  592: appended to a scantext candidate by name, in either case.  Any other two letters
  593: are appended in upper case, and any other value as written.  C<''> and C<'0'>
  594: append nothing.  A scantext that found nothing is remembered per C<region> and
  595: C<ignore_words>, as long as a miss in L<Geo::Coder::Free::MissCache> lasts and
  596: until L</clear_miss_cache>.
  597: 
  598: =item * C<ignore_words> - an arrayref of words, matched in any case.  A false
  599: value is the same as absent.  With OpenAddresses, anything else true dies with
  600: perl's own C<ARRAY> reference error during a scantext scan; without it the value
  601: is not looked at.
  602: 
  603: =item * C<on_error> - exactly C<'croak'> or C<'undef'>, in lower case; C<undef> is
  604: C<'croak'>.  Anything else, C<''> included, croaks C<on_error must be ...>, and
  605: that is reported before a bad location or scantext.
  606: 
  607: =item * The arguments - a bare string, an even list or a hashref.  No arguments, a
  608: lone C<undef>, an empty hashref, a reference other than a hashref, an odd list
  609: longer than one, or options with neither a location nor a scantext croak C<Usage:>.
  610: 
  611: =back
  612: 
  613: =head4 output
  614: 
  615:     # Output schema (Return::Set)
  616:     # scalar context: { type => 'object',   isa => 'Geo::Location::Point', optional => 1 }
  617:     # list context:   { type => 'arrayref', of  => { isa => 'Geo::Location::Point' } }
  618: 
  619: =head4 provenance
  620: 
  621: Every result carries C<geocoder>, C<database>, C<confidence> and C<accuracy>
  622: which distribution produced
  623: it, which backend answered, how good the match was, and how precise the
  624: coordinate is.  C<provenance()> reads the four back.  C<location> is set by every
  625: path but the MaxMind cities one, and C<text> only by a scantext lookup; C<lat>,
  626: C<long> and C<lng> come from the value object itself.
  627: 
  628: =head3 MESSAGES
  629: 
  630:     Usage: ...::geocode(...)        No location or scantext argument given.
  631:     invalid location to geocode()   location is purely numeric.
  632:     invalid scantext to geocode()   scantext is purely numeric.
  633:     on_error must be ...            on_error is neither 'croak' nor 'undef'.
  634: 
  635: =head3 PSEUDOCODE
  636: 
  637:     if self is not a blessed object -> delegate to new()->geocode(@args)
  638:     normalise @_ into %params
  639:     validate: on_error is 'croak' or 'undef' (croak if not)
  640:     validate: location is not purely numeric; scantext is not purely numeric
  641:               (undef instead of croaking when on_error is 'undef')
  642:     if openaddr backend is available:
  643:         if scantext:

  649:             try region-specific address finders (GB / US / CA / IE)
  650:             mark scantext as a miss; return undef

  652:             try openaddr backend
  653:             try local backend

  655:     try maxmind backend for location lookups
  656:     croak if no scantext and no location

  660: sub geocode {
  661: 	my $self = shift;
  662: 
  663: 	# Handle being called as a function rather than a method
  664: 	if (!ref($self)) {
  665: 		if (scalar @_) {
  666: 			return __PACKAGE__->new()->geocode(@_);
  667: 		} elsif (!defined($self)) {
  668: 			Carp::croak(_i18n('usage_geocode', __PACKAGE__));
  669: 		} elsif ($self eq __PACKAGE__) {
  670: 			Carp::croak(_i18n('usage_geocode', $self));
  671: 		}
  672: 		return __PACKAGE__->new()->geocode($self);
  673: 	} elsif (ref($self) eq 'HASH') {
  674: 		return __PACKAGE__->new()->geocode($self);
  675: 	}
  676: 
  677: 	my %params = _normalize_args(_i18n('usage_geocode', __PACKAGE__), 'location', @_);
  678: 
  679: 	# What to do with an input this module rejects before it touches a backend.
  680: 	# 'croak' is the historical behaviour and stays the default, so no existing
  681: 	# caller changes; 'undef' is for a batch caller working down a dirty column,
  682: 	# which wants the row skipped rather than the whole run killed.  Only the two
  683: 	# input errors below consult it: a backend that throws still throws, because
  684: 	# nothing here is wrapped in an eval
  685: 	my $on_error = $params{'on_error'} // 'croak';
  686: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
  687: 		unless $on_error eq 'croak' || $on_error eq 'undef';
  688: 
  689: 	# Reject pure-numeric inputs early - they are never valid addresses.
  690: 	# The rule is Geo::Location::Predicate's, the same one the backends
  691: 	# apply, and valid_location() answers it in public, so a caller can
  692: 	# pre-filter with it and never reach this croak at all.
  693: 	if (defined($params{'location'}) && !_valid_location($params{'location'})) {
  694: 		return if !length($params{'location'}) || ($on_error eq 'undef');
  695: 		Carp::croak(_i18n('invalid_location', __PACKAGE__, $params{'location'}));
  696: 	}
  697: 	if (defined($params{'scantext'}) && !_valid_location($params{'scantext'})) {
  698: 		return if !length($params{'scantext'}) || ($on_error eq 'undef');
  699: 		Carp::croak(_i18n('invalid_scantext', __PACKAGE__, $params{'scantext'}));
  700: 	}
  701: 
  702: 	if ($self->{'openaddr'}) {
  703: 		if (my $scantext = $params{'scantext'}) {
  704: 			my $miss_key = _scantext_miss_key($scantext, $params{'region'}, $params{'ignore_words'});
  705: 			return if $self->_scantext_missed($miss_key);
  706: 
  707: 			# First try the whole scantext as a direct location lookup -
  708: 			# saves work when the text happens to be a valid address string.
  709: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  710: 			my @direct = grep { defined }
  711: 				$self->{'local'}->geocode($scantext),
  712: 				$self->{'openaddr'}->geocode($scantext),
  713: 				$self->{'maxmind'}->geocode($scantext);
  714: 			return @direct if @direct;
  715: 
  716: 			my $region = $params{'region'};
  717: 			my $country = defined($region) ? ($_REGION_COUNTRY{uc $region} // $region) : undef;
  718: 			# An ISO code is upper case to the parsers, whatever it was given in
  719: 			$country = uc($country) if defined($country) && ($country =~ /\A[a-z]{2}\z/);
  720: 
  721: 			# Build the effective stopword set.  When the caller supplies no
  722: 			# ignore_words we avoid copying %_COMMON_WORDS (which is immutable
  723: 			# at runtime) by using a reference to it directly.  Only when extra
  724: 			# words are needed do we allocate and populate a merged hash.
  725: 			my $ignore_words;
  726: 			if (my $iw = $params{'ignore_words'}) {
  727: 				my %merged = %_COMMON_WORDS;
  728: 				$merged{lc $_} = 1 for @{$iw};
  729: 				$ignore_words = \%merged;
  730: 			} else {
  731: 				$ignore_words = \%_COMMON_WORDS;
  732: 			}
  733: 
  734: 			# 3-word window search
  735: 			my @triplets = _find_word_ngrams($scantext, 3, $ignore_words);
  736: 			my $res = $self->_resolve_scan_candidates(\@triplets, $country, $CONF_TRIPLET, $scantext);
  737: 			if (@{$res}) {
  738: 				return wantarray ? @{$res} : $res->[0];
  739: 			}
  740: 
  741: 			# 2-word window search
  742: 			my @duplets = _find_word_ngrams($scantext, 2, $ignore_words);
  743: 			$res = $self->_resolve_scan_candidates(\@duplets, $country, $CONF_DUPLET, $scantext);
  744: 			if (@{$res}) {
  745: 				return wantarray ? @{$res} : $res->[0];
  746: 			}
  747: 
  748: 			# Regex-based address pattern - catches "City, ST"-style fragments.
  749: 			# Note: misses sentences like "born May 21, 1937 in Noblesville, IN"
  750: 			# because the pattern requires a capitalised word before the city.
  751: 			my @regex_matches = $scantext =~
  752: 				/\b(?:\d+\s+)?(?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*\.?),\s*
  753: 				 (?:[A-Z][a-z]+(?:\s+[A-Z][a-z]+)*(?:,\s*[A-Z]{2,})*)\b/gx;
  754: 			my @places = grep { defined && $_ ne '' } @regex_matches;
  755: 			$res = $self->_resolve_scan_candidates(\@places, $country, $CONF_REGEX, $scantext);
  756: 			if (@{$res}) {
  757: 				return wantarray ? @{$res} : $res->[0];
  758: 			}
  759: 
  760: 			# Region-specific structured address patterns
  761: 			if ($region) {
  762: 				my @candidates;
  763: 				my $code = uc $region;
  764: 				if    ($code eq 'GB') { @candidates = _find_gb_addresses($scantext) }
  765: 				elsif ($code eq 'US') { @candidates = _find_us_addresses($scantext) }
  766: 				elsif ($code eq 'CA') { @candidates = _find_ca_addresses($scantext) }
  767: 				# Irish addresses are written in the same comma-separated
  768: 				# "street, town, county, country" form as British ones
  769: 				elsif ($code eq 'IE') { @candidates = _find_gb_addresses($scantext) }
  770: 
  771: 				if (@candidates) {
  772: 					my @regional;
  773: 					for my $candidate (@candidates) {
  774: 						next if $ignore_words->{lc $candidate};
  775: 						my @hits = grep { defined }
  776: 							$self->{'openaddr'}->geocode("$candidate, $country");
  777: 						push @regional, @hits if @hits;
  778: 					}
  779: 					return @regional if @regional;
  780: 				}
  781: 			}
  782: 
  783: 			$self->_remember_scantext_miss($miss_key);
  784: 			return;
  785: 		}
  786: 
  787: 		# Standard (non-scantext) lookup path
  788: 		if (wantarray) {
  789: 			my @rc = $self->{'openaddr'}->geocode(\%params);
  790: 			return @rc if @rc && $rc[0];
  791: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  792: 			@rc = $self->{'local'}->geocode(\%params);
  793: 			return @rc if @rc && $rc[0];
  794: 		} else {
  795: 			if (my $rc = $self->{'openaddr'}->geocode(\%params)) {
  796: 				return $rc;
  797: 			}
  798: 			$self->{'local'} ||= Geo::Coder::Free::Local->new();
  799: 			if (my $rc = $self->{'local'}->geocode(\%params)) {
  800: 				return $rc;
  801: 			}
  802: 		}
  803: 
  804: 		# Try the alternatives table - hand-curated mappings for locations that
  805: 		# the databases have under slightly different names.
  806: 		# M3 (transitive reduction): every scantext path inside this block returned
  807: 		# early above; at this point $params{'scantext'} is provably falsy, so the
  808: 		# former `if (!$params{'scantext'})` guard was a tautology - removed.
  809: 		if (my $alt = $self->{'alternatives'}) {
  810: 			my $location = $params{'location'};
  811: 			# Not each(): the recursive geocode() calls below walk the same
  812: 			# hash, sharing and resetting its iterator, so an each() loop here
  813: 			# would start again from the top and retry the same key forever.
  814: 			foreach my $key (sort keys %{$alt}) {
  815: 				next if $_alternatives_active{$key};
  816: 				my $value = $alt->{$key};
  817: 				next unless $location =~ $key;
  818: 				local $_alternatives_active{$key} = 1;
  819: 				(my $new_loc = $location) =~ s/$key/$value/;
  820: 				$params{'location'} = $new_loc;
  821: 				if (my $rc = $self->geocode(\%params)) {
  822: 					return $rc;
  823: 				}
  824: 				# Also try the comma-free variant ("Tyne and Wear" etc.)
  825: 				if ($value =~ /, /) {
  826: 					(my $flat = $value) =~ s/,//g;
  827: 					($new_loc = $location) =~ s/$key/$flat/;
  828: 					$params{'location'} = $new_loc;
  829: 					if (my $rc = $self->geocode(\%params)) {
  830: 						return $rc;
  831: 					}
  832: 				}
  833: 				# Restore for the next iteration
  834: 				$params{'location'} = $location;
  835: 			}
  836: 		}
  837: 	}
  838: 
  839: 	# Final fallback: MaxMind for location lookups.
  840: 	# Scantext without OPENADDR_HOME falls through this to the warning below.
  841: 	# M8 (tautology elimination): both arms of the former wantarray ternary were
  842: 	# identical - collapsed to a single call; context propagates implicitly.
  843: 	if ($params{'location'}) {
  844: 		return $self->{'maxmind'}->geocode(\%params);
  845: 	}
  846: 
  847: 	Carp::croak(_i18n('usage_geocode', __PACKAGE__)) unless $params{'scantext'};
  848: 
  849: 	# Once per object: a caller scanning a whole file doesn't want a line each
  850: 	Carp::carp(_i18n('scantext_needs_oa', __PACKAGE__)) unless $self->{'warned_scantext'}++;
  851: 	return;
  852: }

  854: =head2 geocode_many
  855: 
  856: =head3 SYNOPSIS
  857: 
  858:     my $batch = $geo->geocode_many(\@places, region => 'GB', on_error => 'undef');
  859: 
  860:     for my $place (@places) {
  861:         my $pt = $batch->{$place};              # a Geo::Location::Point, or undef
  862:         next unless defined $pt;
  863:         printf "%s is at %.4f, %.4f\n", $place, $pt->lat(), $pt->long();
  864:     }
  865: 
  866:     printf "geocoded %d of %d places in %d lookups\n",
  867:         $batch->{'resolved'},
  868:         $batch->{'resolved'} + $batch->{'unresolved'},
  869:         $batch->{'lookups'};
  870: 
  871: =head3 DESCRIPTION
  872: 
  873: The loop a batch caller writes around C<geocode()>, run for it: one lookup per
  874: B<distinct> value, with the same options and the same results, plus the counts
  875: that caller would otherwise keep itself - how many values made a backend read,
  876: how many resolved, how many did not, which ones, and which backend read for them
  877: 
  878: The hashref returned holds one entry per distinct value given, keyed by the
  879: value, plus five keys of its own:
  880: 
  881: =over 4
  882: 
  883: =item * C<< $batch->{$value} >> - the C<Geo::Location::Point> the value resolved
  884: to, or C<undef> if nothing did.  Every distinct value in the input is keyed, so
  885: a caller walking a column can look each row up without first asking whether the
  886: batch covered it.  An C<undef> in the input has no key of its own and shares the
  887: entry of the empty string, which is not a location either.
  888: 
  889: =item * C<lookups> - how many distinct values made a backend read to answer
  890: them: one per value, however many backends looked at it.  A value the module
  891: refuses before any backend is touched - a bare number, C<''>, C<undef>, a
  892: reference - is not counted, and neither is a value a backend answered from a
  893: cache or from a hand-curated entry, because nothing was read for it.  This is
  894: what makes the count the work a caller is capping rather than the work it asked
  895: for.  A value repeated in the batch is one lookup.  Every backend reports its
  896: reads through C<reads()>, and a value every backend has already missed is
  897: remembered in L<Geo::Coder::Free::MissCache>, one process-level cache that all
  898: backends and instances share, whose entries expire after an hour and can be
  899: emptied early with L</clear_miss_cache>.  A later batch in the same process is
  900: answered from those caches and so reports the reads it needed, often none, in
  901: place of the ones the first batch made.
  902: 
  903: =item * C<reads> - how many reads each backend made for the batch, keyed by the
  904: name C<provenance()> reports that backend under: C<MaxMind>, C<Local> or
  905: C<OpenAddresses>.  Every backend the object holds is named, at zero for one that
  906: read nothing, so a batch answered from a cache names its backends at zero rather
  907: than naming none.  C<lookups> counts values and this counts reads - a value that
  908: made two backends read is one lookup and a read for each of them, so these
  909: numbers can add up to more than C<lookups> - and the two vocabularies are the
  910: same, so a caller can put the backend that read a value beside the backend a
  911: result came from.
  912: 
  913: =item * C<resolved> - how many distinct values produced a point.
  914: 
  915: =item * C<unresolved> - how many produced nothing, the refused values included.
  916: 
  917: =item * C<unresolved_values> - those values, in the order they were first seen,
  918: so that a caller can record them as tried-and-failed rather than retrying them
  919: on every request.  Section 2.5 sketches this list under the name C<unresolved>;
  920: here C<unresolved> is the count a "geocoded N of M" message needs and the values
  921: themselves are C<unresolved_values>.
  922: 
  923: =back
  924: 
  925: C<resolved> and C<unresolved> always add up to the number of distinct values
  926: given, and the five keys above are reserved: a value equal to one of them is
  927: refused by name, before anything is looked up, rather than allowed to overwrite
  928: a count.
  929: 
  930: C<region> and C<on_error> are handed to every lookup and mean there what they
  931: mean in C<geocode()>, including the rule that a backend exception is still an
  932: exception - nothing here is wrapped in an C<eval>.  C<on_error> defaults to
  933: C<'croak'> for the same reason it does there: a batch should not quietly plot
  934: fewer points than its column holds unless the caller asked it to, and a caller
  935: working down a dirty column asks for C<'undef'>.  The two settings do not differ
  936: in which values are looked up, only in what happens to a value the module
  937: refuses: C<'croak'> dies on it with the message C<geocode()> gives for it,
  938: C<'undef'> counts it unresolved and carries on.
  939: 
  940: A batch of no values is not an error: the counts come back zero.
  941: 
  942: The values are treated as a set.  Repeating a value in the input looks it up
  943: once and every row is keyed to the same point object, so a column that repeats
  944: the same handful of places thousands of times costs the handful of lookups.
  945: 
  946: =head3 API SPECIFICATION
  947: 
  948: =head4 input
  949: 
  950:     # Input schema (Params::Validate::Strict) - values required, options optional
  951:     values   => { type => 'arrayref' }                  # location strings, one per row
  952:     region   => { type => 'scalar', optional => 1 }     # ISO 3166-1 alpha-2 country code hint
  953:     on_error => { type => 'scalar', optional => 1 }     # 'croak' (the default) or 'undef'
  954: 
  955: The domain of each parameter:
  956: 
  957: =over 4
  958: 
  959: =item * C<values> - an arrayref of any size, from none up.  Anything that is not
  960: an arrayref, or none at all, croaks C<Usage:>.  Each row is a C<location> as
  961: C<geocode()> defines it, in any characters, and keys the result as given.
  962: C<undef> and C<''> are one value, which is unresolved on either C<on_error>
  963: setting.  A string only of digits, or a reference, follows C<on_error>.
  964: 
  965: =item * A reserved value - C<lookups>, C<reads>, C<resolved>, C<unresolved> and
  966: C<unresolved_values>, spelled exactly, croak on either C<on_error> setting before
  967: anything is looked up.  C<Lookups> or C<' resolved'> are ordinary values.
  968: 
  969: =item * C<region> - any string, handed to every lookup as it is.
  970: 
  971: =item * C<on_error> - as for C<geocode()>.  It is checked first, so a bad setting
  972: croaks even with no values, or with a reserved value.
  973: 
  974: =item * The options - a hashref or an even list of non-references.  A lone scalar,
  975: an odd list, an arrayref or a reference as a value croak C<Usage:>.
  976: 
  977: =back
  978: 
  979: =head4 output
  980: 
  981:     # Output schema (Return::Set)
  982:     { type => 'hashref' }
  983:     #   $result->{$value}            => { isa => 'Geo::Location::Point', optional => 1 }
  984:     #   $result->{lookups}           => { type => 'integer' }
  985:     #   $result->{reads}             => { type => 'hashref' }
  986:     #   $result->{resolved}          => { type => 'integer' }
  987:     #   $result->{unresolved}        => { type => 'integer' }
  988:     #   $result->{unresolved_values} => { type => 'arrayref' }

  990: =head3 MESSAGES
  991: 
  992:     Usage: ...::geocode_many(...)   No values argument, one that is not an arrayref,
  993:                                     or options that are neither a list nor a hashref.
  994:     invalid location to geocode()   A value refused under on_error => 'croak', with the
  995:                                     message geocode() gives for that value.
  996:     on_error must be ...            on_error is neither 'croak' nor 'undef'.

 1026: sub geocode_many {
 1027: 	my $self = shift;
 1028: 
 1029: 	# The same calling conventions as the rest of the module, with the batch's
 1030: 	# own spelling for the plain-function form: the values are always an
 1031: 	# arrayref, so that is what a function call arrives holding.
 1032: 	if (!Scalar::Util::blessed($self)) {
 1033: 		return __PACKAGE__->new()->geocode_many($self, @_)
 1034: 			if ref($self) eq 'ARRAY';
 1035: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless @_;
 1036: 		return __PACKAGE__->new()->geocode_many(@_);
 1037: 	}
 1038: 
 1039: 	my $values = shift;
 1040: 	Carp::croak(_i18n('usage_geocode_many', __PACKAGE__)) unless ref($values) eq 'ARRAY';
 1041: 
 1042: 	# Options are a hashref or an even list.  A lone scalar is neither: there is
 1043: 	# no bare-string form of a batch, so it is refused rather than guessed at.
 1044: 	my $opts;
 1045: 	if (@_ == 1 && ref($_[0]) eq 'HASH') {
 1046: 		$opts = { %{$_[0]} };
 1047: 	} elsif ((scalar @_) % 2 == 0 && !grep { ref } @_) {
 1048: 		$opts = { @_ };
 1049: 	} else {
 1050: 		Carp::croak(_i18n('usage_geocode_many', __PACKAGE__));
 1051: 	}
 1052: 
 1053: 	my $on_error = $opts->{'on_error'} // 'croak';
 1054: 	Carp::croak(_i18n('invalid_on_error', __PACKAGE__, $on_error))
 1055: 		unless $on_error eq 'croak' || $on_error eq 'undef';
 1056: 
 1057: 	my $region = $opts->{'region'};
 1058: 
 1059: 	# A value spelled like one of the keys this method answers with would
 1060: 	# overwrite it, so it is refused by name - before anything is looked up,
 1061: 	# rather than after a count has been lost.
 1062: 	my %reserved = map { $_ => 1 } @RESULT_KEYS;
 1063: 	for my $value (@{$values}) {
 1064: 		my $key = defined($value) ? $value : '';
 1065: 		Carp::croak(_i18n('reserved_location', __PACKAGE__, $key)) if $reserved{$key};
 1066: 	}
 1067: 
 1068: 	my %results = map { $_ => 0 } @RESULT_KEYS;
 1069: 	$results{'unresolved_values'} = [];
 1070: 	$results{'reads'} = {};
 1071: 
 1072: 	# A batch is a set: a value repeated in the input is looked up once, and
 1073: 	# every row holding it is keyed to the same object.
 1074: 	my %seen;
 1075: 	for my $value (@{$values}) {
 1076: 		# undef has no key of its own, and the empty string it shares is not a
 1077: 		# location either, so it is unresolved without reaching a backend.
 1078: 		my $key = defined($value) ? $value : '';
 1079: 		next if $seen{$key}++;
 1080: 
 1081: 		# What geocode() makes of this value on this setting is asked of
 1082: 		# geocode() rather than written out again here: the guard, its message and
 1083: 		# the choice of backend are all its own.  The backends' read counters are
 1084: 		# taken around the call, so the value is counted as a lookup only if one of
 1085: 		# them actually read: a value answered from a cache, or from a hand-curated
 1086: 		# entry, is not counted as work the batch did not do.  Taking them per
 1087: 		# backend rather than in total says which backend read, and which answered
 1088: 		# from somewhere else: a read is added to the name of the backend that made
 1089: 		# it, so a value two backends read through is one lookup and a read each.
 1090: 		my $reads_before = $self->_backend_reads();
 1091: 		my $point = $self->geocode(
 1092: 			location => $key,
 1093: 			defined($region) ? (region => $region) : (),
 1094: 			on_error => $on_error,
 1095: 		);
 1096: 		my $reads_after = $self->_backend_reads();
 1097: 
 1098: 		my $read = 0;
 1099: 		foreach my $backend (keys %{$reads_after}) {
 1100: 			my $reads = $reads_after->{$backend} - ($reads_before->{$backend} // 0);
 1101: 			next unless $reads > 0;
 1102: 			$results{'reads'}{$backend} += $reads;
 1103: 			$read += $reads;
 1104: 		}
 1105: 
 1106: 		# A value the module refuses is not a lookup: it never reached a backend,
 1107: 		# so it does not count against the work a caller is capping.
 1108: 		$results{'lookups'}++ if _valid_location($key) && $read;
 1109: 		$results{$key} = $point;
 1110: 
 1111: 		if (defined($point)) {
 1112: 			$results{'resolved'}++;
 1113: 		} else {
 1114: 			$results{'unresolved'}++;
 1115: 			push @{$results{'unresolved_values'}}, $value;
 1116: 		}
 1117: 	}
 1118: 
 1119: 	# A backend that read nothing is reported as well, at zero: what a caller is
 1120: 	# asking is which backend read and which answered from a cache, and a backend
 1121: 	# left out of the answer cannot be told from one that answered from one.
 1122: 	# Local is built the first time a lookup falls through to it, so it appears
 1123: 	# once it has been consulted, whether or not it found anything.
 1124: 	foreach my $backend (keys %{$self->_backend_reads()}) {
 1125: 		$results{'reads'}{$backend} //= 0;
 1126: 	}
 1127: 
 1128: 	return \%results;
 1129: }
 1130: 
 1131: # How much reading each backend has done so far, by the name it is reported
 1132: # under.  Counters rather than flags: the change across a call says which
 1133: # backend read for that value, and a backend that was never called cannot leave
 1134: # a stale flag behind.  A backend object may not exist yet - Local is built on
 1135: # first use - and a test may hand the facade a stand-in, so each slot is asked
 1136: # only if it holds something that can answer.
 1137: sub _backend_reads {
 1138: 	my $self = shift;
 1139: 
 1140: 	my %reads;
 1141: 	foreach my $slot (sort keys %_BACKEND_NAMES) {
 1142: 		my $backend = $self->{$slot} or next;
 1143: 		next unless Scalar::Util::blessed($backend) && $backend->can('reads');
 1144: 		$reads{$_BACKEND_NAMES{$slot}} = $backend->reads() // 0;
 1145: 	}
 1146: 
 1147: 	return \%reads;
 1148: }

 1151:

 1195: =head2 provenance
 1196: 
 1197:     my ($dist, $backend, $confidence, $accuracy) = $geocoder->provenance($point);
 1198: 
 1199: or, in scalar context, the same four as a hashref:
 1200: 
 1201:     my $provenance = $geocoder->provenance($point);
 1202:     print $provenance->{'backend'};
 1203: 
 1204: Where a result came from and how good it is, so that a caller does not have to
 1205: reach for the hash keys itself:
 1206: 
 1207: =over 4
 1208: 
 1209: =item * C<$dist> - the distribution that produced the result: the C<geocoder>
 1210: key, C<Geo::Coder::Free> for a result from this distribution, or the wrapper
 1211: that passed it on, such as C<Geo::Coder::List>.
 1212: 
 1213: =item * C<$backend> - which backend answered, in a short vocabulary: C<Local>,
 1214: C<MaxMind>, C<OpenAddresses> or C<GeoNames>.  This is the C<database> key with
 1215: the distribution's prefix removed, so that the two spellings the backends use -
 1216: C<Geo::Coder::Free::Local> from C<Local>, and C<MaxMind> from C<MaxMind> - speak
 1217: the same vocabulary here.  B<The C<database> key itself is unchanged>, for the
 1218: consumers that already match on it.
 1219: 
 1220: =item * C<$confidence> - how good the match was, 0.0 to 1.0, where 1.0 is exact.
 1221: 
 1222: =item * C<$accuracy> - how precise the coordinate is: C<address>, C<street>,
 1223: C<postcode>, C<locality>, C<city>, C<region> or C<country>.
 1224: 
 1225: =back
 1226: 
 1227: Returns an empty list - and an empty hashref in scalar context - when handed
 1228: something that is not a result.  A key a result does not carry comes back
 1229: C<undef> rather than being guessed at, because a plain hash from another

 1233:

 1235: 
 1236:     point => { type => 'hashref', optional => 1 }  # a result, usually a Geo::Location::Point
 1237:

 1239: it holds; nothing else does, so C<undef>, a string, or a reference to an array,

 1244: =head4 output
 1245: 
 1246:     # list context
 1247:     { type => 'array', min => 0, max => 4 }   # dist, backend, confidence, accuracy; or ()

 1249:     # scalar context
 1250:     {
 1251:         type   => 'hashref',
 1252:         schema => {
 1253:             dist       => { type => 'string', optional => 1 },

 1436: # Purpose:  Normalise the four calling conventions accepted by geocode/reverse_geocode:
 1437: #             hashref, even-length key-val list, odd-length list, single bare string.
 1438: # Entry:    $error_msg - message to croak if a non-hash reference is passed.
 1439: #           $bare_key  - hash key to assign to a single bare string argument
 1440: #                        ('location' for geocode, 'latlng' for reverse_geocode).
 1441: #           @args - raw @_ after $self has been shifted.
 1442: # Exit:     Flat key-value %params hash.
 1443: # Side Effects: None; croaks on unsupported reference argument.
 1444: sub _normalize_args {
 1445: 	my ($error_msg, $bare_key, @args) = @_;
 1446: 	return %{$args[0]}              if ref($args[0]) eq 'HASH';
 1447: 	Carp::croak($error_msg)         if ref($args[0]);
 1448: 	return @args                    if @args && @args % 2 == 0;
 1449: 	return ($bare_key => $args[0])  if @args == 1;
 1450: 	# M7 (logic-gap closure): odd-count > 1 is not a valid calling convention.
 1451: 	# The former code silently returned () here, discarding the trailing elements.
 1452: 	# Fail fast instead of propagating a malformed argument list downstream.
 1453: 	Carp::croak($error_msg)         if @args;
 1454: 	return ();

 1457: # Purpose:  Try to geocode each candidate place string via the openaddr backend,
 1458: #           annotating every hit with location/text/confidence metadata and
 1459: #           memoising misses to avoid re-querying the same failing string.
 1460: # Entry:    $self       - geocoder instance with {openaddr} and {scantext_misses}.
 1461: #           $candidates - arrayref of place-name strings to probe.
 1462: #           $region     - optional country appended to each candidate: an ISO
 1463: #                         code, or the name from %_REGION_COUNTRY.
 1464: #           $confidence - numeric confidence score assigned to all hits.
 1465: #           $scantext   - original free text (stored inside each result object).
 1466: # Exit:     Arrayref of Geo::Location::Point objects; empty arrayref on no hits.
 1467: # Side Effects: Populates $self->{scantext_misses} for every non-matching place.
 1468: sub _resolve_scan_candidates {
 1469: 	my ($self, $candidates, $region, $confidence, $scantext) = @_;
 1470: 	my @results;
 1471: 	for my $place (@{$candidates}) {
 1472: 		my $location = $region ? "$place, $region" : $place;
 1473: 		next if $self->_scantext_missed($location);
 1474: 		my @res = grep { defined } $self->{'openaddr'}->geocode($location);
 1475: 		if (@res) {
 1476: 			for my $entry (@res) {
 1477: 				$entry->{'location'}   = $location;
 1478: 				$entry->{'text'}       = $scantext;
 1479: 				$entry->{'confidence'} = $confidence;
 1480: 			}
 1481: 			push @results, @res;
 1482: 		} else {
 1483: 			$self->_remember_scantext_miss($location);
 1484: 		}
 1485: 	}
 1486: 	return \@results;
 1487: }

 1489: # Purpose:  The key a scantext miss is remembered under.  A miss depends on what
 1490: #           was searched for, so a different region or ignore_words is another search.
 1491: # Entry:    $text; $region and $ignore_words as given to geocode(), or undef.
 1492: # Exit:     The text itself when there are no options, otherwise a composite key.
 1493: sub _scantext_miss_key {
 1494: 	my ($text, $region, $ignore_words) = @_;
 1495: 
 1496: 	my @words = $ignore_words ? sort(map { lc($_) } @{$ignore_words}) : ();
 1497: 	return $text if !length($region // '') && !@words;
 1498: 
 1499: 	return join("\0", $text, uc($region // ''), @words);
 1500: }

 1502: # Purpose:  Is this key a scantext miss that has not expired?
 1503: # Side Effects: Forgets everything after clear_miss_cache(), and an expired entry.
 1504: sub _scantext_missed {
 1505: 	my ($self, $key) = @_;
 1506: 
 1507: 	my $misses = $self->{'scantext_misses'} or return 0;
 1508: 	if (($self->{'scantext_generation'} // 0) != $_scantext_generation) {
 1509: 		%{$misses} = ();
 1510: 		$self->{'scantext_generation'} = $_scantext_generation;
 1511: 		return 0;
 1512: 	}
 1513: 
 1514: 	my $expires_at = $misses->{$key} // return 0;
 1515: 	return 1 if $expires_at > time();
 1516: 	delete $misses->{$key};
 1517: 
 1518: 	return 0;
 1519: }

 1521: # Purpose:  Remember a scantext miss for as long as MissCache remembers a miss.
 1522: # Side Effects: Starts again rather than grow past $SCANTEXT_MISS_LIMIT entries.
 1523: sub _remember_scantext_miss {
 1524: 	my ($self, $key) = @_;
 1525: 
 1526: 	my $misses = $self->{'scantext_misses'} //= {};
 1527: 	%{$misses} = () if keys(%{$misses}) >= $SCANTEXT_MISS_LIMIT;
 1528: 	$misses->{$key} = time() + Geo::Coder::Free::MissCache->expires_after();
 1529: 	$self->{'scantext_generation'} //= $_scantext_generation;
 1530: 
 1531: 	return;
 1532: }

 1534: # Purpose:  Slide a window of $n words across $text and return all comma-joined
 1535: #           n-grams, excluding pure-numeric tokens and stopwords.  A token of
 1536: #           digits only is not a word of a place name, which is the question
 1537: #           Geo::Location::Predicate::_valid_location() answers, so it is asked
 1538: #           there rather than spelled out here (t/location-rule.t fails if the
 1539: #           rule is written out again).
 1540: #           Replaces the former _find_word_triplets ($n=3) and
 1541: #           _find_word_duplets ($n=2) which were identical except for window size
 1542: #           and the duplets version was missing the lc() normalisation on stopwords.
 1543: # Entry:    $text - raw string; $n - window size; $stop - stopword hashref.
 1544: # Exit:     Flat list of n-gram strings.
 1545: sub _find_word_ngrams {
 1546: 	my ($text, $n, $stop) = @_;
 1547: 	$text =~ s/,+/ /g;
 1548: 	$text =~ s/\s+/ /g;
 1549: 	$text =~ s/^\s+|\s+$//g;
 1550: 	my @words = grep { !$stop->{lc $_} && _valid_location($_) } split /\s+/, $text;
 1551: 	my @ngrams;
 1552: 	for my $i (0 .. $#words - ($n - 1)) {
 1553: 		push @ngrams, join ', ', @words[$i .. $i + $n - 1];
 1554: 	}
 1555: 	return @ngrams;
 1556: }

 1558: # Purpose:  Extract structured US street addresses from free text.
 1559: # Entry:    $text - arbitrary string.
 1560: # Exit:     List of full address strings matching the US pattern.
 1561: sub _find_us_addresses {
 1562: 	my $text = shift;
 1563: 	my @addresses;
 1564: 	my $re = qr/
 1565: 		\b \d{1,5} \s+                                      # house number
 1566: 		(?:[A-Za-z0-9]+(?:\s+[A-Za-z0-9]+){0,6}) \s+       # street name: 1-7 words (bounded)
 1567: 		(?:Avenue|Ave\.?|Boulevard|Blvd\.?|Road|Rd\.?|Lane|Ln\.?|Drive|Dr\.?|Street|St\.?)
 1568: 		(?:\s+[A-Za-z]{2})? ,\s*
 1569: 		(?:[A-Za-z]+(?:\s+[A-Za-z]+){0,3}) ,\s*            # city: 1-4 words
 1570: 		[A-Z]{2} \s* (?:\d{5}(?:-\d{4})?)? \b              # state + optional zip
 1571: 	/x;
 1572: 	while ($text =~ /$re/g) {
 1573: 		push @addresses, $&;
 1574: 	}
 1575: 	return @addresses;
 1576: }

 1578: # Purpose:  Extract British-style addresses from free text.
 1579: # Entry:    $text - arbitrary string.
 1580: # Exit:     List of trimmed address strings.
 1581: sub _find_gb_addresses {
 1582: 	my $text = shift;
 1583: 	my @addresses;
 1584: 	# ReDoS fix: the former pattern used \s*,?\s* between all parts and
 1585: 	# [A-Za-z\s'-]+ groups - with commas optional, the engine must try all
 1586: 	# possible splits of a long string among 5 overlapping space-containing
 1587: 	# groups, causing exponential backtracking.  Making commas mandatory
 1588: 	# eliminates the ambiguity entirely: UK postal addresses always have commas.
 1589: 	# All groups are non-capturing (only $& is used).
 1590: 	my $re = qr/
 1591: 		\b
 1592: 		(?:\d{1,5} | [\w'-]+)                   # house number or single-word name
 1593: 		\s+
 1594: 		(?:[\w'-]+(?:\s+[\w'-]+){0,5})           # street name (up to 6 words)
 1595: 		\s*,\s*                                   # COMMA REQUIRED - kills the ambiguity
 1596: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # town (up to 4 words)
 1597: 		\s*,\s*                                   # COMMA REQUIRED
 1598: 		(?:[\w'-]+(?:\s+[\w'-]+){0,3})           # county (up to 4 words)
 1599: 		\s*,\s*                                   # COMMA REQUIRED
 1600: 		(?:[\w'-]+(?:\s+[\w'-]+){0,2})           # country (up to 3 words)
 1601: 		\b
 1602: 	/x;
 1603: 	while ($text =~ /$re/g) {
 1604: 		(my $addr = $&) =~ s/[,\s]+$//;
 1605: 		push @addresses, $addr;
 1606: 	}
 1607: 	return @addresses;
 1608: }

 1633: =head1 GETTING STARTED
 1634: 
 1635: To download, import and set up the local database:
 1636: before running C<make>, but after running C<perl Makefile.PL>, follow these instructions.
 1637: 
 1638: Optionally set C<OPENADDR_HOME> to point to an empty directory and download the data from
 1639: L<http://results.openaddresses.io> into that directory; and
 1640: optionally set C<WHOSONFIRST_HOME> to point to an empty directory and download the data using
 1641: L<https://github.com/nigelhorne/NJH-Snippets/blob/master/bin/wof-clone>.
 1642: The script C<bin/download_databases> (see below) will do those for you.
 1643: You do not need to download the MaxMind data - that is downloaded automatically.
 1644: 
 1645: You will need to create the database used by C<Geo::Coder::Free>.
 1646: 
 1647: Install L<App::csv2sqlite> and L<https://github.com/nigelhorne/NJH-Snippets>.
 1648: Run C<bin/create_sqlite> - this converts the MaxMind "cities" database from CSV to SQLite.
 1649: 
 1650: To use with MariaDB, set C<MARIADB_SERVER="$hostname;$port"> and
 1651: C<MARIADB_USER="$user;$password"> (TODO: username/password should be asked for interactively).
 1652: The code will use a database called C<geo_code_free>, which will be dropped and recreated if it exists.
 1653: C<$user> needs only DROP, CREATE, SELECT, INSERT, and INDEX privileges on that database.
 1654: 
 1655: The following optional steps download and install large databases.
 1656: This will take a long time and use a lot of disc space.
 1657: 
 1658: =over 4
 1659: 
 1660: =item 1
 1661: 
 1662: C<mkdir $WHOSONFIRST_HOME; cd $WHOSONFIRST_HOME> then run C<wof-clone> from NJH-Snippets.
 1663: 
 1664: This can take a long time because it contains many nested directories, which filesystem drivers
 1665: can be slow to navigate (particularly on EXT4 and ZFS).
 1666: 
 1667: =item 2
 1668: 
 1669: Install L<https://github.com/dr5hn/countries-states-cities-database.git> into C<$DR5HN_HOME>.
 1670: This data covers cities only, so it is not used when C<OSM_HOME> is set (OSM is far more
 1671: comprehensive).  Only Australia, Canada, and the US are imported, as the UK data is difficult
 1672: to parse.
 1673: 
 1674: =item 3
 1675: 
 1676: Run C<bin/download_databases> - this downloads the Who's On First, OpenAddr, OpenStreetMap,
 1677: and dr5hn databases.
 1678: OpenStreetMap now uses PBF files, so you will need C<apt install osmium-tool> first.
 1679: Check the values of C<OSM_HOME>, C<OPENADDR_HOME>, C<DR5HN_HOME> and C<WHOSONFIRST_HOME>
 1680: within that script and adjust them for your setup.
 1681: The C<Makefile.PL> file downloads the MaxMind database automatically, as it is not optional.
 1682: 
 1683: =item 4
 1684: 
 1685: Run C<bin/create_db> - this creates the database used by C<Geo::Coder::Free> from the data you
 1686: have just downloaded.
 1687: The database is called C<openaddr.sql> for historical reasons (before Who's On First was added);
 1688: it actually contains data from all sources above.
 1689: 
 1690: =back
 1691: 
 1692: Now you are ready to run C<make>.
 1693: See the comment at the start of C<createdatabase.PL> for further details.
