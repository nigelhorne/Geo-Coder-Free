   21: =head1 DESCRIPTION
   22: 
   23: Which distribution and which backend produced a result, how good the match was
   24: and how precise the coordinate is: the keys of section 2.1 of
   25: F<BI-Phase6-Dependency-Specs.md>, and the vocabulary they speak.
   26: 
   27:     use Geo::Coder::Free::Provenance qw(GEOCODER _accuracy_for);

   29:     my $point = Geo::Location::Point->new({

   32:         confidence => 1.0,
   33:         accuracy   => _accuracy_for(qw(house_number road city)),
   34:     });
   35: 
   36: C<< Geo::Coder::Free->provenance($point) >> reads the four keys back, so a
   37: consumer does not have to know them.

   39: These three live here rather than in L<Geo::Coder::Free::Utils> because Utils is
   40: synced from VWF master, where the provenance of a geocoder result has no
   41: meaning; an addition there would be lost the next time that sync runs.

   51: # The distribution that produced a result.  Every backend stamps this on the
   52: # Geo::Location::Point it hands back, so a consumer can tell a result from this
   53: # distribution from one passed on by a wrapper such as Geo::Coder::List.
   54: # Section 2.1 of BI-Phase6-Dependency-Specs.md.
   55: use constant GEOCODER => 'Geo::Coder::Free';
   56: 
   57: # How precise the coordinates behind a match can claim to be, most precise
   58: # first.  _accuracy_for() returns one of these, and anything that validates an
   59: # accuracy (section 3.2) validates against this list.
   60: use constant ACCURACY_LEVELS => [qw(address street postcode locality city region country)];
   61: 
   62: =head1 SUBROUTINES/METHODS
   63: 
   64: =head2 GEOCODER
   65: 
   66: The distribution that produced a result: C<Geo::Coder::Free>.  It is the
   67: C<geocoder> key of every result this distribution returns, whether the answer
   68: came from OpenAddresses, Local or MaxMind.
   69: 
   70: =head2 ACCURACY_LEVELS
   71: 
   72: A list of the accuracies a result may claim, most precise first: C<address>,
   73: C<street>, C<postcode>, C<locality>, C<city>, C<region> and C<country>.
   74: 
   75: =head2 _accuracy_for
   76: 
   77: The precision a match can claim, from the fields that made it.  The most
   78: precise field present decides: a house number makes it an C<address>, a road a
   79: C<street>, a postcode a C<postcode>, a name or a city a C<locality>, a state or
   80: region a C<region>, and a country a C<country>.  So a dataset row carrying only
   81: a city, state and country is a C<locality>, which is what the geographic centres
   82: C<Local.pm> derives are.
   83: 
   84: Always returns one of the C<ACCURACY_LEVELS>: a match on a row with none of the
   85: fields above is still a named place, so it is reported as a C<locality> rather
   86: than left unsaid, because every result promises an accuracy.
   87: 
   88: Exported so that a backend can describe the match it made without repeating the
   89: vocabulary.
   90: 
   91: =cut
   92:
